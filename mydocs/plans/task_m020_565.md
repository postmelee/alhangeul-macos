## 현재 목표와 범위

Mac에서 활성화된 설치 글꼴을 감지하고 사용 설정·식별 정보·필요한 접근 권한을 지속한다. 정상 권한에서는 앱 재실행마다 사용자가 감지나 가져오기를 반복하지 않고, 문서가 요청한 글꼴 데이터를 필요한 시점에 공급한다. 전체 font bytes의 영구 복사나 디스크 읽기 없는 실행을 의미하지 않는다.

rhwp의 기존 이름·스타일 매칭, fallback, renderer cache를 재사용한다. 알한글은 설치 상태와 권한, native 데이터 공급 경계를 맡는다. 폴더 내 파일 수를 활성 face 수로 취급하지 않는다. 최소 연결 실험에서 실제 선택된 face와 적용을 먼저 증명한 뒤 제품 기반을 구현한다.

한글 `.app` 내부에만 있는 글꼴 자동 추출은 기본 범위에서 제외한다. Windows ZIP/외부 파일 입력과 독립 보관은 별도 #566 범위다. #564 기반 및 기존 Stage 1–2 코드는 보존하고 기본 UI 연결을 조정한다. Studio 제품 연동은 #567, PDF·인쇄·native·Quick Look·썸네일은 #568, 전체 수용과 웹 안내는 #569 소유다.

## 단계

1. 기존 Mac 후보 탐색·출처·일시 권한 기반: 완료, 이전 범위의 재사용 자산.

## 제한과 검증 원칙

- 한컴 삭제 후에도 글꼴이 Mac에 독립적으로 남는 경우와 앱 내부에만 있던 경우를 구분한다. 원본 삭제 후 사용을 보장하지 않는다.
- OS 설치, 이름, fsType, 사용자 체크는 외부 사용·복사 허가의 증명이 아니다.
- 최초 권한 허용/복구가 필요할 수 있다. persistent bookmark 필요 여부는 실제 signed sandbox에서 결정한다.
- TTC/가변은 정확한 face/축을 소비자별로 검증한 범위만 지원한다. HFT·레이아웃 완전 동일성·상용 글꼴 재배포는 제외한다.
- 기존 rhwp 고정 commit을 유지한다. upstream 변경이 필요하면 정식 소스·pin/sync 절차로 별도 승인받으며 bundled minified 파일을 직접 수정하지 않는다.
- build_run_guide의 변경 유형별 검증을 적용한다. 산출물은 build.noindex 아래, macOS 12 컴파일과 실제 실행을 구분한다. 사용자 글꼴·한컴 앱을 수정/삭제하지 않는다.

# Task #565 — Mac 한글 글꼴 자동 탐색 및 일괄 가져오기 수행계획서

- 이슈: [#565](https://github.com/postmelee/alhangeul-macos/issues/565), 상위 #562
- 마일스톤: M020 — 글꼴 마이그레이션, v0.2 계열
- 기준 브랜치: `devel` (`609acc3`) / 작업 브랜치: `local/task565`
- 선행: #563 조사·설계, #564 공통 관리 기반(PR #571) 통합 완료
- 상태: 2026-09-20 수행·[구현계획](task_m020_565_impl.md) 승인, [Stage 2](../working/task_m020_565_stage2.md) 완료, Stage 3 승인 대기
- 사용자 요청: 시각적 변경이 생기면 스크린샷을 제공하거나 직접 실행·확인할 수 있는 방법을 안내한다.

## 1. 목적

같은 Mac의 한글 앱 내부 및 사용자가 설치한 글꼴을 찾아, 개별 파일을 일일이 고르지 않고 알한글 관리 저장소로 복사하는 화면과 탐색 계층을 구현한다. 권한·설치 위치 차이를 안내하고 가져오기 결과를 확인할 수 있게 한다.

## 2. 배경

공통 `FontLibraryService`는 검증·독립 저장·중복·충돌 선택·삭제·복구를 제공하지만 사용자 진입점과 Mac 탐색은 없다. 현재 설정 화면은 개인정보 설정만 표시한다. [연동 계약](../tech/font_library_integration.md)과 [조사 설계](../tech/font_migration_design.md)를 기준으로 제품 UI를 연결한다.

조사에서 확인한 뷰어 12.31.8의 문서용 경로는 `Contents/Resources/Hnc/Shared/TTF/Install`이다. 편집기의 `Hnc/Shared/Fonts`, `Hnc/Shared/TTF/Hwp`는 후보 경로이며 실제 설치본 확인이 필요하다. CoreText 목록만으로 한글 미설치를 판정하지 않는다.

## 3. 범위(포함·제외)

포함:

- 설정의 글꼴 진입점, 기존 한글 글꼴 가져오기 → 이 Mac의 한글 흐름.
- 표준 Applications 위치의 설치 후보 탐색, 여러 설치본의 출처·버전 구분, 수동 앱·폴더 선택.
- 사용자·공용 Fonts 후보를 별도 출처로 표시. 한컴 제공 여부를 이름만으로 추정하지 않음.
- 후보 목록 확인·선택, 일괄 가져오기·취소·재시도, 중복·충돌·부분 실패·지원 제한 안내.
- 저장된 글꼴 목록과 공통 서비스의 충돌 선택·삭제 동작 연결.
- signed sandbox 검증, 회귀 테스트, 실제 화면 증거와 직접 확인 경로 기록.

제외:

- Windows ZIP·폴더 전용 흐름(#566), Studio 적용(#567), PDF·인쇄·확장 적용(#568), 제품 웹 안내·전체 수용(#569).
- HFT 해석, TTC 개별 face 및 가변 글꼴 활성화, 상용 글꼴 재배포, 한컴 앱 삭제.
- 모든 위치의 무제한 탐색, 시스템 Fonts 일괄 복사, 원본의 영구 접근 권한 저장.

## 4. 설계 방향

### 탐색과 권한

- 알려진 문서용 하위 경로만 자동 후보로 수집해 앱 프레임워크의 UI 아이콘 글꼴 혼입을 피한다. 설치본 식별·경로 규칙은 테스트 가능한 데이터로 분리한다.
- 접근 가능한 경로부터 조사하고 미발견·접근 불가·지원 후보 없음·사용자 취소를 구분한다. 실패를 한글 미설치로 단정하지 않는다.
- 직접 선택한 앱·폴더는 NSOpenPanel에서 얻은 URL의 scope를 탐색 및 가져오기 동안 유지한다. 공통 서비스의 accessURLs와 수명을 맞추고 종료·취소 시 해제한다.
- 탐색은 UI 스레드를 막지 않으며 취소 가능하게 한다. 깊이·방문 항목·후보 수를 제한하고 symlink 순환·루트 이탈을 방지한다. 구체 한도와 실패 정책은 구현계획에서 확정한다.

### 화면 흐름

1. 설정 → 글꼴에서 ‘기존 한글 글꼴 가져오기’를 선택한다.
2. ‘이 Mac의 한글’에서 설치본을 탐색한다. ‘Mac에 설치한 글꼴’은 별도 출처로 제공한다.
3. 발견한 설치본·글꼴 후보를 확인한다. 찾지 못하거나 접근이 필요하면 ‘한글 앱 또는 글꼴 폴더 선택’으로 이어진다.
4. 사용자가 선택한 후보를 한 배치로 가져온다. 처리 중 상태와 취소를 제공하며 이미 저장된 항목은 취소 후에도 유지한다.
5. 추가됨·이미 있음·선택 필요·미지원·실패 결과와 후속 행동을 보여준다. 충돌은 기존 선택을 유지하며 명시적 사용자 선택으로 해결한다.

설정의 개인정보 기능을 유지하고 글꼴 화면을 추가하는 구성을 우선 검토한다. 최종 메뉴·화면 배치와 창 크기는 구현계획에서 정한다. 저장 완료를 문서 렌더링 적용 완료로 표시하지 않으며, 후속 연동 전에는 현재 제한을 짧고 명확하게 안내한다.

### 공통 서비스 연결

- 사용 시작 시 prepare()를 호출하고 구성·복구 오류를 안내한다. 다른 저장 경로로 임의 우회하지 않는다.
- 후보별 호출로 쪼개지 않고 하나의 import 요청을 보내 기존 파일 64 MiB / 후보 4,096개 / 배치 1 GiB 제한을 유지한다.
- generation 기반 선택·삭제, staleGeneration 재조회, publication 내구성 미확인 상태를 구분한다.
- 원본 경로와 권한 정보는 native 계층에 유지하고 로그·분석 이벤트·WebView로 보내지 않는다. 사용 조건이 unknown인 항목을 허용으로 단정하지 않는다.

## 7. 검증 계획

- 탐색: 여러 설치본, 사용자 지정 위치, 접근 오류, 한글 경로, symlink·깊이·개수 한도, UI 아이콘 제외, OS 출처 구분.
- 가져오기: 정상·중복·충돌·손상·TTC/가변/HFT 제한, 전체 배치 제한, 취소 전후 부분 성공, 재시도와 삭제·재가져오기.
- UI: 빈 화면, 탐색 중, 후보 확인, 권한 재선택, 가져오는 중, 결과·충돌·오류. 긴 이름, 키보드 조작, 창 크기 및 밝은/어두운 모드 확인.
- 시각적 변경이 생긴 단계부터 실제 앱 스크린샷을 제시한다. 캡처가 불가능하면 빌드 산출물의 절대 경로, 실행 명령, 메뉴 이동, 확인 항목을 제공하고 직접 확인을 요청한다. 모형을 구현 완료 화면으로 제시하지 않는다.
- signed sandbox에서 자동 탐색·NSOpenPanel 선택·취소·재시도를 확인한다. 실제 설치본과 자체 fixture를 구분하고 한컴 원본·사용자 Fonts를 수정하거나 삭제하지 않는다.
- 테스트용 원본만 제거한 뒤 새 프로세스에서 관리 복사본 조회를 확인한다. 문서의 실제 적용 검증은 후속 이슈 범위로 남긴다.
- 최소 검증은 build_run_guide 기준 HostApp 빌드, 글꼴 테스트, 변경한 설정·문서 수명주기 회귀다. 앱 산출물은 build.noindex 아래에 두며 실행 후 개발 산출물 등록 정리를 확인한다.
- macOS 12 컴파일과 실제 macOS 12 실행을 구분한다. 편집기 실설치·최소 OS 환경이 없으면 미검증으로 기록하고 지원 확인으로 확대하지 않는다.

## 8. 리스크

- sandbox에서 자동 탐색이 제한될 수 있다. 위치 선택을 정상적인 대안으로 제공하며 무조건 한 번 클릭 완료를 약속하지 않는다.
- 편집기 버전별 설치 위치가 미확인이다. 확인한 뷰어·합성 fixture 결과를 편집기 전체 지원으로 일반화하지 않는다.
- 큰 글꼴 검증이 오래 걸릴 수 있다. 탐색·처리를 비동기로 유지하고 실제 서비스가 제공하는 정보만 진행 상태로 표시한다.
- 가져오기 UI가 렌더러 연동보다 먼저 완성된다. 현재 기능 범위와 제한을 화면·보고서에서 명시한다.

## 9. 승인 요청 사항

위 범위와 4단계 흐름으로 진행하고, 다음 단계에서 구체적인 구현계획을 작성하는 것에 대한 승인을 요청한다. 수행계획 승인 전 제품 소스와 구현계획은 변경하지 않는다.
