# Task #558 구현계획

## 승인과 기준

수행계획 및 구현·검증·PR·공개 배포 연속 진행 승인(2026-09-15)을 적용한다. 자동 수집 활성화는 범위 밖이다.

## Stage 1 — 문의와 데이터 계약

- Meta 공식 지원의 제출 경로와 문의 결과를 기록한다. AI 안내를 담당자 접수·개별 승인으로 바꾸어 보고하지 않는다.
- 기존 6개 후보의 공개 원문을 방문하여 작성자·태그·순서를 확인한다.
- 수동 계약: `schema_version: 3`, `mode: manual`, `items: [{platform, permalink}]`. 시간 필드가 없어 자동 조회를 가장하지 않는다.
- 기존 자동 계약 v2와 48시간 만료를 유지한다. 수동 항목 검증에도 기존 작성자·URL·중복 제한을 적용한다.

## Stage 2 — 구현과 회귀 검사

- `docs/data/news-manual.json`은 운영자가 선택한 순서의 수동 목록이다.
- helper `--manual-input`은 자동 비활성일 때만 사용한다. 수동 입력 없음은 기존 빈 seed이다. 자동 활성 시 반드시 새 조회가 성공해야 하며 수동 목록으로 실패를 대체하지 않는다.
- 두 workflow의 collect에 수동 파일을 명시하고 assembler는 docs 원천의 수동 파일과 collect 결과의 일치를 확인한다. 다른 임의 수동 snapshot은 거부한다.
- UI는 v3 manual을 만료 없는 ready/empty로 구분하고 타이머를 만들지 않는다. 카드·스크롤·로딩 표현은 유지한다.
- 검증: 수동/비활성/자동 경계, 토큰·네트워크 없는 수동 처리, 잘못된 수동 데이터·목록 불일치·실패 시 보존, 기존 자동 만료/수집, Pages 양 경로·appcast 동일성.

## Stage 3 — 표시 검증과 공개 반영

- 실제 6개 공식 임베드와 홈1/피드5+1, 기존 합성 브라우저 회귀를 확인한다.
- 운영 안내에 수동 추가·제거와 전체 중단 방법을 반영한다. 수동 원문 삭제/비공개 시 Threads 표시 제한과 운영자의 목록 정리 책임을 설명한다.
- 단계 보고서와 최종 보고, 오늘할일 갱신 후 devel PR을 게시한다. CI 성공 후 merge하고 main 배포 PR을 통해 공개한다.
- 공개 Pages 결과·JSON 및 appcast 전후 bytes를 확인한다. 이슈와 작업 브랜치는 완료 범위에 맞춰 정리한다.
