## 판정 및 운영 경계

- `mdimport -L` 발견, `mdimport -t` 실제 후보 선택, `mdfind` 실제 색인을 별개로 기록한다. `mdimport -i`는 자동 색인의 증거가 아니다.
- 새 경로 최초 설치, 동일 경로 교체, bundle timestamp 변경과 등록 변경을 혼합한 결과를 단일 원인 증거로 쓰지 않는다.
- 사용자 앱 두 개와 기본 연결·provider를 보존한다. 새 앱/문서/등록은 소유권 검사와 표준 cleanup으로 정리하고 원본 패키지는 읽기/복사만 한다. 원시 진단은 `build.noindex/`에 두고 공개 자료에는 경로·계정·시스템 로그를 넣지 않는다.
- 전역 색인 초기화, daemon 종료, 사용자 앱 변경, 공개 서명·공증·배포, 버전 상향, 기존 PR merge/이슈 close는 제외한다.
- 최종 서명·공증 후보와 macOS 12/Intel runtime은 별도 미실행 관문이다. 개발 후보 성공으로 대체하지 않는다.
- 후속 PR 게시/병합 준비 시 선행 리뷰 결과와 최신 devel을 다시 확인한다. 선행 미병합 시 누적 diff와 #513 기준 compare를 명시한다.

## 2026-09-13 공개 후 동일 버전 재설치 보완

작업지시자가 #520 공개 기록 종료 후 같은 버전 재설치 문제의 보완·회귀 검증을 계속 진행하도록 승인했다. 기준은 devel `b84b9d15868a6c09ad84df25b106935689084011`이며 새 `local/task513`에서 수행한다. [#520 Stage 5](../working/task_m900_520_stage5.md)의 최초 누락, 실제 sandbox 키 하나만 분리한 회복, 이전 버전 상태의 Sparkle 재시험 PASS를 재사용한다.

같은 경로·빌드·importer 변경 시각으로 복사된 새 설치를 과거 요청 기록과 구분한다. 실제 파일 시스템 설치 식별을 추가하고 이전 receipt는 한 번 재요청해 전환한다. 일반 재실행은 중복 요청을 생략하며 발견/접수 실패는 다시 시도한다. 단위 테스트만으로 실제 색인 수용을 선언하지 않고 소유 격리 경로에서 같은 후보 bytes·시각과 receipt를 유지한 반복 설치를 검증한다.

Stage 8~10에서 제품/검증 도구/보고서를 보완하고 devel 대상 리뷰용 PR을 생성한다. 기존 /Applications 공개 앱·설정·사용자 문서와 기본 연결을 보존한다. 공개 버전 변경·서명·공증·배포와 이슈 종료는 이번 구현 범위 밖이며, 공개 배포 검증이 남으면 #513 / #337 을 열린 상태로 명시한다.
