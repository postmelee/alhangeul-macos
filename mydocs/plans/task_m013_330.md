# Task M013 #330 수행계획서

## 목적

GitHub 공개 본문과 코멘트를 등록하기 전에 `rg` 기반 validator를 통과하게 만들어, PR/Issue 참조 토큰이 한글 조사와 붙어 GitHub autolink가 깨지는 실수를 기계적으로 차단한다.

## 배경

Issue #132 및 PR #328 완료 처리 중 Issue 완료 코멘트 첫 줄의 `#328으로` 표기가 GitHub 참조로 안정적으로 표시되지 않는 문제가 확인됐다. 단순히 Skill 프롬프트에 문장 규칙을 반복 추가하는 방식은 누락 위험이 있으므로, 공개 GitHub 본문 등록 직전에 검사하는 공통 preflight가 필요하다.

## 범위

- GitHub 공개 본문/코멘트 파일 검증용 `scripts/validate-github-body.sh` 추가
- PR/Issue/comment body는 `--body-file` 기반으로 작성하고 validator 통과 후 등록한다는 운영 규칙 문서화
- 관련 Skill에서 `gh ... --body-file` 실행 전에 validator를 호출하도록 절차 보정
- validator 자체의 정상/실패 케이스 검증

## 제외

- GitHub 웹 UI에서 직접 작성한 코멘트의 사전 차단
- GitHub Actions `issue_comment`/`pull_request` 이벤트 기반 사후 감지 workflow
- GitHub CLI 자체 확장 또는 전역 alias 강제
- 새 label/milestone 생성

## 설계 방향

validator는 입력 파일을 인자로 받는 작은 shell script로 둔다. 금지 패턴은 `#123으로`, `PR #123은`, `Issue #123를`처럼 PR/Issue 참조 토큰 직후 한글 음절이 이어지는 경우를 잡는다. Skill과 매뉴얼은 regex를 복제하지 않고, 공개 GitHub 본문을 등록하기 전 `scripts/validate-github-body.sh {body-file}`를 실행해야 한다는 절차만 참조한다.

## 잠정 단계

1. Stage 1: 기존 GitHub 본문 등록 경로 inventory
   - `gh issue create`, `gh issue comment`, `gh pr create`, `gh pr comment`, `gh pr edit --body-file` 사용 지점을 찾는다.
   - validator 적용 대상과 제외 대상을 구분한다.
2. Stage 2: validator 스크립트 구현과 단위 검증
   - 실패해야 하는 붙임 조사 사례와 통과해야 하는 분리 표기 사례를 검증한다.
   - `rg --pcre2` 의존성과 실패 메시지를 명확히 한다.
3. Stage 3: 매뉴얼과 Skill 절차 보정
   - 공통 운영 규칙은 매뉴얼에 두고, 관련 Skill은 validator 호출만 짧게 연결한다.
   - inline `--body` 대신 `--body-file` 우선 원칙을 정리한다.
4. Stage 4: 통합 검증과 문서 정리
   - 관련 파일 검색, validator 샘플 검증, `git diff --check`를 수행한다.
   - 남은 예외와 GitHub UI 직접 작성 한계를 보고서에 기록한다.

## 검증 계획

- `scripts/validate-github-body.sh` 실패 샘플 검증
- `scripts/validate-github-body.sh` 통과 샘플 검증
- `rg -n "body-file|validate-github-body|gh issue comment|gh pr comment|gh pr create|gh issue create" ...`
- `git diff --check`
- 필요한 경우 `shellcheck` 또는 `bash -n scripts/validate-github-body.sh`

## 리스크

- GitHub 웹 UI에서 직접 작성하는 코멘트는 사전 차단할 수 없다.
- `rg --pcre2`가 없는 환경에서는 validator가 실행되지 않을 수 있으므로 의존성 메시지와 fallback 여부를 결정해야 한다.
- 한국어 조사 전체를 완벽히 문법 분석하지 않고, 참조 토큰 직후 한글이 붙는 위험 패턴을 conservative하게 차단한다.
- 너무 넓은 패턴은 코드블록이나 과거 사례 문서의 금지 예시까지 차단할 수 있으므로 공개 body-file 검증용으로 범위를 제한해야 한다.
