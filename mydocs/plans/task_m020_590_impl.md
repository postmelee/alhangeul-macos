## 2. 변경 계약

### 2.1 헤더와 배너

| 위치 | 변경 | 보존 조건 |
|------|------|-----------|

현재 다운로드 계약은 URL `https://github.com/postmelee/alhangeul-macos/releases/latest/download/alhangeul-macos-0.2.3.dmg`, 접근성 이름 `알한글 v0.2.3 DMG 다운로드`다. 다운로드를 시작하거나 설치하지 않고 링크와 이름만 검사한다.

- 새 링크는 기존 `.header-link`와 배너의 보조 링크 패턴을 재사용하고 같은 탭에서 연다. 드롭다운·아이콘만 있는 진입점·새 라이브러리는 추가하지 않는다.
- 다운로드는 기존 강조 버튼을 유지한다. 글꼴 안내처럼 기존 다운로드 버튼이 없는 간결한 헤더에도 대응하며, 전체 사이트 메뉴를 새 템플릿으로 교체하지 않는다.
- 글꼴 페이지의 현재 위치 표시는 nav 안에 한 개만 둔다. 최신 소식의 기존 `aria-current` 등 다른 페이지의 올바른 현재 표시는 유지한다.
- 기존 홈 FAQ·푸터의 글꼴 링크는 남긴다. 배너 링크는 릴리즈 설명과 같은 문맥에 배치하고 모바일에서 자연스럽게 줄바꿈한다.

### 2.2 반응형·접근성

- 큰 화면은 기존 한 줄 헤더를 유지한다. 700px 이하를 두 줄 배치의 시작 기준으로 삼고, 로고/기존 다운로드와 주요 안내 링크를 구분한다. 최종 간격·높이는 실제 화면으로 확인한다.
- 중간 폭에서는 긴 Windows/Linux·GitHub 보조 링크를 먼저 보조 위치로 옮겨 주요 안내의 공간을 확보한다. 820px·700px의 기존 규칙과 1024px 화면을 대조해 전환 폭을 정한다. 글꼴 안내·다운로드를 잘라 숨기지 않는다.
- 보조 링크가 헤더에서 숨겨지는 페이지에서는 푸터 등 기존 보조 탐색 영역에 같은 목적지로 연결한다. 이전 릴리즈에서는 푸터를 보완할 수 있으나 릴리즈 본문과 버전별 다운로드는 유지한다.
- `.site-header`의 sticky 동작과 `--header-height`, 관련 화면 높이/스크롤 여백을 함께 정렬한다. 글꼴 안내의 고정 `scroll-margin-top: 76px`도 두 줄 헤더에 가려지지 않도록 공통 높이를 참조한다.
- 기존 `.font-guide-page .header-actions` 간격과 `.has-news-nav` 전용 숨김/현재 위치 규칙을 검토해 공통 반응형 규칙과 충돌을 제거한다. 파일 끝에 같은 속성을 반복 덮어쓰는 방식은 피한다.
- 모바일의 링크·버튼 클릭 영역은 높이 44px를 목표로 잡는다. 문자를 지나치게 축소하거나 가로 스크롤을 기본 동선으로 만들지 않는다.
- nav 의미와 기존 논리적 읽기 순서를 유지한다. 양수 `tabindex`로 순서를 강제하거나 화면별 중복 메뉴를 만들지 않는다. 키보드 초점이 숨겨진 링크로 이동하거나 보이지 않는 곳으로 튀지 않는지 확인한다.
- 320px에서 가로 넘침·겹침이 없어야 하며 로고·글꼴 안내·기존 다운로드가 읽혀야 한다. 기존 skip link와 줄바꿈, 초점 표시, 현재 위치가 작동해야 한다.
- 필요한 CSS 참조는 21개 문서에서 `styles.css?v=20261015-font-navigation`으로 맞춰 이전 캐시와 섞이는 것을 줄인다. 나머지 자산·기능 캐시 정책은 바꾸지 않는다.

### 2.3 변경 전 증거와 보존

Stage 1 시작 시 `be8f4663` 기준을 고정하고 `build.noindex/task590/stage1/`에 아래 작은 manifest를 만든다. 원본 사이트·동영상 전체를 복사하지 않는다.

1. HTML 21개의 목록·헤더 주요 링크·CSS 참조, 홈 FAQ/푸터의 기존 글꼴 진입점.
2. 릴리즈 노트 16개의 `<main>...</main>` 원문 hash와 해당 페이지의 모든 다운로드 URL/접근성 이름. 헤더 밖의 이전 버전 안내 배너도 원문 hash로 보존한다.
3. 글꼴 안내 `<main>` hash와 최신 소식의 feed/container·외부 콘텐츠 안내 등 본문 hash.
4. 저장소 `docs/appcast.xml` 등 배포 피드 관련 tracked 파일의 hash. 현재 원격 공개 피드와 저장소 피드가 다를 수 있으므로 서로 같다고 가정하지 않는다.

구조 검사로 새 링크·CSS 참조·승인한 두 다운로드 변경을 검증하고 보존 구간을 원문과 대조한다. 이전 본문·배너까지 통째로 재직렬화하는 HTML 변환은 사용하지 않는다. 보존 실패를 기대값 갱신으로 넘기지 않고 해당 변경을 고친다.

### Stage 2 — 실제 화면·키보드·동작 검증

대표 화면의 검증표를 다음과 같이 사용한다. 화면의 높이는 실제 viewport와 함께 기록한다.

| 대상 | 화면 폭/동작 | 확인점 |
|------|-------------|--------|
| 홈 | 320·360·390·768·1024·1440px | 헤더·배너·본문 시작, 가로 넘침, 보조 링크 접근 |
| 글꼴 안내 | 320·390·1440px | 현재 위치, 간결한 헤더, 목차/섹션 앵커가 sticky 헤더에 가려지지 않음 |
| 최신 소식·문의·업데이트 목록 | 각 390·1024px | 메뉴 변형, 다운로드 이름/URL, 본문과의 충돌, 보조 링크 접근 |
| 최신/과거 노트 | v0.2.3과 v0.1.0 각 390·1440px | 글꼴 안내·과거 버전 배너·본문 다운로드 보존 |
| 경계 폭 | 홈 699/700/701px, 보조 링크 숨김 기준의 직전/직후 | 전환 시 메뉴 잘림·중복 표시·높이 오차 없음 |
| 키보드 | 홈·글꼴 페이지의 데스크톱/모바일 폭 | skip link, Tab/Shift+Tab, 초점 표시, Enter로 안내 도착, 숨김 링크 제외 |

- 브라우저의 실제 화면과 읽기 전용 DOM의 `scrollWidth/clientWidth`·요소 경계를 함께 확인한다. 숫자만 보고 시각 검증을 통과시키지 않는다.
- 홈 헤더와 배너를 각각 눌러 `/fonts/`에 도착하고, 대표 하위 페이지에서도 헤더 링크가 동작하는지 확인한다. 다운로드는 클릭하지 않는다.
- 뉴스의 외부 콘텐츠가 네트워크/동의 상태에 따라 달라질 수 있으므로 해당 상태를 기록하고, 외부 글 자체의 수집·UI 구조를 이 작업에서 수정하지 않는다.
- 같은 배치/범위 안의 CSS·링크 보정은 수행하되 새 메뉴 구조나 릴리즈 본문 변경이 필요해지면 범위를 먼저 확인한다. 보정한 경우 관련 폭·보존 검사만 다시 실행한다.
- 데스크톱 홈, 모바일 홈, 모바일 글꼴 안내의 대표 스크린샷을 파일 형식과 맞는 확장자로 저장한다. 화면은 응답에 직접 보여주고 사용자가 조작할 미리보기 주소·글꼴 안내 경로를 함께 제시한다.
- 직접 확인 환경은 Codex 내장 브라우저의 해당 viewport로 기록한다. 실제 iPhone/Android 또는 다른 브라우저에서 시험한 것으로 확대하지 않는다.
- `task_m020_590_stage2.md`에 결과·보정·남은 제한을 기록하고 커밋한다. Stage 3는 결과 수용·승인 후 실행한다.

완료 조건: 표의 실제 검증 항목이 PASS이고 예외/미검증 조건이 구분되며, 요청한 화면과 조작 가능한 미리보기가 제공됐다.

5. `mydocs/working/task_m020_590_pr_draft.md`에 devel 대상 PR 본문을 작성한다. 본문 문서 링크는 구체 commit SHA의 GitHub blob URL을 사용하고, `scripts/validate-github-body.sh`로 검사한다.
6. 최종 보고 수용 및 구체 head의 push/Open PR 게시 승인을 요청한다. 공개 CI·리뷰·병합·이슈 종료는 실제 게시·병합 후 승인 범위에서 수행한다.

완료 조건: 필요한 회귀와 보존/문서 검사가 PASS이며 최종 보고·화면·PR 초안·clean 로컬 커밋이 준비됐다. 원격 CI나 공개 웹 반영을 미리 PASS로 표시하지 않는다.

## 4. 산출물·저장 공간·도구

- 임시 manifest·서버 receipt·검사 출력: `build.noindex/task590/stage{1,2,3}/`.
- 장기 보관할 소수의 화면·검증 요약·checksum: `mydocs/report/assets/task_m020_590/`.
- 실행 서버의 PID·포트·제공 경로를 기록한다. 사용자 확인을 위해 서버를 유지하는 동안은 주소를 안내하고, 이후 목적이 끝나면 해당 PID만 종료한다.
- 스크린샷은 PNG/JPEG 등 실제 bytes에 맞는 확장자로 저장한다. 모든 viewport·문서의 중복 화면을 Git에 쌓지 않는다.
- `docs/` 원본을 직접 제공하므로 동영상/이미지 전체를 복사하지 않는다. 기존 공증 DMG·복원 자료·설치 앱·사용자 TXT와 다른 작업의 부산물은 건드리지 않는다.
- 앱/Rust 재빌드, 브라우저 설치, 의존성 설치, 전체 캐시/OS 색인 변경을 하지 않는다. 이 정적 변경에 필요한 도구가 없는 경우 기존 제공 도구를 먼저 사용하고 한계를 보고한다.

## 5. 범위 보정과 공개 반영

링크·간격·폭·헤더 높이·기존 보조 링크 위치의 조정은 위 계약 안에서 처리한다. 새 상호작용 메뉴, 사이트 생성/템플릿 구조, 릴리즈 원문·앱 기능·배포 workflow의 변경이 필요하면 계획 보정과 승인을 먼저 받는다.

이 문서 승인 후에도 각 단계 완료 시 다음 단계 승인을 받는다. 최종 보고 수용과 구체 push/Open PR 게시, 병합·이슈 close 및 main/Pages 반영은 각 시점의 승인 범위를 따른다. main의 `docs/**` 변경은 기존 docs-only Pages workflow를 유발하므로 공개 반영 직전 현재 public appcast를 읽어 보존 입력과 동시 배포 상태를 확인해야 한다. 이번 로컬 계획/화면 준비에서 공개 배포를 실행하지 않는다.
