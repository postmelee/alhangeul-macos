# Issue #433 수행 계획서

## 목적

HOP과 알한글의 Quick Look Preview가 같은 HWP/HWPX UTI를 지원하는 환경에서 provider 선택 충돌 가능성을 사용자에게 알리고, 설치된 버전과 검증된 `rhwp` provenance를 근거로 시스템 설정에서 알한글 미리보기를 사용하도록 안내한다.

## 배경

macOS Quick Look에는 동일한 UTI를 지원하는 여러 preview extension 사이의 공개 우선순위 설정이 없다. 이 Mac에서 HOP과 알한글이 함께 활성화된 상태에서는 HOP Quick Look Preview가 선택되었고, `issue1949_giant_cell_nested_tables_perf.hwpx`가 169페이지로 나뉘면서 2페이지 대부분이 비었다. HOP Preview를 비활성화한 뒤 알한글 Preview가 선택되자 같은 문서는 115페이지와 정상적인 2페이지 본문을 표시했다.

설치본 바이너리와 bundle metadata에서 확인한 기준은 다음과 같다.

- 알한글 `0.1.8` build `14`
  - Quick Look Preview `0.1.8`
  - `rhwp v0.7.18`
  - commit `93862a4`
- HOP 앱 `0.3.1`
  - Quick Look Preview `0.2.0`
  - `rhwp v0.7.13`

알한글은 이미 bundle provenance를 통해 자신의 `rhwp` 버전을 표시한다. 반면 샌드박스 HostApp은 `/usr/bin/pluginkit`으로 다른 확장의 활성 상태를 신뢰성 있게 조회할 수 없으므로, 공개 API로 HOP 설치와 bundle version을 확인하고 검증된 버전 매핑 범위에서만 `rhwp` 비교를 제공해야 한다.

## 범위

포함:

- `NSWorkspace` 기반 HOP 앱 설치 여부 감지
- HOP HostApp과 Quick Look Preview extension 버전 확인
- 알한글 `RhwpProvenance`와 검증된 HOP Preview 버전별 `rhwp` 매핑 비교
- 알려진 HOP Preview `0.2.0`을 `rhwp v0.7.13`으로 표시
- 알한글이 HOP보다 최신 `rhwp`를 포함한 경우에만 사실 기반 추천 문구 표시
- 알 수 없는 HOP Preview 버전에서 `rhwp` 버전을 `확인 불가`로 표시하고 최신 여부 단정 생략
- 기존 About 확장 상태 영역에 충돌 가능성 안내와 버전 비교 UI 통합
- `확장 프로그램 설정 열기`, `다시 확인`, `나중에` 사용자 동작 제공
- 감지·비교 정책의 단위 검증이 가능한 구조와 최소 회귀 검증 추가

제외:

- HOP Quick Look Preview 자동 비활성화
- Quick Look provider 우선순위 강제 변경
- `/usr/bin/pluginkit` 또는 비공개 PlugInKit API 호출
- HOP 실행 파일의 문자열을 런타임에 스캔해 `rhwp` 버전 추정
- 알한글 또는 HOP 업데이트·삭제
- `rhwp` core dependency 업데이트
- Quick Look/Thumbnail renderer 자체 변경

## 사용자 안내 원칙

- 절대적인 “최신 `rhwp`”가 아니라 “HOP Preview보다 최신인 `rhwp`”로 표현한다.
- HOP과 알한글의 앱·Preview·`rhwp` 버전을 구분해 표시한다.
- 경쟁 앱의 품질을 평가하지 않고 설치된 버전과 검증된 provenance만 설명한다.
- 공개 API로 실제 선택된 provider를 확인할 수 없으므로 “충돌”이 아니라 “충돌 가능성”으로 안내한다.
- 사용자가 직접 시스템 설정에서 확장 상태를 결정하며 알한글이 다른 앱의 확장을 변경하지 않는다.
- 설정 버튼을 누른 뒤 `확장 프로그램` 섹션에서 HOP 훑어보기를 끄고 알한글 훑어보기를 켜도록 행동 경로를 직접 안내한다.
- 설정 화면을 연 뒤에도 안내 팝업을 유지하며, `나중에`·`자세히 보기`·창 닫기에서만 해당 fingerprint를 확인한 것으로 기록한다.
- 알 수 없는 버전에서는 비교 추천 대신 일반적인 중복 provider 안내만 제공한다.

## 설계 방향

충돌 감지는 HostApp 소유 서비스로 둔다. `NSWorkspace.shared.urlsForApplications(withBundleIdentifier:)`로 `net.golbin.hop` 후보를 찾고, 접근 가능한 HOP app bundle과 `HopQuickLookPreview.appex` metadata에서 버전을 읽는다. 여러 설치본이 발견되면 LaunchServices의 적합도 순서를 존중하되 진단 정보에는 선택한 bundle URL과 버전을 남길 수 있는 구조를 검토한다.

알한글의 `rhwp` 버전은 기존 `RhwpProvenanceLoader`를 재사용한다. HOP의 `rhwp` 버전은 검증된 Preview extension 버전 매핑으로만 제공한다. 최초 매핑은 `0.2.0 -> 0.7.13`이며, 매핑이 없는 버전은 `.unknown`으로 처리한다. 런타임 binary scanning은 사용하지 않는다.

UI는 기존 About 창의 확장 섹션과 `ExtensionStatusModel` 갱신 흐름을 확장하는 방향을 우선한다. 안내는 경고 카드 또는 인라인 배너로 표시하고, “나중에”는 현재 표시만 닫되 새 앱 빌드나 감지 결과 변경 시 다시 평가할 수 있도록 저장 범위를 최소화한다.

시스템 설정 진입은 공개적으로 안정된 상위 설정 화면을 우선하고, 특정 Quick Look 하위 화면 deep link가 OS 버전에 따라 불안정하면 상위 `로그인 항목 및 확장 프로그램` 화면과 수동 경로 설명을 함께 제공한다.

## 검증 계획

- HOP 미설치, 알려진 Preview `0.2.0`, 알 수 없는 Preview 버전을 분리한 정책 검증
- 알한글 `rhwp v0.7.18`과 HOP `rhwp v0.7.13` 비교 결과 확인
- `xcodegen generate`
- `xcodebuild -project Alhangeul.xcodeproj -scheme HostApp -configuration Debug -derivedDataPath build.noindex/DerivedData CODE_SIGNING_ALLOWED=NO build`
- `./scripts/check-no-appkit.sh`
- `git diff --check`
- Debug HostApp About 창에서 안내 카드, 버전 표시, 다시 확인, 나중에, 설정 열기 동작 수동 확인
- 샌드박스 실행 로그에서 `pluginkit` 또는 비공개 API 호출이 없는지 확인

Quick Look provider 선택과 실제 HOP extension 활성 상태는 공개 API로 판정할 수 없으므로, 설치된 extension metadata와 안내 UI 동작을 이번 타스크의 검증 기준으로 삼는다. Finder provider 전환 smoke는 자동 변경 범위가 아니며 필요 시 사용자 선택 이후 별도 수동 확인으로 기록한다.

## 리스크

- 샌드박스에서 다른 앱 bundle 내부 extension metadata 접근이 OS 버전 또는 설치 위치에 따라 제한될 수 있다.
- HOP 앱 버전과 Preview extension 버전이 독립적으로 변경될 수 있으므로 HostApp 버전만으로 `rhwp`를 추정하면 안 된다.
- HOP이 vendored `rhwp`를 변경하면서 Preview version을 유지하면 정적 매핑의 신뢰 근거가 약해질 수 있다.
- 비공개 System Settings deep link는 macOS 업데이트로 동작이 바뀔 수 있다.
- 사용자에게 반복적으로 경고하면 피로도가 높아질 수 있으므로 표시 주기와 “나중에” 저장 범위를 보수적으로 정해야 한다.
- HOP이 설치되어 있어도 Preview extension이 이미 비활성화된 환경에서는 충돌 가능성 경고가 과잉 안내가 될 수 있다.
