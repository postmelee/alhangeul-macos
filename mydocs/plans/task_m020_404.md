# Task M020 #404 수행계획서

## 목적

upstream `edwardkim/rhwp`의 최근 렌더 관련 PR이 알한글 Quick Look preview와 Finder thumbnail에 어떤 방식으로 반영되는지 대표 샘플 diff로 측정한다.

측정 결과를 바탕으로 upstream 개선이 기존 render tree + Swift CoreGraphics/CoreText 경로에 자동 반영되는 축과, Skia opt-in 또는 Swift renderer 보강이 필요한 축을 분리한다. 후속 구현 이슈는 추측이 아니라 샘플 diff 결과에 근거해 등록한다.

## 배경

알한글의 현재 release 기본 경로는 Quick Look/Thumbnail에서 RustBridge render tree를 Swift CoreGraphics/CoreText renderer로 그리는 방식이다. Skia PNG backend는 opt-in 또는 diagnostic backend로 유지한다.

최근 upstream `rhwp` PR은 page geometry, line height, row break, anchor, image/BinData, chart/RawSvg, group/transform, text/equation/endnote/font/clip 계열 정합을 계속 개선하고 있다. 이 중 page geometry와 기존 node 좌표 보정은 알한글에 자연 반영될 가능성이 크지만, RawSvg 일반 SVG, group-level transform, external image data, CoreText clipping/font fallback처럼 Swift renderer가 별도 해석하는 영역은 downstream 보정이 필요할 수 있다.

이 작업은 #387 `Preview/Thumbnail Skia readiness 후속 개선 추적`의 후속 측정 작업으로 둔다.

## 범위

포함:

- upstream 최근 렌더 관련 PR을 대표 샘플군으로 묶어 출처를 기록한다.
- RawSvg/차트, Group/shape/transform, external/large image data, text/equation/font/clip/endnote, page geometry baseline 후보를 측정한다.
- core SVG, render tree JSON, Swift native PNG, 가능한 경우 Skia PNG를 같은 입력 기준으로 비교한다.
- 각 후보를 `자동 반영`, `Skia 전환 후보`, `Swift CoreGraphics 보강 필요`, `upstream 대기/별도 조사`로 분류한다.
- 후속 구현 이슈 후보와 우선순위를 정리한다.

제외:

- upstream `rhwp` 수정 자체
- unreleased upstream commit의 release default pin 적용
- Skia를 Quick Look/Thumbnail release default로 즉시 전환
- Swift CoreGraphics renderer 구현 보강
- HostApp native viewer/editor 전환
- release, signing, notarization, Homebrew Cask 작업

## 설계 방향

측정은 먼저 현재 알한글 저장소의 `rhwp-core.lock` 기준을 확인하고, upstream PR별 샘플을 알한글 측 비교 도구에 투입 가능한 형태로 분류한다. 저장소에 없는 upstream 샘플은 장기 fixture로 바로 편입하지 않고, 임시 산출물 또는 후속 test asset 이슈 후보로 분리한다.

비교 기준은 `render-debug-compare.sh`의 core SVG, render tree JSON, native PNG 산출물을 중심으로 둔다. Skia PNG가 필요한 샘플은 기존 M020 Skia diagnostic 경로와 smoke script를 재사용할 수 있는지 먼저 확인한다.

판정은 pixel diff 숫자 하나로 하지 않는다. 구조 누락, blank/fallback, page size/aspect ratio, glyph/clip, image data, group transform, RawSvg fallback 여부를 hard fail로 먼저 분리하고, anti-aliasing이나 1px rounding 계열은 별도로 기록한다.

후속 구현 후보는 다음처럼 분리한다.

- `RawSvg/차트`: 일반 SVG vector 또는 chart SVG가 Swift fallback으로 떨어지는 경우
- `Group/shape/transform`: render tree schema 또는 group-level matrix 적응이 필요한 경우
- `external/large image data`: image node와 byte data 계약이 어긋나거나 external context ABI가 필요한 경우
- `text/equation/font/clip/endnote`: CoreText, equation SVG parser, table cell clip, footnote/endnote ordering 차이가 남는 경우
- `page geometry baseline`: core update만으로 자동 반영되는지 확인하고 별도 구현 없이 release note/known limitation으로 충분한 경우

## 잠정 단계

1. Stage 1: upstream PR별 대표 샘플 후보와 알한글 측 입력 가능성을 조사한다.
2. Stage 2: 비교 명령, 산출물 위치, backend별 측정 표 형식을 확정한다.
3. Stage 3: 대표 샘플군의 core SVG/render tree/native PNG/Skia PNG 비교를 실행하고 hard fail을 분류한다.
4. Stage 4: downstream 보정 후보와 후속 이슈 분리안을 정리한다.
5. Stage 5: 최종 보고서에 측정 결과, residual risk, 후속 권고를 남긴다.

## 검증 계획

기본 검증:

```bash
git diff --check
```

측정 단계에서 사용할 후보 명령:

```bash
./scripts/validate-stage3-render.sh
./scripts/render-debug-compare.sh output/task404-render-debug path/to/sample.hwp
./scripts/render-debug-compare.sh output/task404-render-debug --page 1 path/to/sample.hwpx
```

Skia/Quick Look/Thumbnail 관련 후보 명령은 Stage 2에서 기존 M020 스크립트와 연결 가능성을 확인한 뒤 확정한다.

## 리스크

- upstream `devel` 샘플이 현재 알한글이 고정한 `rhwp v0.7.17`에 없는 behavior를 전제하면 직접 측정과 release tag 반영 판단을 분리해야 한다.
- upstream 샘플을 저장소에 바로 편입하면 fixture 크기와 provenance 관리 부담이 생긴다. 이번 작업은 샘플 편입 여부를 후속 권고로 남긴다.
- `qlmanage` 또는 Skia diagnostic 측정은 로컬 Quick Look 상태, sandbox, cache 상태에 민감할 수 있다. 필수 산출물과 선택 산출물을 구분한다.
- core SVG와 Swift native PNG 차이가 실제 사용자 문제인지, anti-aliasing/rasterizer 차이인지 눈검증이 필요하다.
- 측정 결과가 여러 축으로 흩어질 경우 하나의 구현 이슈로 묶지 않고 후속 이슈를 작게 분리해야 한다.
