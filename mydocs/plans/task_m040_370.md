## 목적

upstream `edwardkim/rhwp` root `Cargo.lock`이 git 추적 대상으로 전환된 점을 downstream 운영에 반영한다. 앱 저장소의 기존 core provenance 기준인 `RustBridge/Cargo.lock`과 `rhwp-core.lock`은 유지하면서, upstream release sync와 bundled `rhwp-studio`/WASM 검증에서 dependency graph 재현성을 더 명확히 기록하고 검증한다.

## 배경

upstream issue #1423은 root `Cargo.lock`을 추적해 CLI/WASM/build 산출물의 dependency graph를 재현 가능하게 만드는 변경이다. 현재 downstream 앱은 `RustBridge` crate의 lockfile과 `rhwp-core.lock`으로 native bridge source provenance를 검증하지만, bundled `rhwp-studio`/WASM asset provenance에는 upstream root `Cargo.lock` fingerprint가 없다.

따라서 upstream `Cargo.lock`은 downstream lockfile을 대체하는 값이 아니라, upstream release asset과 sync 작업의 추가 provenance 입력으로 다루어야 한다. 이 작업은 그 역할 구분을 스크립트와 문서에 반영하고, locked build 검증이 가능한 경로를 보강한다.

## 범위

포함:

- `scripts/build-rust-macos.sh`의 RustBridge cargo build 경로에서 `--locked` 적용 가능성 확인 및 반영

- upstream release sync PR 본문 또는 release delta checklist에서 `Cargo.lock` 변경을 dependency graph 변화로 식별하도록 보강
- core dependency/release 운영 문서에 upstream root `Cargo.lock`과 downstream `RustBridge/Cargo.lock`의 역할 차이 명시

제외:

## 설계 방향

lockfile의 소유 경계를 명확히 유지한다. `RustBridge/Cargo.lock`은 downstream native bridge 빌드의 Cargo 해석 결과이고, upstream root `Cargo.lock`은 upstream release checkout에서 만들어지는 CLI/WASM/studio build input의 fingerprint로 취급한다.

RustBridge build에는 lockfile drift를 조기에 잡기 위한 `--locked` 사용을 우선 검토한다. 이 변경은 dependency graph를 바꾸지 않고, `Cargo.toml`과 `Cargo.lock` 불일치가 있는 경우 실패하도록 하는 검증 강화로 제한한다.

`rhwp-studio` manifest에는 upstream checkout의 root `Cargo.lock` sha256과 존재 여부를 기록한다. 검증 스크립트는 이 필드가 비어 있거나 manifest provenance와 맞지 않는 경우를 실패로 처리하되, 과거 asset과의 호환성 필요 여부는 구현 단계에서 별도로 판단한다.

release sync 자동화는 `Cargo.lock` 변경을 사용자-facing 기능 변경으로 단정하지 않는다. 대신 core/studio build input 변화로 분류하고, PR 검토자가 dependency graph 변경 여부를 빠르게 볼 수 있게 요약한다.

## 잠정 단계(3~6단계)

1. 기존 lock/provenance 경로 조사
   - RustBridge build, core update, rhwp-studio sync, upstream sync PR body, release delta checklist가 현재 어떤 lock 정보를 쓰는지 정리한다.
   - upstream root `Cargo.lock`을 추가 provenance로 넣을 위치와 호환성 범위를 확정한다.
2. RustBridge locked build 검증 보강
   - cargo build 경로에 `--locked`를 적용하고 기존 `Cargo.lock`/`rhwp-core.lock` 검증과 충돌하지 않는지 확인한다.
   - 실패 메시지가 dependency fetch failure, Cargo.lock mismatch, artifact mismatch와 구분되는지 검토한다.
3. rhwp-studio/WASM manifest provenance 보강
   - sync script가 upstream root `Cargo.lock` hash를 기록하고 verify script가 이를 검증하도록 수정한다.
   - 기존 manifest 검증과 release tag/commit 검증 흐름을 유지한다.
4. release sync/delta 가시성 보강
   - upstream release diff에서 `Cargo.lock` 변경을 dependency graph 변경으로 분류하고 PR body 또는 checklist에 표시한다.
   - 사용자-facing 변화와 build input 변화가 섞이지 않도록 문구를 조정한다.
5. 문서와 최종 검증
   - core dependency 운영 문서에 upstream/downstream lockfile 역할 차이를 반영한다.
   - 전체 스크립트 smoke와 문서 검증 결과를 단계 보고서와 최종 보고서에 남긴다.

## 리스크

- upstream root `Cargo.lock`과 downstream `RustBridge/Cargo.lock`의 역할을 혼동하면 잘못된 검증 기준이 생길 수 있다.
- `--locked` 적용이 의도치 않게 기존 개발자의 local Cargo workflow를 막을 수 있으므로, build script 범위와 오류 안내를 명확히 해야 한다.
- bundled `rhwp-studio` manifest schema를 강화하면 기존 asset 검증과 과거 release artifact 검사에 영향을 줄 수 있다.
- upstream release diff에서 `Cargo.lock`은 noisy할 수 있으므로, 기능 변경으로 오분류하지 않고 dependency graph 변경으로만 표시해야 한다.
- 실제 `rhwp v0.7.17` 이상 sync는 이번 작업 범위가 아니므로, 검증 fixture와 현재 pinned release의 차이를 보고서에 분리해 남겨야 한다.
