# Task #595 — 그림 삽입 파일 선택창 연결 수행계획서

## 목적

HWP/HWPX 편집 중 그림 버튼을 누르면 현재 문서 창에 파일 선택창이 열리고, 선택한 그림을 본문에 배치하고 저장할 수 있게 한다.

## 배경

macOS 27.2 Beta의 v0.2.3에서 제보됐고 macOS 26.5.2의 v0.2.4 (22)에서도 버튼 클릭 후 선택창이 나타나지 않았다. Studio는 HTML 파일 입력을 호출하고 편집 WKWebView에는 UI delegate가 없다. 진단 앱에서 delegate가 선택 결과를 반환하자 취소와 PNG·JPEG 배치, 두 문서 형식의 저장·재열기가 동작했다. 실제 선택창의 사용자 조작은 제품 검증에 남아 있다. [이슈 및 대조 시험](https://github.com/postmelee/alhangeul-macos/issues/595#issuecomment-6969806085)

## 범위

알한글 편집 WKWebView에서 WebKit 파일 선택 요청을 받아 문서별 패널을 표시하고 결과를 반환한다. Studio의 이미지 형식 처리·배치·저장은 기존 경로를 사용한다. 업스트림 동기화, Finder 확장, 정식 릴리스는 별도 작업이다.

## 설계 방향

현재 편집기를 소유한 Coordinator를 WKUIDelegate로 연결한다. 패널은 요청한 webView.window에 붙이고 WKOpenPanelParameters의 단일·복수 선택 및 디렉터리 허용 정보를 확인한다. 같은 delegate가 다른 HTML 파일 입력에도 적용되므로 그림 전용 확장자 제한을 일괄 적용하지 않는다. 선택 시 URL, 취소·창 부재 시 nil을 정확히 한 번 반환한다. 요청 중 창 닫기와 편집기 해제 시 패널 종료 및 콜백 소유권을 명시한다.

## 예상 변경 파일

- `Sources/HostApp/Views/RhwpStudioWebView.swift`의 makeWebView, Coordinator 및 해제 경로.
- `Sources/HostApp/Services/DocumentOpenPanel.swift`의 시트 사용 방식을 참고한다. 문서 열기와 WebKit 선택의 정책 차이를 유지한다.
- `Tests/StudioDocumentLifecycleSmoke/`와 `scripts/smoke-studio-document-lifecycle.py`의 기존 검증 진입점을 검토하고 누락된 회귀 사례를 추가한다.

## 잠정 단계

1. 파일 요청의 발신 뷰와 창 수명, 기존 문서 열기 패널의 사용 조건을 확인하고 구현계획에 콜백 종료 조건을 기록한다.
2. 편집 호스트에 delegate와 파일 선택 시트를 연결한다. 선택·취소·창 종료·두 창 간 독립성을 검증한다.
3. 실제 버튼과 패널을 거쳐 배치·저장·재열기를 검증하고 제보 환경에서 추가로 확인할 항목을 기록한다.

## 검증 계획

- 앱 빌드 후 서로 다른 두 문서를 열고 두 번째 창에서 그림 버튼을 누른다. 그 창에만 시트가 붙는지, 취소 후 문서가 수정되지 않고 다시 선택 가능한지 확인한다.
- PNG와 JPEG 각각을 실제 패널에서 선택해 지정 위치에 배치한다. 각 이미지를 HWP와 HWPX로 저장한 뒤 다시 열어 네 조합 모두 첫 페이지에 해당 그림이 보이는지 확인한다.
- 패널이 열린 상태에서 창을 닫은 뒤 다른 문서에서 다시 시도한다. 중복 콜백, 남은 패널, 멈춘 파일 입력이 있는지 확인한다.
- 합성 문서와 공개 가능한 이미지를 사용한다. 빌드와 GUI 증거는 T7 아래 build.noindex에 두고 사용 OS·앱 빌드·시험 결과를 남긴다.

## 리스크

전면 창을 사용하면 다른 문서에 시트가 붙을 수 있다. WebKit이 delegate를 약하게 보관하므로 Coordinator 수명과 해제 순서를 확인한다. 자동으로 URL을 반환하는 시험만으로는 실제 패널 표시 문제를 놓칠 수 있어 사용자 조작 경로를 완료 기준에 포함한다.

## 승인 요청 사항
