# M010 · #615 번들 Studio의 최초 열기 빈 화면 수정 수행계획서

## 목적

문서를 한 번 열면 첫 페이지의 본문이 표시되고, 그 시점에 로딩 완료 상태가 나타나도록 한다. [알한글 #615](https://github.com/postmelee/alhangeul-macos/issues/615)

## 배경

알한글 0.2.4(22)와 Firefox 확장에서 첫 열기 직후 빈 페이지가 남고 재열기하면 복구되는 현상이 보고됐다. 번들 Studio v0.9.0의 격리 Chromium 실험에서 최초 페이지 준비 도중 글꼴 완료 이벤트를 발생시키면 하단에 3페이지가 표시되지만 실제 문서 캔버스는 0개였다. 실제 HostApp에서 같은 경합이 발생하는 조건은 1단계에서 검증한다. [업스트림 #9164](https://github.com/edwardkim/rhwp/issues/9164)

## 범위

현재 고정한 Studio의 번들 빌드에 초기 렌더 보정을 적용하고 WKWebView 문서 열기 경로를 검증한다. 호스트 글꼴 수집 성능은 업스트림 #9165에서 추적한다. 배포 실행은 별도 승인 대상이다.

## 설계 방향

최초 문서의 페이지 목록이 생기기 전에 글꼴 갱신이 렌더 작업을 대체할 때, 현재 문서의 최신 작업이 목록 구성과 첫 화면 표시를 끝내도록 한다. 재열기나 임의 타이머를 사용하지 않고 기존 문서 교체·취소 규칙을 유지한다. 번들 생성 시 보정을 적용하고 예상 소스가 달라지면 빌드에서 감지한다. 업스트림 수정이 포함된 정식 릴리즈로 갱신할 때 같은 회귀 검사로 보정 제거를 검증한다.

## 예상 변경 파일

- `scripts/build-rhwp-studio.mjs` 및 초기 렌더 전용 빌드 어댑터
- `Sources/HostApp/Resources/rhwp-studio/`의 재생성 자산 및 출처 기록
- `scripts/smoke-studio-document-lifecycle.py`와 대응 WKWebView 검증 코드
- 필요 시 `scripts/verify-rhwp-studio-assets.sh`의 자산 일치 검사

## 잠정 단계

1. 합성 문서로 실제 HostApp WKWebView에서 최초 로드 중 글꼴 완료 이벤트를 한 번 발생시켜 실패 대조군을 확보한다.
2. 문서·렌더 세대 전환을 보정하고 고정 소스에서 Studio 번들을 재생성한다.
3. 같은 대조군과 정상 열기, 반복 글꼴 통지, 빠른 문서 교체를 검증하고 업스트림 반영 후 보정 제거 조건을 기록한다.

## 검증 계획

실행 전 T7 검증 출력 경로를 확인한다. 두 합성 문서의 첫 페이지에 서로 다른 식별 표식을 둔다. 최초 열기 완료 시 실제 페이지 캔버스와 첫 문서의 표식이 모두 보이는지 확인한다. 첫 렌더가 대기 중일 때 두 번째 문서를 열고, 지연된 앞 문서 통지가 끝난 뒤에도 두 번째 표식과 쪽수가 유지되는지 확인한다. 글꼴 통지가 없는 정상 열기와 재열기를 대조하고 번들 자산 검증을 실행한다.

## 리스크

캔버스 개수만 검사하면 빈 캔버스를 성공으로 오판할 수 있다. 첫 화면 표식을 함께 확인한다. 연속 글꼴 통지가 무한 재시도를 만들거나 이전 문서 작업이 새 문서에 반영될 가능성이 있어 반복 통지와 교체를 별도로 검증한다. 강제 이벤트로 재현한 결과와 자연 발생 관측은 구분해 기록한다.

## 승인 요청 사항

이 계획 승인 후 구현계획을 구체화하고 1단계의 WKWebView 통제 재현을 진행한다.
