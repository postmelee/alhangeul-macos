## 목적

릴리즈 배포를 요청받을 때 작업자와 에이전트가 먼저 읽고 그대로 따라갈 수 있는 public release 실행 runbook을 작성한다. 기존 릴리스/배포 매뉴얼 묶음의 세부 절차는 유지하되, 실제 배포일에 필요한 입력값 확정, 최신 릴리즈 비교, workflow 실행, 검증, Homebrew 반영, 중단/rollback 판단을 한 문서에서 순서대로 확인할 수 있게 한다.

## 배경

Issue #79는 Task #78 이후 실제 public release 당일에 참고할 메인테이너 전용 실행 문서가 필요하다는 후속 작업이다. 현재 저장소에는 `release_distribution_guide.md`와 하위 매뉴얼들이 충분히 존재하지만, 릴리즈 때마다 여러 문서를 오가며 현재 버전, 직전 public release, upstream `rhwp`, workflow 기본 입력, Cask 상태를 재검증해야 한다.

2026-05-30 현재 확인한 기준은 다음과 같다.

- 최신 공개 앱 릴리즈: `v0.1.3`
- 최신 공개 앱 릴리즈의 bundled `rhwp`: `v0.7.12`
- 현재 `devel`의 `rhwp-core.lock`과 bundled `rhwp-studio` manifest: `v0.7.13`
- 현재 app/extension plist version: `0.1.3 (9)`
- 현재 release workflow 기본 입력: `version=0.1.3`, `previous_release_ref=v0.1.2`, `expected_rhwp_tag=v0.7.12`
- 현재 repository Cask source: `0.1.2`

따라서 runbook은 고정 명령 나열보다, 매 릴리즈 시작 시 stale 기본값과 최신성 불일치를 잡아내는 preflight 문서여야 한다.

## 범위

## 설계 방향

새 runbook은 `release_distribution_guide.md`를 대체하지 않고 실행용 상위 문서로 둔다. 세부 정책은 기존 하위 매뉴얼에 링크하고, runbook에는 릴리즈 당일 순서와 판정 기준만 둔다.

문서는 다음 흐름으로 구성한다.

1. 시작 전 권한과 중단 원칙
2. 현재 release context 수집
3. release identity 확정
4. release candidate source preflight
5. rehearsal 실행과 delta checklist 보정
6. public publish workflow 실행
7. GitHub Release, Pages, Sparkle 확인
8. 설치본과 Finder 통합 smoke
9. Homebrew Cask 반영 gate
10. release record, 최종 보고, rollback

명령 예시는 실제 secret 값을 포함하지 않고 placeholder 또는 비밀이 아닌 운영 식별자만 사용한다. workflow 기본값은 stale할 수 있음을 전제로, 매번 입력값을 수동 확인하도록 쓴다.

## 리스크

- runbook이 기존 세부 매뉴얼 내용을 과도하게 복제하면 이후 정책 변경 시 문서 drift가 생길 수 있다.
- workflow 기본값과 현재 release candidate 값은 릴리즈마다 달라지므로, 문서에는 특정 버전을 고정하지 않고 예시와 검증 절차를 분리해야 한다.
- 최신 upstream `rhwp`와 앱 release candidate의 불일치는 의도된 예외일 수 있으므로, runbook은 실패 조건과 release owner 예외 승인 조건을 구분해야 한다.
- Homebrew Cask는 GitHub Release public DMG SHA256 확정 이후에만 갱신할 수 있으므로, runbook에서 release publish와 Homebrew 반영을 같은 성공 조건으로 묶지 않아야 한다.
