## 목적

HostApp에서 core가 처리할 수 있는 HWP 3.0 문서를 열기 전에 잘못 차단하는 문제를 수정한다. 사용자가 HWP 3.0 샘플 문서를 앱으로 열었을 때 "HWP/HWPX 형식이 아니거나 손상" 오류 화면으로 빠지지 않고, bundled `rhwp-studio` 경로까지 정상 전달되도록 한다.

## 배경

사용자 제보 파일 `/Users/melee/Documents/projects/forks/rhwp/samples/hwp3-sample16.hwp`는 헤더가 `HWP Document File V3.00`인 HWP 3.0 문서다. 별도 분석에서 현재 고정된 `rhwp v0.7.16` core는 이 파일을 직접 파싱하고 렌더링할 수 있었으며, `render-debug-compare.sh` 기준 64쪽 문서로 처리되었다.

문제는 HostApp 열기 흐름의 사전 검증 계층에 있다. Swift 쪽 `HwpDocumentInputValidator`는 HWP5 CFB magic과 HWPX ZIP magic만 허용하고, HWP 3.0 signature를 지원 문서로 인정하지 않는다. 또한 HostApp이 bundled `rhwp-studio`에 문서 URL을 넘긴 뒤에도 Studio 쪽 원격 문서 byte guard가 CFB/ZIP만 문서 byte로 인정하므로, Swift validator만 수정하면 WebView 내부에서 다시 차단될 가능성이 있다.

## 범위

포함:

- HostApp 공용 입력 검증에서 HWP 3.0 signature 허용
- bundled `rhwp-studio`의 URL 문서 로드 byte guard에서 HWP 3.0 signature 허용
- HWP5/HWPX 기존 허용 경로와 손상/미지원 파일 거부 경로 유지
- 제보 샘플 파일 기준 재현과 수정 후 smoke 검증
- 변경 범위와 잔여 위험 문서화

제외:

- HWP 3.0 렌더링 품질 자체의 개선
- `rhwp` core parser/renderer 변경
- Quick Look/Thumbnail extension 동작 변경
- 지원하지 않는 파일 열기 실패를 모달 UX로 바꾸는 작업. 이는 #372에서 별도 처리한다.
- HWP 3.0 fixture를 저장소에 새로 추가하는 결정. 필요성이 확인되면 별도 승인 후 진행한다.

## 설계 방향

Swift validator에는 HWP 3.0 문서 헤더 prefix를 명시적으로 추가한다. 정확한 제보 파일 signature는 `HWP Document File V3.00`이며, 같은 3.x 계열의 patch/minor 표기를 고려해 `HWP Document File V3.` prefix 기반 검증을 우선 검토한다. 기존 HWP5 CFB magic과 HWPX ZIP magic 판정 순서는 유지하고, 너무 짧은 데이터나 임의 텍스트가 우연히 통과하지 않도록 최소 prefix 길이 기준을 둔다.

Studio 쪽은 HostApp에 bundled된 정적 `rhwp-studio` asset에서 원격 문서 byte guard를 같은 기준으로 확장한다. 이 변경은 upstream Studio source와 bundle asset 사이 drift가 생기기 쉬우므로, 실제 구현 단계에서 현재 저장소가 bundle만 소유하는지, upstream source 갱신 절차가 필요한지 확인하고 가장 작은 변경으로 처리한다.

오류 문구와 전체 failure UX는 이번 작업에서 바꾸지 않는다. #371은 core가 지원하는 HWP 3.0 문서가 미지원 파일처럼 차단되는 것을 풀어 주는 작업으로 제한하고, 실패 후 복구 가능한 모달 전환은 #372의 범위로 남긴다.

## 리스크

- bundled `rhwp-studio` asset이 minified build 산출물이라면 변경 의도 추적과 향후 upstream 갱신 시 보존이 어렵다.
- HWP 3.0 signature 허용 폭을 과하게 넓히면 비문서 파일을 오탐할 수 있으므로 prefix와 최소 길이를 보수적으로 잡아야 한다.
- core가 제보 샘플은 처리하더라도 모든 HWP 3.x 변형을 완전히 렌더링한다고 단정할 수 없다.
- 외부 샘플 파일은 저장소에 포함되어 있지 않으므로 CI 자동 회귀 테스트에는 별도 fixture 정책이 필요할 수 있다.
