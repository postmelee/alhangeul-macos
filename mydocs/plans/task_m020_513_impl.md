# Task M020 #513 구현계획서

## Stage 1: 기준 고정과 기존 실패 재현

선행 SHA·패키지 서명과 실행 파일 hash·fixture를 확인한다. 활성 smoke, 프로세스, importer/provider를 읽어 공유 시스템을 점검한다. 기존 표준 smoke의 prepare → environment → install → launch 결과와 elapsed time을 기록하고 실패 후에도 정리한다.

## Stage 2: 조건 분리와 검증 절차 보완

기존 helper의 수동 `lsregister -f`, `mdimport -i` 경로와 별개로 순수 복사/첫 실행/검색 경로를 만든다. 중첩 위치와 일반 Applications 바로 아래의 고유 소유 앱을 비교할 수 있도록 경로 소유권 검사를 유지한다. 복사 후 timestamp만 변경, 재등록만 수행, 첫 실행 순서/관찰 시간을 각각 기록한다. 기존 사용자 동일 ID 앱은 제거하지 않으므로 그 영향은 실험으로 확정할 수 없는 한 한계로 남긴다.

일반 설치 판정에서 수동 재색인·touch·강제 등록·재설치가 섞이면 통과를 거부하도록 회귀 검증한다. 제품 코드는 원인 근거가 있을 때만 최소 변경한다.

첫 비교에서 자동 발견 성공과 기존 문서 자동 검색 실패가 갈려, 발견 후 새 합성 문서 자동 색인과 기존 문서 재색인을 추가로 구분한다. 동일 importer 변경 시각의 반복 등록 이력 영향을 확인하기 위해 소유 소스 사본의 importer 디렉터리 시각만 바꾸는 진단 비교를 추가한다. 이 사본의 성공은 일반 설치 수용 기준을 통과한 것으로 쓰지 않는다.

## Stage 3: 실제 결과와 후속 PR 준비

설치 전 corpus의 HWP3/HWP5/HWPX 영문 및 HWP5/HWPX 한글 독립 단어, 대조군 제외, 후보 선택, 앱 종료 후 검색을 확인한다. 같은 경로 교체와 수정/삭제 전파는 최초 설치와 구분한다. 실패·미실행은 그대로 기록하고 소유 시험 앱/문서/등록 제거와 기존 앱/provider 보존을 검증한다. 검증 명령·합성 공개 증거·보고서 및 PR 본문 초안을 준비한다.

## 검증

Python 운영/소유권 회귀, 변경 파일 구문 검사, `git diff --check`, 실제 macOS smoke. 패키지/앱 변경 시 build 가이드의 해당 최소 검증을 추가한다. 공개 서명/공증 및 없는 macOS 12/Intel 환경은 실행하지 않는다.

## Stage 4: 병합 전 최신 개발 후보 재검증

선행 PR의 CI 기본 도구 수정과 최신 devel을 통합하고 universal Release 개발 패키지를 새로 생성한다. 운영 23개·bundle 5개 회귀와 rg 없는 환경의 직접 callback 13사례를 확인한다. 새 합성 corpus와 격리 경로에서 기존 자동 설치/검색 판정을 한 번 재실행하고 성공·실패 그대로 기록한 뒤 정리한다. 이 단계는 조사 PR의 검증이며 신규 원인 비교·제품 수정·공개 서명/공증·출시는 수행하지 않는다. #513과 #337은 열린 상태를 유지한다.

## Stage 5: TXT 양성 대조와 자동 색인 전제 조사

PR #514 병합 기준 devel 56fe1ca에서 재개한다. 일반 TXT의 직접 생성과 fixture 복사를 같은 소유 경로에서 비교해, 신규 파일 색인 지연·복사 metadata·검색 도구 전제를 분리한다. 시스템 전체 색인은 초기화하지 않고 진단용 TXT와 state를 모두 정리한다. 대조가 확보되면 최신 패키지의 자동 발견과 설치 전 문서 색인을 새 state로 다시 측정한다. 필요한 제품 또는 검증 도구 변경은 원인 증거와 Apple 문서에 근거하고, 제품 변경·회귀·최종 후보 검증·후속 PR까지 진행한다.

Stage 5 관찰에서 새 TXT 복사/직접 생성 모두 색인됐고, 새 후보는 첫 실행 12초에 발견됐지만 설치 전 HWP/HWPX는 검색되지 않았다. 외부 LSRegisterURL 성공 후에도 동일했고, 최소 App Sandbox 진단에서 `mdimport -r` 요청 후 세 형식 본문 및 한글 검색/실제 후보 추출/앱 종료 후 검색이 통과했다. 앱 내부 LSRegisterURL은 -10819를 반환했으나 이 요청은 추가 entitlement 없이 성공했다. 이에 기존 Quick Look 유지보수 완료 기록과 별개인 백그라운드 Spotlight 요청을 추가한다. 요청은 bundled importer 형식으로 한정하고 설치 위치·빌드·importer 변경 시각별 접수를 기록한다. 실패/timeout은 기록하지 않아 다음 실행에 재시도한다. 접수와 색인 완료는 구분한다. 새 패키지의 첫 실행 전에 corpus를 준비해 수동 보조 없는 최종 검증을 수행한다.

최초 구현의 -r 요청 접수 이후에 importer가 발견되어 기존 파일 색인이 누락됐으므로 발견 확인을 선행하도록 보완했다. 180초 후보는 실제 발견이 약 286초까지 지연되어 재실행에서만 자동 요청/검색이 통과했다. 최종 후보의 발견 대기는 600초이며, 실패/재실행 결과와 새 경로 첫 실행 결과를 분리한다. 요청 정책 테스트를 PR CI에도 연결한다.


## Stage 6: PR #515 리뷰 보정

2026-09-10 작업지시자가 리뷰 보정과 완료 코멘트 게시를 승인했다. 발견 조회의 일시 실패를 같은 deadline 안에서 재시도하고 stdout/stderr를 분리한다. 명령 timeout은 남은 발견 시간으로 제한한다. 가짜 시계·조회 결과를 사용해 실패 후 회복과 최종 시간 초과를 검증하고 진단 출력이 섞인 subprocess 회귀를 추가한다.

앱별 live 의존 연결과 유지보수 순서 정책을 분리하여 주입된 UserDefaults와 Spotlight 시작 호출을 함께 검증한다. 기존 유지보수 완료 기록이 있어도 시작하고, importer가 없으면 요청하지 않으며, 테스트에서는 시스템 등록이나 실제 mdimport를 실행하지 않도록 한다. 제품의 URL 계산으로 실제 빌드 앱 내부 importer 존재/식별자를 대조한다. smoke의 발견 timeout 인자는 짧은 범위 오류로 보정한다.

여러 앱 사본의 접수 기록 관리와 PID 종료 정책 재설계는 이번 범위에 포함하지 않는다. Swift/Python 회귀, 앱 빌드 및 번들 계약, 최종 후보의 표준 자동 검색 smoke와 정리를 검증하고 결과 보고서·PR 본문·보정 코멘트를 갱신한다. 공개 배포·병합·이슈 종료는 하지 않는다.
