# Task M020 #278 수행계획서

## 목적

upstream `edwardkim/rhwp` 최신 stable release인 `v0.7.13`을 앱 저장소의 core provenance 기준으로 반영하고, Quick Look preview와 Finder thumbnail의 Skia/CoreGraphics 렌더 경로가 새 core 기준에서 회귀하지 않는지 확인한다.

이 작업은 #282 Stage 3 이후 구현을 stale `v0.7.12` payload 기준으로 진행하지 않기 위한 선행 작업이다.

## 배경

현재 앱 저장소의 `rhwp-core.lock`과 `RustBridge/Cargo.toml`은 `v0.7.12` / `1899ef9bc2dfd1c6c0c4d18b192d253a2d0a1fb5`를 가리킨다.

`v0.7.13`은 #278 본문에 기록된 upstream PR #947, #976, #982, #1018 계열을 포함하며, PageLayerTree text/display payload, resolved image payload, watermark bake/render 경로가 Quick Look/Thumbnail Skia 및 #282 compositor 후속 작업에 영향을 준다.

## 범위

포함:

- `scripts/update-rhwp-core.sh --channel stable --tag v0.7.13`로 release tag compatibility를 확인하고 core dependency를 갱신한다.
- `RustBridge/Cargo.toml`, `RustBridge/Cargo.lock`, `rhwp-core.lock`의 tag/resolved commit/provenance를 `v0.7.13` 기준으로 맞춘다.
- `scripts/build-rust-macos.sh --update-lock`로 Rust bridge 산출물과 reference metadata를 갱신한다.
- `rhwp-ffi-symbols.txt`, `Frameworks/generated_rhwp.h`, Swift bridge wrapper의 ABI 영향 여부를 확인한다.
- bundled `rhwp-studio` manifest/assets가 `v0.7.13` reference와 맞아야 하는지 판단하고, visual diff reference 일관성에 필요한 경우 `scripts/sync-rhwp-studio.sh` 경로로 함께 동기화한다.
- Quick Look/Thumbnail Skia 경로와 CoreGraphics fallback 경로 smoke를 새 core 기준으로 실행한다.
- #282로 넘길 v0.7.13 overlay payload 관찰값과 baseline 영향 범위를 기록한다.

제외:

- upstream `edwardkim/rhwp` 소스 수정
- unreleased commit pin 적용
- Swift PageLayerTree replay renderer 신규 구현
- #282 compositor Stage 3 구현 자체
- Skia backend default 전환 판단
- public release, signing, notarization, Homebrew 배포

## 설계 방향

Stable core 기준은 release tag와 resolved commit을 함께 고정한다. `main`, `devel`, floating branch는 사용하지 않는다.

Core update와 #282 compositor 구현을 같은 PR에 섞지 않는다. 이 작업은 `v0.7.13` provenance와 기본 렌더/bridge 회귀 여부를 먼저 고정하고, #282는 이 결과를 받은 뒤 branch를 최신 `devel`에 재정렬해 Stage 3를 이어간다.

bundled `rhwp-studio`는 `rhwp-core.lock`과 별도 provenance를 가진다. 다만 #280/#282 visual diff harness의 reference가 bundled `rhwp-studio`이므로, `v0.7.13` core만 올리고 studio reference를 `v0.7.12`에 남기는 구성이 측정값을 왜곡하는지 Stage 1에서 판단한다.

## 리스크

- `v0.7.13`의 Rust dependency graph 또는 native-skia build가 macOS universal static archive 생성 시간과 용량을 증가시킬 수 있다.
- `Frameworks/universal/librhwp.a` byte hash는 toolchain/build path에 민감하므로 source provenance, generated header, FFI symbol 검증과 구분해서 해석해야 한다.
- `v0.7.13` core만 올리고 bundled `rhwp-studio`를 그대로 두면 visual diff reference와 native renderer core가 다른 기준이 될 수 있다.
- upstream LFS 예산 문제로 release/source clone 중 대형 PDF smudge가 실패할 수 있다. core update script가 LFS smudge에 영향받는지 Stage 1에서 확인한다.
- #282 Stage 2 branch는 별도 worktree에 있으므로, 이 PR merge 뒤 #282 branch를 재정렬해야 한다.

## 승인 요청 사항

- 기존 열린 이슈 #278을 새 core update 작업의 추적 이슈로 사용한다.
- 기준 브랜치는 `devel`, 작업 브랜치는 `local/task278`로 진행한다.
- Stage 1에서 `v0.7.13` core update와 bundled `rhwp-studio` sync를 같은 PR에 포함해야 하는지 먼저 판단한다.
- 이 수행계획서 승인 후 Stage 1 구현 계획서를 작성하고 조사를 시작한다.
