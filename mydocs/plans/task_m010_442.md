# Issue #442 수행 계획서

## 목적

rhwp-studio v0.8.2의 ribbon 및 responsive layout과 충돌하는 HostApp WKWebView 전용 CSS를 최소 범위로 보정해, 최소·일반 창 폭에서 상단 도구 모음과 서식 도구 모음이 겹치거나 잘리는 회귀를 제거한다. 수정 결과를 `devel`에 통합할 수 있는 상태로 검증하고, Issue #441 v0.1.9 릴리스 후보가 새 통합 SHA에서 Release Rehearsal을 다시 수행할 수 있도록 인계한다.

Issue #441 Release Rehearsal run `30365232108`은 candidate SHA `1d358103a877a9d0b6c924a280b84e60e94d6739`에서 기술적으로 성공했다. 그러나 릴리스 소유자 visual QA에서 HostApp을 최소·일반 창 폭으로 표시하면 툴바가 겹치고 잘리며, 넓은 창에서는 정상처럼 보이는 회귀가 확인됐다. 따라서 해당 rehearsal artifact는 공개 릴리스 승인 후보로 사용하지 않는다.

bundled rhwp-studio v0.8.2는 `#style-bar`를 기본 `min-height: 68px`, `height: auto`, wrapping ribbon으로 구성하고, 768~1023px 구간에서는 grid 기반 다중 행 배치를 사용한다. 반면 저장소 소유 `alhangeul-wkwebview-overrides.css`는 이전 단일 행 UI 기준으로 `#style-bar` 높이를 32px에 고정하고, style/language/font field 폭도 이전 값으로 덮어쓴다. 로컬 override가 upstream의 새 layout ownership을 가리는 것이 이번 회귀의 직접 원인이다.

## 설계 방향

upstream bundle은 ribbon container 구조, responsive breakpoint, field 폭과 control 기본 크기를 소유한다. Alhangeul local stylesheet는 WKWebView가 native `select`를 데스크톱 Safari와 다르게 그리는 부분만 소유한다. 따라서 `#style-bar`, `#style-name`, `.sb-font-lang`, `.sb-font`처럼 upstream layout을 재정의하는 selector는 local override에서 제거하는 방향을 기본안으로 한다.

select 보정은 upstream의 27px control rhythm과 responsive 규칙을 깨지 않는 범위에서 `appearance`, 내부 padding, line-height, dropdown indicator 위치, disabled 색상만 조정한다. size/line-spacing group의 container 높이와 정렬도 upstream을 우선하고, WKWebView에서 실제로 필요한 속성인지 Stage 1에서 구분한다.

정적 guard는 generated upstream CSS의 해시나 전체 minified 내용을 고정하지 않는다. 대신 local override가 다시 `#style-bar` container 또는 upstream field width를 소유하지 않는다는 경계만 검증한다. 기존 `scripts/verify-rhwp-studio-assets.sh`에 단순하고 명확한 검사가 적합한지 확인하고, 과도하게 CSS 확장을 막는다면 별도 검증 명령과 단계 보고서 기준으로 제한한다.

시각 판정은 “넓은 창에서 보인다”만으로 통과시키지 않는다. breakpoint 전후를 포함한 각 폭에서 toolbar와 style bar의 경계, control clipping, horizontal overflow, label/field 정렬을 확인하고 light/dark 및 문서 로드 전후를 같은 기준으로 비교한다.

## 리스크

- local override를 과도하게 제거하면 WKWebView native select의 글자 수직 정렬이나 dropdown indicator가 다시 깨질 수 있다.
- 고정 높이만 제거하고 stale field width를 남기면 768~1023px responsive grid의 밀도와 정렬이 여전히 upstream과 다를 수 있다.
- 1023/1024px breakpoint 전후에서 ribbon 높이가 정상적으로 달라져도 이를 회귀로 오판할 수 있으므로 overlap/clipping 여부와 의도된 layout 변화를 분리해야 한다.
- source CSS가 정상이어도 app bundle에 이전 resource가 남으면 잘못된 visual 결과를 볼 수 있으므로 clean DerivedData 경로와 bundle resource 검증이 필요하다.
- dark mode에서 native select disabled 색상과 indicator 대비가 light mode와 다르게 보일 수 있다.
- 정적 guard가 selector 문자열만 과도하게 금지하면 향후 정당한 platform 보정까지 막을 수 있다.
- Debug app 실행이 LaunchServices에 개발 산출물을 등록할 수 있으므로 Finder 통합 검증과 혼동하지 않으며, 필요 시 표준 hygiene 절차로만 정리한다.
- Issue #442 PR merge 뒤 Issue #441 candidate가 새 merge SHA를 포함하지 않으면 이전 rehearsal 성공을 잘못 재사용할 수 있다.
