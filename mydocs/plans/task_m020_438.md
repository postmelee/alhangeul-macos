# Task M020 #438 수행계획서

## 목적

upstream `edwardkim/rhwp v0.8.2` full sync 후보인 PR #436을 최신 `devel`과 결합해 native core, bundled `rhwp-studio`, external image 경로, HostApp, Quick Look preview, Finder thumbnail의 호환성을 검증한다.

중간 버전 후보인 PR #429와 PR #435는 반영하지 않고 PR #436만 최종 sync 후보로 유지한다. 검증 결과로 PR #436의 merge 가능 여부와 다음 public release 타스크에 전달할 upstream 변화, 필수 smoke, 잔여 위험을 확정한다.

## 배경

현재 `devel`의 native core와 bundled `rhwp-studio`는 `rhwp v0.7.18` / `93862a4e16df59834ebce46d91e948cd739208e9`에 고정돼 있다. PR #436은 이를 stable release `v0.8.2` / `9b16aa9e23f476e2b335d7c029fc9f24a199d63c`로 갱신하며 `RustBridge` lock, core provenance, bundled studio와 WASM asset을 같은 upstream commit으로 맞춘다.

PR #436 head `c9e55c83aaeb9e8104b446e8c15c14f0da40c770`의 PR CI는 통과했다. 다만 이 PR은 `devel`의 `09953414276c0f31e20193cd9c2f6aa4662df209` 기준에서 생성됐고, 이후 PR #437 반영으로 Task #409의 Swift external image wrapper/resolver와 Quick Look 연결이 현재 `devel` `c968c1a4a059f31f5e9973900b276bbb00e452cb`에 추가됐다.

PR #436과 PR #437의 변경 파일은 직접 겹치지 않고 GitHub은 PR #436을 merge 가능한 상태로 판정한다. 그러나 기존 녹색 CI는 PR #437 반영 이후의 external image bridge, resolver, Preview 경로와 `v0.8.2` core를 함께 검증하지 않았다. 따라서 compile 성공뿐 아니라 provenance, ABI, external image unit test, 앱 target build, representative render와 Finder surface smoke를 최신 결합 상태에서 다시 확인해야 한다.

upstream commit ancestry는 `v0.7.18 → v0.7.19 → v0.8.0 → v0.8.2` 순방향이며 각 비교에서 `behind 0`임을 확인했다. PR #429와 PR #435는 PR #436으로 superseded 처리해 닫았으며, 이 타스크에서는 중간 generated asset을 순차 반영하지 않는다.

## 설계 방향

1. stable dependency 기준은 `v0.8.2` release tag와 resolved commit `9b16aa9e23f476e2b335d7c029fc9f24a199d63c`의 쌍으로 고정한다. branch나 floating ref를 검증·배포 기준으로 사용하지 않는다.
2. PR #436을 유일한 upstream sync 후보로 유지한다. PR #429와 PR #435의 generated asset 또는 lock을 다시 가져오지 않는다.
3. `local/task438`에는 계획·단계·최종 보고 문서만 커밋하는 것을 기본으로 한다. 최신 `devel + PR #436` 제품 상태는 별도 격리 worktree/임시 통합 ref에서 검증해 PR #436 변경을 타스크 PR에 복제하지 않는다.
4. 통합 후보는 검증 시작 시점의 `origin/devel`과 PR #436 head SHA를 고정해 재현한다. 검증 도중 `devel`이 전진하면 기존 결과를 최신 상태의 통과로 간주하지 않고 영향 범위를 다시 판정한다.
5. core source provenance, Cargo resolved commit, generated header와 FFI symbol 검증은 필수 gate로 둔다. `librhwp.a` byte hash 차이는 toolchain/build path 민감도를 분리해 기록하되 source·ABI 실패를 숨기는 근거로 사용하지 않는다.
6. Task #409 external image 경로는 Rust C ABI, Swift wrapper, resolver policy, QLExtension load 연결의 계층별 검증으로 나눈다. ThumbnailExtension은 현재 기능 경계를 유지하면서 build와 renderer 회귀를 확인한다.
7. Quick Look/Thumbnail 등록 smoke는 표준 smoke 절차 안에서만 실행하고 종료 시 개발 산출물 등록 해제와 hygiene 검사를 확인한다.
8. PR branch update, CI 재실행, PR merge 같은 GitHub mutation은 해당 단계 조사 결과를 보고하고 작업지시자 승인 후 수행한다.
9. public release 준비와 배포는 PR #436 merge 확인 뒤 별도 `Release Operations` 이슈로 진행한다.

## 리스크

- `v0.7.18..v0.8.2` upstream 범위는 3,028개 changed path와 482개 viewer/WASM/core impact path를 포함한다. compile 성공만으로 bundled editor와 renderer의 사용자-visible 회귀가 없다고 판단할 수 없다.
- PR #436의 기존 녹색 CI는 PR #437 반영 전 base를 사용했다. latest `devel`과의 파일 충돌이 없더라도 external image runtime 계약이 유지된다는 근거는 별도 검증이 필요하다.
- PR #436에는 generated JS/CSS/WASM/font 자산이 포함된다. entrypoint와 service worker manifest가 서로 다른 build 산출물을 가리키면 앱 build가 성공해도 WKWebView runtime에서 실패할 수 있다.
- Rust static archive의 byte hash와 size는 compiler, Xcode, build path 차이에 민감하다. reference mismatch와 source/ABI mismatch를 구분하지 않으면 정상 build를 실패로 오판하거나 실제 drift를 놓칠 수 있다.
- 격리 통합 후보를 만든 뒤 `devel` 또는 PR #436 head가 전진하면 검증 기준이 stale해질 수 있다. 모든 보고서에 base/head SHA를 기록해야 한다.
- Quick Look/Thumbnail registered smoke는 macOS extension cache와 기존 설치본 영향을 받는다. 표준 cleanup을 누락하면 이후 Finder 동작과 다른 타스크 검증을 오염시킬 수 있다.
- upstream 회귀가 발견되면 PR #436 merge와 public release를 보류해야 한다. 별도 제품 수정이나 upstream 수정은 새 범위 승인 없이는 진행하지 않는다.

## 승인 요청 사항

1. 기준 통합 브랜치는 `devel`, 타스크 브랜치는 `local/task438`로 진행한다.
2. PR #436을 유일한 upstream sync 후보로 유지하고 PR #429와 PR #435는 닫힌 상태를 유지한다.
3. `local/task438`에는 타스크 문서만 커밋하고, latest `devel + PR #436` 제품 상태는 격리된 임시 통합 후보에서 검증한다.
4. stable 기준은 `v0.8.2` / `9b16aa9e23f476e2b335d7c029fc9f24a199d63c`으로 고정한다.
5. 위 4개 잠정 단계와 core/studio provenance, external image, 앱 target, Finder surface 검증 gate를 승인한다.
6. PR #436 branch refresh, CI 재실행, merge와 public release는 조사·검증 결과를 보고한 뒤 각각 별도 승인을 받는다.

수행계획서 승인 전에는 구현계획서 작성, 격리 통합 후보 생성, core/studio 검증, PR 상태 변경 또는 merge를 진행하지 않는다.
