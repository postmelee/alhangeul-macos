# Task M900 #584 수행계획서

## 1. 목적과 현재 승인 범위

[이슈 #584](https://github.com/postmelee/alhangeul-macos/issues/584)에 따라 rhwp v0.8.7과 Mac 설치 글꼴 자동 사용을 포함한 Alhangeul v0.2.3 후보를 준비한다. 최종 signed/notarized DMG의 설치·글꼴·문서·출력·Finder 수용을 거쳐 검증한 동일 파일을 공개하는 것을 전체 목표로 둔다.

2026-10-12 작업지시자는 준비된 이슈 본문·제목·마일스톤·라벨을 확인하고 **“이슈 등록·수행계획 준비 승인”**으로 이슈 등록, 작업 브랜치, 오늘할일과 수행계획서 준비를 승인했다. 승인한 초안을 그대로 등록했으며 공개 이슈의 본문·상태·마일스톤·라벨이 원본과 일치함을 확인했다. 이 승인에는 제품 소스 구현, tag, 서명·공증, 임시 설치 또는 공개 배포가 포함되지 않는다.

2026-10-12 작업지시자의 **“수행계획 승인·구현계획 작성 진행”**으로 범위·5단계·수용 기준을 승인받아 [구현계획서](task_m900_584_impl.md)를 작성했다. 이후 **“구현계획 승인·Stage 1 진행”**으로 read-only 조사·문서를 실행해 [Stage 1](../working/task_m900_584_stage1.md)을 완료했다. 현재는 Stage 1 결과 수용·Stage 2 승인 대기이며 제품 소스 변경·설치/공개는 하지 않았다. 명시 호출 전용 타스크 SKILL은 이번 준비에서 호출하지 않았다.

## 3. 포함 범위와 출시 판정

- v0.2.2 이후 병합 PR의 제목·본문·연결 이슈·최종 보고서를 대조하여 사용자 변화, 내부 구현, 검증 도구, 웹 문서, 릴리즈 운반을 구분한다. 원시 diff 또는 자동 closing reference만으로 해결 목록을 만들지 않는다.
- 네 bundle의 버전/빌드와 필요한 release workflow 입력, 릴리즈 본문·장기 기록·Pages 후보·Mac 안내를 준비한다. 미공개 v0.2.3을 최신 다운로드·Sparkle·Homebrew 제공 버전으로 먼저 표시하지 않는다. README의 개발 기준과 공개 기준도 구분한다.
- Mac 글꼴 안내는 설정(⌘,) → 글꼴 → Mac에 설치된 글꼴 사용 → 기존 시스템 글꼴 목록에서 선택하는 동선을 중심으로 한다. 별도 가져오기 창을 필수 동선으로 다시 소개하지 않는다.
- 최종 일반 Release 설정의 signed/notarized universal DMG를 새로 검증한다. #569 수용에서 사용한 진단 flag·고유 보관함 임시 앱의 결과를 최종 배포 DMG 성공으로 대신하지 않는다.
- 기존 공개 앱에서의 실제 Sparkle 업데이트·재실행, 동일 DMG 설치, Spotlight/Finder 및 로컬 글꼴의 문서·출력 동선을 확인한다.
- 공개·Pages/Sparkle 및 Homebrew는 각각 승인된 정확한 산출물에서 실행한다. Homebrew를 별도 후속으로 분리해야 한다면 제공 버전과 미완료 조건을 명시하고 작업지시자의 판정을 받는다.

열린 [#480 암호 문서 저장](https://github.com/postmelee/alhangeul-macos/issues/480)과 [#525 복구 후보](https://github.com/postmelee/alhangeul-macos/issues/525)는 Stage 1에서 최신 코드·기존 증거·후속 변경을 대조하고 필요한 후보 재현을 계획한다. 이전 릴리즈에서 수용한 한계를 새 후보에도 자동 적용하지 않는다. 암호 문서의 무경고 평문 덮어쓰기처럼 문서 보호에 영향을 주는 동작이 남아 있으면 공개 전 차단 또는 별도 수정 필요성을 판단하여 제시한다. 문제를 이미 해결됐다고 표시하거나 이번 승인으로 수정 범위를 자동 확대하지 않는다.

## 4. 제외와 지원 한계

Windows ZIP/외부 글꼴 가져오기 [#566](https://github.com/postmelee/alhangeul-macos/issues/566), Finder 현재성 검사 추가 최적화 [#581](https://github.com/postmelee/alhangeul-macos/issues/581), 신규 upstream/API 확장, renderer 기본값 전환, 저장/복구 기능 수정 자체는 제외한다. 필요한 제품 수정이 발견되면 독립 이슈·범위 승인을 거친다. #566 / #581 은 Mac 기능 공개의 자동 선행 조건으로 만들지 않는다.

Mac 기능은 활성 설치 글꼴의 원본을 읽어 사용한다. 한컴 앱 내부 글꼴 자동 추출, 한컴 제거 후 모든 글꼴 유지, 전체 글꼴 영구 복사와 동일한 보장을 하지 않는다. 일반 TTF/OTF의 검증된 Regular/Bold 범위를 안내하고, TTC 개별 face·가변 축·HFT·외부 사용 허가 또는 레이아웃 완전 동일성을 보장하지 않는다. 기존 fsType/권한·원본 상실·fallback 경계는 유지한다.

기존 public v0.2.2와 보존된 v0.2.1 draft/tag/자산을 변경·삭제하지 않는다. 사용자 OS 글꼴 변경·전역 캐시 초기화·다른 앱의 등록 변경·물리 인쇄는 포함하지 않는다.

## 5. 예상 5단계

| 단계 | 주요 산출물 | 종료 기준과 다음 gate |
|------|-------------|-----------------------|
| 1. 맥락·변경·출시 기준 | 포함 PR 분석, 버전/빌드·core/Studio 대조, #480/#525 영향 판단, DMG 수용표 | 출처·위험·검증 범위가 구체화되고 제품 소스 변경 없이 다음 준비 범위를 승인받음 |
| 2. 소스·안내 후보 준비 | 네 bundle·필요 workflow 입력, 릴리즈·Pages·Mac 안내 후보, 회귀 및 준비 보고/PR 본문 | 최소 검증·화면 검토·최종 준비 보고 승인 후 devel 대상 게시·CI·검토·병합 |
| 3. 고정 후보·설치 수용 | main 릴리즈 PR, 정확한 source SHA/tag, signed/notarized draft DMG, ARM/Intel VM 설치 기록 | 각 실행 gate 승인 후 동일 hash의 최초 설치·기록 유지 재설치·종료 후 검색·cleanup PASS |
| 4. 동일 DMG 실제 Mac 수용 | 실제 설정·글꼴·저장/출력·Finder·Spotlight 수용 증거, 임시 시험 시 복원 기록 | 로컬 글꼴 ON/OFF·재실행, HWP/HWPX 저장/재열기, PDF, 인쇄 취소, Finder 및 기존 동작 수용 |
| 5. 동일 파일 공개·사후 확인 | public hash·Pages/appcast, 실제 이전 버전 업데이트, Homebrew 판정, 최종 기록 | 별도 공개 승인 후 동일 DMG 게시·사후 검증·최종 보고·이슈/브랜치/부산물 정리 |

위 단계는 전체 release execution 흐름이다. Stage 2의 소스 준비 PR 전에는 준비 범위의 최종 결과보고서를 작성하고 승인받는다. 전체 이슈는 후보 PR 병합만으로 닫지 않으며, Stage 3–5의 실행·수용·공개 결과로 같은 릴리즈 기록과 최종 보고서를 갱신한다. 각 단계 소스/문서와 단계 보고서는 함께 커밋한다. 구현계획서에서는 필요한 하위 단계, 파일, 검증 명령, 실행 gate를 정한다.

## 6. 검증과 완료 기준

| 검증 영역 | 계획과 한계 |
|-----------|-------------|
| 출처·identity | 네 bundle 버전/빌드, lock/generated build info/Studio 자산·어댑터 출처, main/source content gate, tag source·DMG hash 대조 |
| 준비 소스 | 변경 유형별 최소 build·XCTest·Studio Node·shell/release helper 검증과 PR CI. 새 변화·실패·미해결 우려가 없으면 이미 통과한 광범위 검증을 반복하지 않음 |
| 웹 안내 | 로컬 desktop/mobile·키보드 동선 및 사용자 직접 확인, 실제 제공 버전·다운로드·Homebrew 표시, 공개 전 상태와 기존 appcast 보존 |
| 최종 DMG | Developer ID·공증/staple·Gatekeeper·arm64+x86_64 slice·layout·source/run/artifact/hash 확인. 재빌드한 다른 파일의 결과를 합치지 않음 |
| ARM/Intel VM | 기존 release-first-install schema 3 절차의 최초 설치·같은 버전 재설치·종료 후 검색·lifecycle·정리. 실제 Intel Mac GUI 글꼴 수용으로 확대하지 않음 |
| 실제 Mac 글꼴 | 실제 감지 목록·기존 메뉴·선택·권한·재실행 유지, 일반 Regular/Bold와 원본/보관함 경계 확인. 가상 목록 또는 고운바탕 한 개 probe를 전체 감지로 소개하지 않음 |
| 문서·출력·Finder | HWP/HWPX 저장·재열기, PDF 글꼴/텍스트·확대 확인, macOS 인쇄 패널 취소, Quick Look/Thumbnail 및 Spotlight, 기존 닫기·종료 동작 |
| 공개와 업데이트 | 검증한 동일 hash의 공개 URL·Pages 안내·Sparkle appcast 대조, 기존 v0.2.2의 실제 다운로드·설치·자동 재실행·문서/확장 확인 |

완료는 승인된 후보 identity와 알려진 문제 판정, 준비 소스/CI, 동일 signed/notarized DMG의 설치·Mac 수용, 동일 파일 공개·사후 검증, Homebrew 반영 또는 승인된 후속 분리, 최종 보고/정리를 모두 확인한 상태다. 실행하지 못한 최소 macOS 12, Intel 실기기 GUI, 물리 인쇄 등은 미검증으로 기록하고 통과한 환경과 합산하지 않는다.

#580 작업에서 수용된 반복 비용과 최초 <300ms 미충족 이력을 유지한다. 새 릴리즈 수용에서 확인한 수치를 앱 실행시간 또는 모든 Mac의 성능 상한으로 확대하지 않는다. 후속 최적화가 새 필수 완료 조건으로 되돌아오지 않게 한다.

## 7. 공개 시점과 승인 gate

수행계획 승인 → 구현계획 작성 → 구현계획/Stage 1 승인 → 단계별 보고·승인을 따른다. 소스 수정 전 승인을 받고, scope 변경·신규 제품 수정 필요성이 생기면 보정안을 먼저 제시한다.

Git tag, Release Publish DMG, 로컬 인증서 사용·임시 앱 설치, 공개 승격, Pages/Sparkle, Homebrew 반영은 [runbook](../manual/public_release_runbook.md)의 각 gate에서 정확한 후보·입력·hash·설치 대상·백업/복원을 제시해 승인받는다. 수행계획 승인만으로 모든 실행 gate를 넘지 않는다. 실패 또는 identity 불일치 시 공개하지 않고 원인·회복 범위를 기록한다.

Pages는 main의 docs 변경으로 자동 배포될 수 있으므로 main 운반 PR에서 공개 timing과 public asset gate를 확인한다. 공개 전에는 v0.2.2가 최신 제공 버전이라는 사실과 기존 feed를 유지하며, 승격 후에야 v0.2.3의 설치·Mac 안내가 실제 제공 상태와 맞도록 확인한다.

## 8. 저장 공간과 부산물

초기 관측 가용 공간은 약 15GiB다. 이번 계획 준비에서는 앱/core/DMG를 새로 만들지 않았다. 이후 build.noindex/task584 아래에 후보와 중간 산출물을 배치하고, 기존 증거·사용자 변경·원래 앱 백업·확정 후보·공개 hash 파일을 먼저 보존한다.

재사용 가능한 core/Studio 입력과 필요한 검증 receipt는 유지한다. 재생성 가능한 중복 빌드·실패 후보 앱·목적을 마친 임시 DMG 등만 크기·활성 프로세스·복원 필요성을 확인한 뒤 작업 범위 안에서 정리한다. 삭제 용량과 실제 가용 공간 변화는 구분하고, 저장 공간만을 위해 전역 캐시나 이전 공개 자산을 지우지 않는다.
