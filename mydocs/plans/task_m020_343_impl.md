# Task M020 #343 구현계획서

## Stage 1: 구현·검증 지원 범위 정합성 확인

#338~#342 설계·본문 계약·Rust/CFPlugIn 구현·실제 검증 보고서를 대조한다. 사용자 기능, 내부 metadata 동작, 실제 색인과 배포 검증을 구분하고 출시 전 확인할 항목을 정리한다. README의 현재 공개 버전과 core pin은 확인만 한다.

## Stage 2: 사용자·운영 문서와 릴리스 초안

README에 개발 중인 Spotlight 항목과 별도 지원 안내를 연결한다. 지원 안내에는 형식/본문 범위·보호 제외·OCR 제외·한도·로컬 색인·가시성·검색 지연·삭제 지연을 설명한다. 운영 가이드에는 기존 표준 smoke 링크와 실제 실패 분류를 연결한다. mydocs/release/v0.2.0.md는 미공개 초안으로 만들고 버전/빌드 번호/태그·asset·배포 feed를 바꾸지 않는다.

## Stage 3: 문서 링크·명령·지원 범위 교차 검증

문서 내부 링크·코드 경로와 CLI 인자, 지원 한도와 제외 정책을 실제 소스 및 선행 증거와 대조한다. 공개 v0.1.11 표시와 pin/Info.plist/Pages/appcast가 그대로인지 diff로 확인한다. 계획/Stage/commit/최종 보고서 링크를 SHA로 고정한 Open PR을 생성한다. UI 변경이 없어 새 스크린샷을 합성하지 않으며 실제 시험 화면은 #342 보고서로 연결한다.

## 수용 기준

문서가 확인된 개발 후보 검색 결과와 v0.2.0 공개 여부를 구분한다. 일반 최초 설치, macOS 12/Intel runtime, Developer ID/공증·Sparkle 업데이트 등 남은 관문을 명시한다. 보안/지원 정책을 구현 이상으로 보장하지 않는다.

## Stage 4: 실제 검색 검증 후 문서 정렬

#342 Stage 5의 실제 검색·수정·삭제 및 Spotlight 화면 증거를 반영한다. 기존 미검증 표현을 최신 결과로 바꾸되 최초 설치 자동 발견, 최소 OS/Intel runtime 및 공개 배포 관문은 남긴다. 선행 변경을 merge로 가져오고 제품 버전·core pin·공개 배포 자산의 불변과 문서 링크를 검사한다.
