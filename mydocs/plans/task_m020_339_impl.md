# Task M020 #339 구현계획서

## Stage 1: core 추출 후보·모델과 샘플 조사

고정 commit의 parser, DocumentCore Unicode, page text, Semantic IR 경로를 조사한다. 공개 저장소 샘플에서 HWP5/HWPX 본문·표·글상자·수식·메모 후보를 선정한다. API가 파싱 뒤 레이아웃 또는 추가 변환을 수행하는지 소스로 확인한다.

## Stage 2: 추출 품질·비용 비교와 계약 확정

Rust example로 동일 입력의 파싱, Semantic IR, DocumentCore 열기와 Unicode/페이지 텍스트 추출의 실행 시간·결과 길이를 측정한다. 본문 내용을 로그에 복제하지 않는다. 이는 경로 선택 근거이며 품질 점수 또는 전체 자원 상한으로 해석하지 않는다. 소스상 순회 범위와 손실 정책을 합쳐 추출 계약을 작성한다.

## Stage 3: 정책·ABI 수용 기준 검증과 인계

입력 형식, 보호 문서, 포함/제외 컨트롤, Unicode와 delimiter, 자원 한도, 상태/소유권을 하나의 계약으로 고정한다. #340 구현에서 검증할 양성·음성·경계 사례를 명시한다. 측정 명령과 환경, 미검증 범위를 최종 보고서에 기록하고 템플릿에 맞춰 PR을 생성한다.

## 수용 기준

추출 경로 결정이 현재 core 코드와 재현 가능한 측정에 근거한다. 부분 추출과 빈 결과를 오류와 구분하며 parser 이전/이후 한도의 차이를 명시한다. macOS 12 runtime과 공개 배포는 미실행 상태로 인계한다.
