# Task M040 #460 수행계획서

## 목적

PDF 저장과 일반 인쇄가 공유하는 `RhwpStudioPagePDFRenderer`의 offscreen `WKWebView`를 정적 page SVG 렌더에 필요한 최소 권한으로 제한한다. 문서에서 유래한 SVG에 script, event handler 또는 외부 리소스 참조가 포함돼도 실행이나 HTTP/HTTPS 요청이 발생하지 않게 하고, 기존 page geometry와 searchable text, PDFKit 인쇄 결과는 유지한다.

## 배경

Issue #455와 PR #458에서 upstream `rhwp-studio`가 생성한 page SVG를 HostApp으로 전달하고, 전용 `WKWebView`의 `createPDF` 결과를 PDF 저장과 인쇄가 공유하도록 통합했다. 현재 renderer는 `loadHTMLString`으로 SVG를 HTML body에 직접 넣고 `defaultWebpagePreferences.allowsContentJavaScript = true`로 구성한다. 페이지 크기는 navigation 완료 후 HostApp이 `evaluateJavaScript`로 SVG의 width, height, viewBox와 bounding rect를 읽어 계산한다.

이 경로는 main editor WebView와 분리돼 있고 bundled upstream SVG를 입력으로 사용하지만, 문서 유래 SVG가 항상 수동 콘텐츠만 포함한다고 HostApp 경계에서 검증하지 않는다. SVG의 `<script>`, inline event handler, `<image>`·`<use>`·CSS URL 같은 외부 참조가 WebKit에서 실행 또는 요청으로 이어질 가능성을 renderer 자체의 정책으로 차단해야 한다. 다만 content JavaScript 비활성화가 HostApp이 직접 실행하는 metrics script까지 막는지, embedded image에 필요한 `data:` 참조를 어느 범위까지 허용해야 하는지는 구현 전에 실제 deployment target인 macOS 12 이상에서 확인해야 한다.

## 범위

포함:

- offscreen PDF renderer의 `WKWebViewConfiguration`, webpage preferences와 data store 최소 권한화
- `allowsContentJavaScript = false`에서 SVG 자체 script·event handler와 HostApp `evaluateJavaScript`의 동작 차이 검증
- `default-src 'none'`을 기준으로 한 CSP와 navigation/resource 차단 정책 결정
- HTTP/HTTPS 외부 subresource, top-level navigation, popup과 frame/object/connect 요청 차단
- upstream page SVG의 embedded image·font에 필요한 `data:` 참조와 불필요한 `blob:` 참조의 허용 범위 확정
- script, event handler, external URL, `data:`와 `blob:` 참조를 포함한 합성 SVG fixture 및 자동 회귀 테스트
- portrait, landscape, mixed-orientation SVG의 page count·geometry·searchable text·nonblank PDF와 PDFKit print operation 회귀 검증
- macOS 12 deployment target에서 항상 참인 availability 검사와 불필요한 optional chaining 정리
- architecture 문서에 page SVG trust boundary, 허용 resource와 renderer 보안 계약 기록

제외:

- bundled `rhwp-studio` SVG 생성기 또는 `rhwp` core 수정
- main editor WebView의 JavaScript, navigation 또는 resource 정책 재설계
- HWP/HWPX 입력 전체나 범용 SVG를 대상으로 하는 sanitizer 구현
- SVG 내용을 재작성해 문서 요소를 제거하는 범용 정규화
- 전체 export deadline, 진행률, 사용자 취소 또는 Issue #459의 중복 요청·stale callback 방어
- Quick Look과 Thumbnail의 render tree 기반 bitmap 경로 변경
- 릴리즈, 서명, 공증 또는 배포 작업

## 설계 방향

보안 경계는 PDF·인쇄가 공유하는 `RhwpStudioPagePDFRenderer` 내부에 둔다. main editor WebView나 upstream payload 생성기를 신뢰 기반으로 확장하지 않고, renderer가 받은 각 page SVG를 잠재적으로 능동 콘텐츠가 포함된 문자열로 취급한다.

우선 `WKWebsiteDataStore.nonPersistent()`와 popup 비활성화, content JavaScript 비활성화를 적용한 격리 configuration을 검토한다. Stage 1에서 `allowsContentJavaScript = false`가 page 안의 `<script>`와 event handler는 막으면서 HostApp의 `evaluateJavaScript` 호출은 허용하는지 실제 WebKit 테스트로 확인한다. HostApp metrics script가 정상 동작하면 현재 DOM 기반 width/height/viewBox/bounding rect 해석을 유지한다. 동작하지 않으면 root SVG의 명시적 width, height와 viewBox를 Swift에서 안전하게 해석하고, bounding rect가 필요한 경우에만 권한을 넓히지 않는 대체 측정 경계를 설계한다.

HTML wrapper에는 `default-src 'none'`을 출발점으로 CSP를 넣고 script, connect, frame, object, media와 외부 navigation을 거부한다. inline renderer CSS와 upstream의 실제 page SVG가 사용하는 embedded image/font만 최소 허용 후보로 둔다. `data:`는 네트워크 요청이 아니지만 중첩 SVG나 예상하지 않은 MIME을 포함할 수 있으므로 실제 upstream fixture를 조사해 필요한 directive와 타입만 남긴다. `blob:`은 정적 payload에 필요하다는 근거가 없으면 허용하지 않는다.

CSP만으로 top-level navigation과 모든 WebKit 버전의 subresource 차단을 가정하지 않는다. `WKNavigationDelegate`에서 renderer가 시작한 내부 문서 이외의 navigation을 취소하고, 필요하면 `WKContentRuleList` 또는 동등한 공개 WebKit 정책을 방어선으로 추가한다. HTTP/HTTPS 요청 검증은 `URLProtocol`에 의존하지 않고 test-local loopback endpoint나 WebKit에서 관측 가능한 격리 probe를 사용해 실제 요청 횟수가 0인지 확인하는 방향을 우선한다.

정책과 HTML 생성은 가능한 한 순수 값 타입 또는 작은 helper로 분리해 CSP, 허용 scheme와 wrapper 내용을 단위 테스트할 수 있게 한다. WebView 통합 테스트는 script sentinel, navigation, network probe와 PDF 결과를 함께 검증하되 외부 인터넷에 의존하지 않는다. 새 Swift 파일을 추가하면 `project.yml`의 HostAppTests 명시 source 목록을 갱신하고 `xcodegen generate`로 Xcode project를 재생성하며, `Alhangeul.xcodeproj`는 직접 수정하지 않는다.

## 검증 계획

- content JavaScript 비활성화 상태에서 SVG `<script>`와 `onload`·`onclick` sentinel이 실행되지 않는지 확인
- 외부 HTTP/HTTPS `<image>`, `<use>`, CSS URL, iframe/object/connect 계열 fixture가 test-local endpoint에 요청을 만들지 않는지 확인
- 허용하지 않은 top-level navigation과 popup이 취소되는지 확인
- `data:` embedded image/font의 필요 범위와 `blob:` 거부 정책을 합성 fixture와 실제 upstream page SVG로 검증
- HostApp metrics script 또는 대체 metrics parser가 width/height, viewBox와 fallback 우선순위를 유지하는지 검증
- portrait, landscape, mixed-orientation payload의 page count와 media box 방향·크기 확인
- PDF text extraction에 합성 fixture의 한글·영문 sentinel이 남고 각 page raster가 nonblank인지 확인
- `PDFDocument.printOperation` 생성과 기존 orientation policy 회귀 확인
- HWP/HWPX 대표 fixture의 PDF export 결과를 page count, geometry, text, raster 기준으로 PR #458 기준과 비교
- 실제 인쇄 패널에서 세로·가로·혼합 문서 preview가 올바른 방향으로 표시되는지 수동 확인
- `xcodegen generate`
- clean `HostAppTests`
- clean HostApp Debug build
- `./scripts/check-no-appkit.sh`
- `./scripts/verify-bundled-studio-assets.sh` 등 기존 bundled asset 검증 명령 유지
- `git diff --check`

정확한 `xcodebuild` 명령과 smoke fixture는 구현계획서에서 저장소 build/run 가이드와 현재 test scheme을 기준으로 확정한다. 네트워크 검증은 외부 서버나 공개 집계를 사용하지 않고 로컬 격리 환경에서 수행한다.

## 리스크

- `allowsContentJavaScript = false`가 WebKit 버전에 따라 HostApp `evaluateJavaScript` 또는 SVG layout 시점에 예상과 다르게 영향을 줄 수 있다.
- CSP를 지나치게 좁히면 upstream SVG의 data URI image·font가 누락돼 PDF가 비거나 글꼴·이미지가 달라질 수 있다.
- CSP만으로 top-level navigation이나 모든 SVG subresource 유형이 차단된다고 가정하면 우회 경로가 남을 수 있다.
- 반대로 범용 sanitizer를 도입하면 SVG geometry, namespace, text layer나 style을 손상시켜 문서 충실도가 낮아질 수 있다.
- WKWebView subresource 요청은 일반 `URLProtocol`로 관측되지 않을 수 있어 잘못된 음성 테스트가 생길 수 있다.
- WebKit 통합 테스트는 navigation과 rendering timing에 민감해 timeout과 completion 계약을 명확히 하지 않으면 플래키해질 수 있다.
- data URI 안의 중첩 SVG나 CSS URL처럼 겉보기에는 로컬인 참조도 능동 콘텐츠를 포함할 수 있으므로 MIME과 사용 맥락을 구분해야 한다.
- security policy helper를 별도 파일로 분리할 경우 HostAppTests의 명시 source 목록과 generated Xcode project가 어긋날 수 있다.

## 승인 요청 사항

- 문서 유래 page SVG를 잠재적으로 능동 콘텐츠가 포함된 입력으로 보고, offscreen renderer에서 content JavaScript와 외부 리소스를 기본 거부하는 원칙을 승인 요청한다.
- 실제 upstream SVG에 필요한 것으로 확인된 inline style과 제한된 `data:` image/font만 예외 후보로 두고, `blob:`과 HTTP/HTTPS는 기본 거부하는 조사 방향을 승인 요청한다.
- 이 수행계획을 기준으로 Stage 1 조사와 구현계획서 작성 단계 진행 승인을 요청한다.
