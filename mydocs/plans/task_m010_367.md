# Task M010 #367 수행계획서

## 목적

LibreOffice가 설치된 macOS 환경에서도 `.hwp` 파일의 Quick Look preview와 Finder thumbnail이 알한글 확장으로 라우팅되게 한다.

완료 후에는 LibreOffice가 `.hwp`를 `org.libreoffice.hwp-document` UTI로 등록한 환경에서도 알한글이 해당 파일 타입을 지원 대상으로 인식해야 하며, 사용자는 LibreOffice를 제거하지 않아도 Finder/Quick Look에서 HWP 미리보기를 사용할 수 있어야 한다.

## 배경

사용자 제보에서 알한글 최신버전 설치 후 Quick Look preview와 Finder thumbnail extension 2개가 등록/활성화된 상태였지만, HWP 파일 Quick Look preview가 문서 내용이 아니라 generic file icon으로 표시되었다. 이후 사용자가 LibreOffice를 제거하자 같은 파일의 preview가 정상 동작한다고 보고했다.

로컬 조사에서 LibreOffice 26.2.4.2 설치본은 앱 본체 `Info.plist`에서 `.hwp` 확장자를 `org.libreoffice.hwp-document` imported UTI로 등록하는 것을 확인했다. 반면 LibreOffice의 Quick Look preview/thumbnail appex는 `org.libreoffice.hwp-document`를 `QLSupportedContentTypes`에 포함하지 않았다.

현재 알한글은 자체 UTI와 Hancom 계열 UTI를 지원하지만 LibreOffice HWP UTI는 지원 목록에 없다. 사용자 환경에서 LaunchServices가 `.hwp` 파일을 LibreOffice UTI로 분류하면 알한글 Quick Look/Thumbnail provider가 호출되지 않고 Quick Look이 file icon fallback으로 떨어질 수 있다.

## 범위(포함·제외)

포함:

- HostApp 문서 타입/UTI 선언에 `org.libreoffice.hwp-document` 지원 추가
- Quick Look preview extension의 `QLSupportedContentTypes`에 `org.libreoffice.hwp-document` 추가
- Finder thumbnail extension의 `QLSupportedContentTypes`에 `org.libreoffice.hwp-document` 추가
- LibreOffice 설치 상태에서 `mdls`, `pluginkit`, `qlmanage -t` 기준 라우팅/thumbnail smoke 검증
- 필요한 경우 Finder 통합 troubleshooting 문서에 LibreOffice 공존 진단 기준 추가
- 수행계획서, 구현계획서, 단계 보고서, 최종 보고서, 오늘할일 갱신

제외:

- LibreOffice 설치/삭제 자동화
- 사용자 계정의 전역 LaunchServices reset을 기본 해결책으로 권장하는 변경
- HWPX 공존 대응. LibreOffice 26.2.4.2 설치본에서 별도 HWPX UTI 등록은 이번 조사 범위에서 확인되지 않았다.
- Quick Look/Thumbnail renderer 품질 parity 개선
- public release packaging, signing, notarization, Homebrew Cask 변경

## 설계 방향

`org.libreoffice.hwp-document`는 알한글이 소유하는 exported UTI가 아니라 LibreOffice가 선언한 외부 호환 UTI로 취급한다. 따라서 HostApp에서는 `UTImportedTypeDeclarations`에 호환 타입을 추가하고, 기존처럼 `LSHandlerRank`는 `Alternate` 기준을 유지한다.

라우팅 표면은 세 군데를 같은 기준으로 맞춘다.

1. HostApp `CFBundleDocumentTypes`의 HWP 문서 타입 목록에 LibreOffice HWP UTI를 포함한다.
2. `Sources/QLExtension/Info.plist`의 `QLSupportedContentTypes`에 같은 UTI를 포함한다.
3. `Sources/ThumbnailExtension/Info.plist`의 `QLSupportedContentTypes`에 같은 UTI를 포함한다.

이 변경은 파일 파서나 renderer 입력을 바꾸지 않는다. 확장자가 `.hwp`이고 실제 HWP magic이 맞는 파일만 기존 입력 검증과 renderer 경로를 통과한다. 따라서 손상 파일, 비어 있는 파일, 대용량 파일 fallback 정책은 유지한다.

문서 보강은 사용자가 LibreOffice 제거를 해결책으로 오해하지 않도록, 진단 기준 중심으로 제한한다. 기본 안내는 `mdls`로 content type을 확인하고 알한글 설치본이 해당 UTI를 지원하는지 확인하는 방향으로 둔다.

## 잠정 단계(3~6단계)

1. Stage 1: UTI/등록 현황 재확인
   - 현재 알한글 HostApp, Quick Look, Thumbnail의 supported content types를 정리한다.
   - LibreOffice 설치본의 `org.libreoffice.hwp-document` 선언과 Quick Look extension 지원 목록을 재확인한다.
   - HWPX에 해당하는 LibreOffice UTI가 없는지 이번 범위 기준으로 확인한다.
2. Stage 2: LibreOffice HWP UTI 호환 선언 추가
   - HostApp `Info.plist`에 imported UTI와 문서 타입 연결을 추가한다.
   - Quick Look preview와 Finder thumbnail extension의 supported content types에 같은 UTI를 추가한다.
   - plist syntax와 Xcode project 입력 경로를 검증한다.
3. Stage 3: Finder 통합 진단 문서와 smoke 검증 보강
   - 필요한 경우 troubleshooting 문서에 LibreOffice UTI 공존 케이스와 `mdls` 확인 기준을 추가한다.
   - LibreOffice 설치 상태에서 알한글 설치본 기준 `pluginkit`, `mdls`, `qlmanage -t` 검증을 수행한다.
4. Stage 4: 통합 검증과 보고
   - 정적 검증, 빌드, Quick Look/Thumbnail smoke 결과를 정리한다.
   - 단계 보고서와 최종 보고서에 잔여 리스크와 사용자-facing 영향 범위를 기록한다.

## 검증 계획

계획 단계:

```bash
git diff --check -- mydocs/orders/20260622.md mydocs/plans/task_m010_367.md
```

구현 단계 후보:

```bash
plutil -lint Sources/HostApp/Info.plist Sources/QLExtension/Info.plist Sources/ThumbnailExtension/Info.plist
plutil -p Sources/HostApp/Info.plist | rg "org.libreoffice.hwp-document|LSItemContentTypes|UTImportedTypeDeclarations"
plutil -p Sources/QLExtension/Info.plist | rg "org.libreoffice.hwp-document|QLSupportedContentTypes"
plutil -p Sources/ThumbnailExtension/Info.plist | rg "org.libreoffice.hwp-document|QLSupportedContentTypes"
xcodebuild -project Alhangeul.xcodeproj -scheme HostApp -configuration Debug -derivedDataPath build.noindex/DerivedData CODE_SIGNING_ALLOWED=NO build
```

설치본/Finder 통합 smoke 후보:

```bash
mdls -name kMDItemContentType -name kMDItemContentTypeTree /tmp/alhangeul-KTX.hwp
pluginkit -mAvvv -i com.postmelee.alhangeul.QLExtension
pluginkit -mAvvv -i com.postmelee.alhangeul.ThumbnailExtension
mkdir -p /tmp/alhangeul-ql-libreoffice
qlmanage -t -x -s 512 -o /tmp/alhangeul-ql-libreoffice /tmp/alhangeul-KTX.hwp
```

릴리스 산출물 기준 smoke가 필요한 경우에는 기존 Finder 통합 helper를 사용한다. 전역 LaunchServices reset이나 Finder/QuickLook daemon kill은 기본 검증으로 쓰지 않는다.

## 리스크

- LaunchServices의 content type 선택은 설치 순서, 기존 캐시, 다른 HWP 지원 앱의 UTI 선언에 영향을 받을 수 있어 로컬 환경에서 사용자 환경과 같은 `mdls` 결과가 나오지 않을 수 있다.
- 현재 로컬 환경에서는 샘플 `.hwp`가 `com.haansoft.hancomofficeviewer.mac.hwp`로 분류되어, LibreOffice UTI가 실제 선택되는 상태를 그대로 재현하지 못했다.
- LibreOffice Quick Look appex는 HWP UTI를 직접 지원하지 않으므로, 사용자가 본 증상은 provider 우선순위 경쟁보다 content type mismatch일 가능성이 높다. 보고서에서 이 차이를 명확히 기록해야 한다.
- imported UTI를 추가해도 이미 캐시된 Quick Look thumbnail은 즉시 갱신되지 않을 수 있다. 검증은 fresh sample 또는 cache reset 범위를 명확히 나눠 수행해야 한다.
- 다른 앱이 별도 HWP UTI를 선언하는 경우에는 같은 유형의 공존 문제가 남을 수 있다.

## 승인 요청 사항

1. 위 범위와 4단계 진행 구조 승인
2. `org.libreoffice.hwp-document`를 imported compatibility UTI로 추가하고 HostApp/Quick Look/Thumbnail 세 표면에 동일하게 반영하는 방향 승인
3. LibreOffice 설치/삭제 자동화와 전역 LaunchServices reset 안내는 이번 작업에서 제외하는 방향 승인
4. 다음 단계: 승인 후 구현계획서(`mydocs/plans/task_m010_367_impl.md`) 작성
