## 원인과 재현

`DocumentSaveWritePolicy.writeNewFileAtomically`가 선택된 destination의 부모 폴더에 임의 sibling 임시 파일을 만든다. NSSavePanel로 선택한 파일과 다른 경로여서 sandbox 권한 오류가 발생했다. 평문·보호 HWP3 → 새 HWP5 두 경우에 재현했으며, 같은 폴더의 일반 HWPX 및 보호 HWP5/HWPX 복사본 저장은 성공했다. 기존 XCTest는 자체 temporaryDirectory 안에서 실행되어 파일 단위 panel 권한을 재현하지 않았다.

## 범위

- OS가 제공하는 destination volume의 임시 디렉터리에서 완성본을 준비하고 배타적으로 게시한다.
- 임시 파일 쓰기·게시 실패, 경쟁 생성, 기존 파일과 원본 보존을 검증한다.
- 실제 sandbox 앱과 NSSavePanel로 평문/보호 HWP3 → HWP5/HWPX 네 조합 및 일반 저장을 검증한다.
- 수행·구현계획, 단계·최종 보고, 오늘할일과 검토 가능한 PR을 준비한다.

광범위한 폴더 entitlement, sandbox 해제, core·Studio·FFI 변경, 종료 dirty 상태 수정은 포함하지 않는다. 기존 v0.1.11 tag/draft 교체, main 병합과 official 공개는 수정 commit이 준비된 후 release task #494의 실행 입력으로 확정한다.

## 설계 방향

`FileManager.url(for: .itemReplacementDirectory, in: .userDomainMask, appropriateFor: destinationURL, create: true)`를 사용해 대상 volume에 적합한 임시 디렉터리를 얻는다. 생성·쓰기 성공 후 기존 `RENAME_EXCL`로 신규 destination만 게시하며 임시 디렉터리는 성공·실패 모두 정리한다. 같은 volume 조건이나 sandbox 접근이 실패하면 원본 보존을 우선하고 실패를 전달한다. 일반 overwrite 허용 경로는 변경하지 않는다.

## 예상 파일

`Sources/HostApp/Services/DocumentSaveContract.swift`, `Tests/HostAppTests/DocumentSaveContractTests.swift`, 필요한 경우 sandbox integration harness·실행 helper와 `DocumentSavePanel.swift`, 이 타스크 문서. `project.yml`의 제품 entitlement나 generated Xcode project를 직접 수정하지 않는다.
