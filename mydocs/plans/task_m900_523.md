## 포함 범위와 화면 방향

1. 업데이트 홈 소개는 한 문단으로 줄이고 중복 최신 버전 설명을 제거한다. 다운로드 버튼의 버전 텍스트와 작은 버전 배지로 정보를 제공한다.
2. 상세 노트의 소개는 한 문단으로 유지하고, 확인된 공개일만 작은 중앙 정렬 보조 정보로 표시한다. 다운로드 버튼과 겹치는 안내 문장은 제거한다. v0.1.11의 2026년 9월 7일 공개 사실을 유지하고, v0.2.0의 공개일은 실제 공개 후 확인한다.
3. 앱 업데이트 안내는 “메뉴 막대에서 알한글 → 업데이트 확인…을 선택하세요.” 수준으로 정리한다.
4. Homebrew 최초 설치와 기존 Homebrew 설치본 업데이트를 구분한다. 각각 코드 블록과 복사 버튼을 제공한다. 설치 명령은 `brew install --cask postmelee/tap/alhangeul`, 업데이트 명령은 아래 두 줄이다.

   ```sh
   brew update
   brew upgrade --cask postmelee/tap/alhangeul
   ```

5. 앱 업데이트와 Homebrew 제목 옆 배지는 읽을 수 있는 버전 텍스트를 제공하며 실제 각 경로의 제공 버전을 독립적으로 확인한다. 후보를 최신 공개로 표시하지 않는다. 이전 상세 노트의 당시 설치 안내가 현재 Homebrew 제공 버전과 혼동되지 않게 한다.
6. 전역 헤더 아래 띠는 이전 버전 안내용으로 유지한다. 공통 CSS·최소 JavaScript와 Pages 작성 매뉴얼에 재사용 규칙을 반영한다.

주요 예상 수정 파일은 `docs/updates/index.html`, `docs/updates/v0.1.11.html`, `docs/updates/v0.2.0.html`, `docs/styles.css`, 업데이트 페이지용 JavaScript, `mydocs/manual/release_github_pages_sparkle_guide.md`다. 공유 CSS 영향은 사이트 홈과 다른 상세 노트까지 점검한다. 과거 릴리스 사실과 날짜는 바꾸지 않는다.

HostApp, Spotlight, Quick Look, Thumbnail, 앱 버전·빌드, core pin, Cask·tap 게시, Release 자산·tag, appcast 생성, 앱 재빌드·재공증은 제외한다.

- 다운로드 URL의 실제 Release·asset, 내부 링크, CSS·JavaScript 경로와 콘솔 오류를 확인한다. 미공개 v0.2.0 자산은 현재 성공한 공개 링크로 기록하지 않는다.
- `scripts/ci/update-release-version-notices.sh --updates-dir docs/updates --check`를 실행한다.
- 당시 public appcast를 새로 내려받아 `test -s`, `xmllint --noout` 검증 후 `scripts/ci/prepare-pages-artifact.sh`로 `build.noindex/task523/` 하위 별도 디렉터리에 조립한다. 입력 appcast와 결과 appcast의 `cmp` 및 SHA-256 일치를 확인한다.
- `git diff --check`, 변경 범위 확인, Pages 관련 기존 검사와 PR CI를 수행한다. 앱 소스 변경이 없으므로 앱 빌드·설치 검증은 실행하지 않는다.
