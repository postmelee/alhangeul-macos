## 목적

앱 실행 시점에 Sparkle 백그라운드 업데이트 확인을 1회 수행해, 사용자가 메뉴의 `업데이트 확인...`을 직접 누르지 않아도 새 public release 안내를 더 빠르게 받을 수 있게 한다. 최신 상태일 때는 사용자-facing 알림 없이 조용히 끝나는 경로를 유지하고, 새 버전이 있을 때만 Sparkle 표준 업데이트 안내 UI를 사용한다.

## 배경

현재 HostApp은 Sparkle 기반 업데이트 확인을 사용하고 `SUEnableAutomaticChecks`를 켜 둔다. 다만 Sparkle의 기본 예약 확인은 마지막 확인 시각과 기본 주기 기준으로 동작하므로, 앱을 실행할 때마다 즉시 appcast를 확인하지는 않는다.

초기 public release 라인에서는 Quick Look/Thumbnail, 설치, 업데이트 관련 수정이 patch release로 자주 배포될 수 있다. 이 경우 사용자가 수동 확인 메뉴를 찾기 전에도 새 버전을 안내하는 편이 유지보수와 사용자 보호 측면에서 유리하다. 단, 자동 설치나 별도 업데이트 체계는 도입하지 않고 Sparkle의 기존 표준 updater 경로 안에서 처리한다.

## 범위(포함·제외)

포함 범위:

- `UpdateController`의 Sparkle 초기화 흐름 점검
- Sparkle updater 시작 직후 백그라운드 업데이트 확인 1회 실행
- 사용자가 자동 업데이트 확인을 꺼 둔 경우 강제 확인하지 않는 guard 반영
- 기존 앱 메뉴 `업데이트 확인...` 수동 확인 경로 유지
- 필요 시 Sparkle 동작 기준과 검증 항목을 작업 문서에 기록

제외 범위:

- Sparkle 외 별도 GitHub Releases API polling 구현
- 자동 다운로드 또는 자동 설치 기본값 변경
- appcast 생성, Pages 배포, public release 실행
- Sparkle 업데이트 안내 UI 커스텀 디자인
- Quick Look/Thumbnail 렌더링 또는 등록 동작 변경

## 설계 방향

Sparkle은 계속 단일 업데이트 경로로 유지한다. 앱 시작 시 수동 확인 UI용 `checkForUpdates(nil)`을 호출하지 않고, 최신 상태일 때 조용히 끝나는 `checkForUpdatesInBackground()` 경로를 우선 사용한다.

호출 위치는 `SPUStandardUpdaterController(startingUpdater: true, ...)` 생성 이후로 잡는다. 이때 `updater.automaticallyChecksForUpdates`가 켜져 있는 경우에만 백그라운드 확인을 요청해, 사용자가 Sparkle 자동 확인을 꺼 둔 상태를 존중한다.

수동 메뉴는 기존처럼 `checkForUpdates(nil)`을 유지한다. 사용자가 명시적으로 메뉴를 누른 경우에는 최신 상태 안내를 포함한 Sparkle 표준 수동 확인 UI가 표시될 수 있어야 한다.

## 잠정 단계(3~6단계)

1. 현재 Sparkle 초기화와 수동 확인 경로 재확인
   - `UpdateController`, `Info.plist`, 관련 release/Sparkle 문서를 대조한다.
   - 자동 확인 설정과 수동 확인 UI의 책임을 구분한다.
2. 실행 시 백그라운드 확인 호출 구현
   - updater 시작 직후 `automaticallyChecksForUpdates` guard를 둔다.
   - guard 통과 시 `checkForUpdatesInBackground()`를 1회 호출한다.
   - 기존 `checkForUpdates()` 수동 메뉴 동작은 유지한다.
3. 문서와 검증 기준 정리
   - 필요한 경우 Sparkle 가이드 또는 작업 문서에 실행 시 확인 정책을 기록한다.
   - 최신 상태 무알림, 새 버전 안내, 자동 확인 비활성화 guard를 검증 항목으로 남긴다.
4. 통합 검증과 보고
   - 정적 검증과 HostApp build를 수행한다.
   - 가능한 범위에서 Sparkle 자동 확인 smoke 방법과 잔여 수동 확인 항목을 보고한다.

## 검증 계획

- `git status --short --branch`
- `git diff --check`
- `plutil -lint Sources/HostApp/Info.plist`
- `xcodegen generate` 필요 여부 확인
- `xcodebuild -project Alhangeul.xcodeproj -scheme HostApp -configuration Debug -derivedDataPath build.noindex/DerivedData CODE_SIGNING_ALLOWED=NO build`
- 가능하면 Debug 또는 설치본에서 다음 항목 수동 확인
  - 앱 실행 시 백그라운드 업데이트 확인 요청 경로가 실행됨
  - 최신 상태에서 불필요한 "최신 버전입니다" 모달이 뜨지 않음
  - `알한글 > 업데이트 확인...` 수동 확인 메뉴는 기존처럼 동작함
  - 자동 확인을 끈 상태에서는 실행 시 강제 백그라운드 확인을 요청하지 않음

## 리스크

- Sparkle 자동 확인 상태와 마지막 확인 시각은 사용자 defaults와 Sparkle 내부 상태에 영향을 받으므로, 자동 smoke가 환경별로 달라질 수 있다.
- appcast 네트워크 확인을 매 실행 시 요청하면 기본 1일 주기보다 더 적극적인 정책이 되므로, 최신 상태에서 사용자-facing UI가 뜨지 않는지 확인해야 한다.
- Sparkle UI 검증은 실제 signed/notarized 설치본, public appcast, 사용자 세션 foreground 상태에 영향을 받을 수 있어 CI만으로 완전히 검증하기 어렵다.
- `UpdateController`가 SwiftUI app lifetime에 묶여 있으므로, 초기화 시점과 중복 생성 여부를 확인해야 한다.
