# Task M014 #292 수행계획서

## 목적

Dock과 Finder에서 알한글 앱 아이콘이 다른 macOS 앱보다 과하게 크게 보일 수 있는 문제를 줄이기 위해, 기존 아이콘 디자인은 유지하면서 macOS 앱 아이콘 관행에 맞는 바깥 여백을 보강한다.

완료 후에는 `AppIcon` PNG 10개가 기존 asset catalog 슬롯과 같은 해상도를 유지하고, 빌드된 `AppIcon.icns`와 실제 Dock/Finder/About 표시에서 주변 macOS 앱과 유사한 시각적 크기로 보이는지 확인할 수 있어야 한다.

## 배경

Issue #292는 Dock 스크린샷과 함께 알한글 앱 아이콘이 다른 아이콘보다 유독 크게 보인다는 제보로 등록되었다. 초기 분석 결과 `project.yml`의 `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` 설정과 `Sources/HostApp/Assets.xcassets/AppIcon.appiconset/Contents.json` 슬롯 구성, PNG 해상도는 형식상 정상이다.

문제 가능성이 큰 지점은 아이콘 자산의 시각적 점유율이다. 현재 알한글 아이콘은 흰색 rounded-square 배경이 캔버스 거의 전체를 채운다. 로컬 측정에서 `icon_512x512@2x.png`와 `icon_128x128@2x.png`의 강한 불투명 영역 bbox는 `100% x 100%`로 확인되었다. 같은 Mac에서 Safari, Mail, Notes, Photos, App Store, Terminal 같은 기본 앱의 `.icns`를 추출해 비교하면 아이콘 본체는 대체로 캔버스의 약 `80.5% x 80.5%` 안쪽에 들어온다.

따라서 이 문제는 해상도 오류나 Xcode 설정 오류라기보다, macOS Dock/Finder가 사용하는 아이콘 캐시·확대·화면 배율·OS 버전 차이에 따라 현재 자산의 여백 부족이 더 크게 드러나는 유형으로 판단한다.

## 범위

포함:

- `Sources/HostApp/Assets.xcassets/AppIcon.appiconset`의 AppIcon PNG 10개를 같은 파일명과 같은 pixel size로 재생성
- 현재 디자인의 색상, 글리프, 흰색 rounded-square 방향성 유지
- 흰색 배경판과 전체 아이콘 본체가 macOS 기본 앱의 시각적 점유율에 가까워지도록 바깥 투명 여백 보강
- 기존 `Contents.json`, `project.yml`, bundle identifier, app display name 변경 없음 확인
- 빌드 산출물의 `AppIcon.icns` 추출과 슬롯/시각 점유율 확인
- Dock, Finder, About 화면에서 기존 아이콘 캐시 영향을 고려한 로컬 표시 검증
- 검증 과정에서 캐시 초기화가 필요한지 판단하고, 필요한 경우 영향 범위를 보고한 뒤 제한적으로 수행

제외:

- 앱 이름, bundle identifier, `Info.plist` 표시명 변경
- Quick Look preview, Finder thumbnail extension, 문서 렌더러, RustBridge 변경
- README/docs 로고 자산(`assets/logo-256@2x.png`, `docs/assets/logo-256@2x.png`) 변경
- upstream `edwardkim/rhwp` 아이콘 provenance 변경 또는 새 third-party asset 도입
- 릴리스 서명, 공증, DMG, Homebrew Cask 작업
- Dock/IconServices 전역 캐시 초기화를 일반 사용자 절차로 문서화하는 작업

## 설계 방향

기존 AppIcon 파일명과 `Contents.json` 구조는 유지하고 PNG 내용만 교체한다. 새 아이콘은 1024px 기준 master 후보를 먼저 만들고, 같은 비율과 중심 정렬을 유지한 채 `512`, `256`, `128`, `64`, `32`, `16` 슬롯으로 내려보내는 방식을 기본으로 한다.

1차 후보는 아이콘 전체를 캔버스의 약 `86%` 안쪽에 배치하는 방향으로 잡는다. Apple 기본 앱의 측정값은 약 `80.5%` 수준이지만, 알한글 글리프 자체가 흰 배경 안에 다시 여백을 갖고 있으므로 80%까지 바로 줄이면 실제 글리프가 작아질 수 있다. Stage 1에서 `84%`, `86%`, `88%` 후보 중 하나를 고정하고, Stage 2에서 최종 PNG 10개를 생성한다.

검증은 캐시와 무관한 파일 검증을 먼저 수행한다. 그 다음 빌드된 앱 bundle의 `AppIcon.icns`를 추출해 실제 포함 슬롯과 시각 점유율을 확인한다. 마지막으로 Dock/Finder 표시 검증을 수행하되, 전역 IconServices 캐시 삭제는 다른 앱 아이콘 표시에도 영향을 줄 수 있으므로 마지막 수단으로만 다룬다.

## 잠정 단계

1. Stage 1: 현행 아이콘과 macOS 기준 점유율 재확인
   - 현재 AppIcon PNG 10개의 해상도, alpha bbox, strong alpha bbox, 시각 점유율을 기록한다.
   - Apple 기본 앱과 대표 서드파티 앱 `.icns` 추출 비교값을 다시 확인한다.
   - 후보 축소율을 `84%`, `86%`, `88%` 중 하나로 고정한다.
2. Stage 2: AppIcon PNG 10개 재생성
   - 기존 파일명과 해상도를 유지한 채 PNG 내용만 교체한다.
   - 작은 슬롯에서 글리프 식별성이 떨어지지 않는지 확인한다.
   - `Contents.json`과 `project.yml`은 변경하지 않는다.
3. Stage 3: 빌드 산출물과 정적 검증
   - HostApp Debug build를 수행하고 앱 bundle의 `AppIcon.icns`를 추출한다.
   - 추출된 `.icns` 슬롯과 새 PNG 점유율을 확인한다.
   - `plutil`, `sips`, `git diff --check`로 파일 정합성을 검증한다.
4. Stage 4: Dock/Finder/About 표시 검증과 캐시 영향 확인
   - 가능한 경우 기존 설치본을 건드리기 전 build 산출물 또는 임시 설치 경로로 표시를 확인한다.
   - `/Applications/Alhangeul.app` 교체 검증이 필요하면 Dock tile 제거/재추가, `touch`, `killall Dock` 순서로 낮은 영향의 캐시 갱신부터 시도한다.
   - 전역 IconServices 캐시 삭제는 필요한 경우에만 별도 보고 후 수행한다.
5. Stage 5: 최종 보고서와 PR 준비
   - 전후 점유율, 빌드 산출물, Dock/Finder/About 확인 결과를 최종 보고서에 정리한다.
   - 아이콘 캐시로 인해 사용자 환경에서 확인이 지연될 수 있는 점과 제보자에게 요청할 재확인 조건을 남긴다.

## 검증 계획

계획 문서 단계:

```bash
git diff --check -- mydocs/orders/20260529.md mydocs/plans/task_m014_292.md
rg -n "#292|AppIcon|앱 아이콘|Dock|Finder|M014|v0.1.4" \
  mydocs/orders/20260529.md mydocs/plans/task_m014_292.md
```

구현 단계 후보:

```bash
sips -g pixelWidth -g pixelHeight -g hasAlpha Sources/HostApp/Assets.xcassets/AppIcon.appiconset/*.png
plutil -lint Sources/HostApp/Assets.xcassets/AppIcon.appiconset/Contents.json
git diff --check
xcodebuild -project Alhangeul.xcodeproj -scheme HostApp -configuration Debug \
  -derivedDataPath build.noindex/DerivedDataTask292 CODE_SIGNING_ALLOWED=NO build
iconutil -c iconset -o build.noindex/task292/AppIcon.iconset \
  build.noindex/DerivedDataTask292/Build/Products/Debug/Alhangeul.app/Contents/Resources/AppIcon.icns
```

표시 검증 후보:

```bash
defaults read com.apple.dock tilesize
defaults read com.apple.dock magnification
defaults read com.apple.dock largesize
touch /Applications/Alhangeul.app
killall Dock
```

전역 IconServices 캐시 삭제는 다른 앱 아이콘 표시에도 영향을 줄 수 있으므로, 위 낮은 영향 검증으로 충분하지 않을 때만 별도 승인 범위에서 수행한다.

## 리스크

- macOS Dock과 Finder는 앱 아이콘 캐시를 강하게 사용하므로 소스와 산출물이 바뀌어도 즉시 화면에 반영되지 않을 수 있다.
- Dock 확대 설정, 커서 hover 위치, Retina/외장 모니터 scale, macOS 버전에 따라 체감 크기가 달라질 수 있다.
- 아이콘을 과하게 줄이면 제보 환경의 문제는 줄어도 일반 환경에서 알한글 글리프가 작고 약해 보일 수 있다.
- 현재 설치본 `AppIcon.icns`는 환경에 따라 일부 큰 슬롯이 추출되지 않을 수 있으므로, asset catalog 입력 PNG와 빌드 산출물 `.icns`를 모두 확인해야 한다.
- 작은 슬롯을 단순 축소하면 16px/32px에서 경계가 뭉개질 수 있다.
- 전역 캐시 초기화는 작업자 로컬 세션의 다른 앱 아이콘 표시에도 영향을 줄 수 있으므로 표준 검증의 첫 단계로 두지 않는다.

## 승인 요청 사항

1. #292를 AppIcon PNG 10개의 macOS 관행 여백 보강 작업으로 진행하는 범위 승인
2. 기존 아이콘 디자인과 파일명/asset catalog 구조는 유지하고 PNG 내용만 교체하는 방향 승인
3. Stage 1에서 `84%`, `86%`, `88%` 후보를 비교한 뒤 최종 축소율을 고정하는 방향 승인
4. Dock/IconServices 전역 캐시 초기화는 마지막 수단으로만 두고, 낮은 영향의 표시 검증부터 수행하는 방향 승인
5. 다음 단계: 승인 후 구현계획서(`mydocs/plans/task_m014_292_impl.md`) 작성과 Stage 1 inventory 진행

승인 전에는 AppIcon PNG, Swift source, `project.yml`, `Contents.json` 변경을 진행하지 않는다.
