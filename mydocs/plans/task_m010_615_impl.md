# M010 · #615 최초 페이지 렌더 복구 구현계획

기준은 devel의 rhwp v0.9.0 고정 커밋 c9095c5f67632e6721e800ccc7fb43ea49d26682다. [수행계획서](task_m010_615.md)와 [업스트림 #9164](https://github.com/edwardkim/rhwp/issues/9164)를 함께 추적한다.

## 1단계 — 실제 HostApp 문서 열기에서 실패 대조군 확보

기존 Studio 생명주기 smoke의 Coordinator, 문서 공급 경로와 WKWebView를 사용한다. 서로 다른 첫 페이지 표식이 있는 합성 문서 A와 B를 준비한다. 시험용 주입 코드로 A의 최초 CanvasView.loadDocument가 prepareCanvasMetrics를 기다리는 순간에 글꼴 완료 이벤트를 한 번 발생시킨다. 단순 시간 지연이나 완료 후 이벤트 발생은 재현 성공으로 집계하지 않는다.

이벤트 주입 여부, 현재 문서 식별값, 상태 표시줄, 첫 페이지 캔버스와 화면 표식을 대조한다. 같은 A가 일반 열기에서는 보이고 경합에서만 사라지는지 확인한다. 실행 로그와 화면은 연결된 T7의 전용 output에 보관하고 실행 전 경로의 실제 장치를 확인한다. 실패 대조군이 성립하지 않으면 호출 순서와 렌더 세대를 점검한 뒤 수정 위치를 결정한다.

## 2단계 — 현재 문서에 첫 렌더 완료 책임 연결

고정 소스의 CanvasView.loadDocument, prepareRendererRevision, refreshPagesForRevision과 상위 initializeDocument의 반환 경로를 추적한다. 같은 문서의 글꼴 갱신과 다른 문서로의 교체를 구분한다. 같은 문서라면 초기 페이지 목록과 가시 영역을 최신 렌더 선택 결과로 구성하고, 다른 문서로 교체된 경우 오래된 호출이 페이지나 완료 메시지를 게시하지 않게 한다. 연속 통지는 합쳐 처리하고 로딩 성공은 첫 페이지가 표시 가능한 상태에서만 확정한다.

Studio 빌드 변환의 입력 파일·변환 횟수를 검사하고 적용 결과를 기존 빌드 증명과 연결한다. upstream 고정 커밋에서 번들을 재생성해 자산·manifest 일치 검사를 통과시킨다. 상류 수정안이 준비된 경우 동일 동작을 확인한 뒤 필요한 변경만 선반영한다.

## 3단계 — 회귀 검증과 PR 리뷰

1단계와 같은 WKWebView 주입 조건에서 A를 한 번만 열어 첫 화면 표식을 확인한다. 글꼴 이벤트 없는 열기, 반복 통지, A의 초기화 중 B 열기를 검증한다. 마지막 경우에는 A의 지연 콜백 종료 후에도 B의 표식과 쪽수가 유지돼야 한다. 종료되지 않는 재시도와 중복 문서 열기도 확인한다.

단계 결과와 번들 검증을 기록하고 오늘할일을 갱신한다. publish/task615에서 devel 대상으로 PR을 게시한다. 소스 변환과 생성 자산의 대응, 사용자 문서 노출 여부, 회귀 결과와 CI를 리뷰한다. 차단 사항 해소 후 병합하고 PR 및 이슈 상태를 확인한다. 업스트림 수정 릴리즈 반영 시 같은 회귀 검사로 임시 변환 제거를 검증한다.
