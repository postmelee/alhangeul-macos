## 2. 배경

- 현재 홈의 글꼴 안내 링크는 FAQ와 푸터에 있다. 공통 헤더와 상단 v0.2.3 기능 소개에는 직접 진입 링크가 없어 새 기능을 읽고 설정 방법으로 이동하기 어렵다.
- `docs/`에는 홈·글꼴·최신 소식·문의·업데이트 목록과 릴리즈 노트를 포함한 HTML 21개가 있다. 헤더 마크업은 페이지마다 반복되며 메뉴 구성도 일부 다르다.
- 현재 모바일 CSS는 Windows/Linux 링크를 820px 이하에서, 일부 헤더의 GitHub 링크를 700px 이하에서 숨긴다. 메뉴 하나만 추가하면 작은 화면에서 가로 넘침·조밀한 클릭 영역이 생길 수 있다.
- 점검 당시 최신 소식 헤더의 다운로드는 v0.2.2, 문의 페이지는 v0.1.7을 가리킨다. 작업지시자는 두 현재 페이지의 다운로드를 v0.2.3으로 정렬하는 범위도 승인했다. 과거 릴리즈별 본문과 그 버전 다운로드는 별개로 보존한다.
- #569의 글꼴 사용 안내와 #584의 v0.2.3 배포는 완료 상태다. 이번 변경은 안내 접근성 개선으로 독립 추적하며 완료된 이슈를 다시 열지 않는다.

## 3. 범위

### 포함

- 홈·글꼴 안내·최신 소식·문의·업데이트 목록/릴리즈 노트의 헤더에 **글꼴 안내** 링크를 추가한다. 각 문서 위치에 맞는 상대 경로로 `/fonts/`에 도착하게 한다.
- 글꼴 안내 페이지의 헤더를 홈과 같은 메뉴·다운로드 버튼으로 통일하고 별도 홈 메뉴와 본문 상단의 파란 ‘Mac 글꼴 사용 안내’ 문구를 제거한다. 나머지 본문은 보존하며 현재 위치를 접근성 속성과 시각 표시로 구분한다. 같은 페이지의 다른 링크와 중복된 현재 표시가 생기지 않게 한다.
- 홈 상단 v0.2.3 배너에 **Mac 글꼴 설정 방법 →** 링크를 추가하고 FAQ·푸터의 기존 안내는 유지한다.
- 모바일은 로고·다운로드와 주요 안내 메뉴를 두 줄로 배치하는 안을 우선 검토한다. 글꼴 안내를 숨기지 않고, GitHub·Windows/Linux 보조 링크에도 대체 접근 경로를 유지한다.
- 최신 소식·문의 페이지의 현재 다운로드 URL과 접근성 문구를 공개 v0.2.3으로 정렬한다.
- 320·360·390·768·1024·1440px 폭에서 대표 페이지의 헤더·배너를 실제로 확인한다. 데스크톱/모바일 스크린샷과 직접 조작할 로컬 미리보기를 제공한다.
- 단계 보고·검증 근거·최종 보고·오늘할일과 devel 대상 PR 초안을 준비한다.

### 제외

- 글꼴 안내의 지원 범위나 앱 동작, Mac/Windows 글꼴 기능, Rust/core/Studio 변경.
- 과거 릴리즈 본문·그 버전 다운로드·공개일·릴리즈 상태 변경.
- 새로운 메뉴 라이브러리·드롭다운, 사이트 빌드 체계 또는 헤더 템플릿 구조 개편.
- 앱 빌드·설치·서명·공증, 태그·DMG·Cask·Sparkle appcast 변경.
- 이번 준비 승인만으로 공개 push/PR·병합·Pages 배포 실행.

## 4. 설계 방향

1. **기존 패턴 유지:** 기존 HTML 링크와 공통 CSS를 사용한다. 다운로드는 주된 강조 버튼으로 유지하고 글꼴 안내는 다른 탐색 메뉴와 같은 일반 링크로 둔다.
2. **직접 연결:** 메뉴는 ‘글꼴 안내’, 배너는 ‘Mac 글꼴 설정 방법 →’으로 표시한다. 새 탭 없이 같은 사이트 안내로 이동한다.
3. **모바일 우선:** 320px에서도 글꼴 안내와 다운로드가 잘리지 않게 하고, 필요한 경우 헤더 높이와 본문/고정 영역의 오프셋을 함께 조정한다. 메뉴를 맞추기 위해 글자를 지나치게 줄이거나 가로 스크롤을 기본 동선으로 만들지 않는다.
4. **접근성과 일관성:** 키보드 초점 표시·탐색 순서·현재 위치·모바일 터치 영역을 점검한다. 보조 링크를 헤더에서 숨기는 경우 푸터 등에서 접근할 수 있게 한다.
5. **과거 문서 보존:** 릴리즈 노트에서는 헤더의 새 진입점과 필요한 공통 CSS 참조만 조정한다. 본문 및 버전별 다운로드는 변경 전후 대조로 보존을 확인한다.
6. **배포 경계:** 로컬 미리보기에서 먼저 화면을 제시한다. devel 반영만으로 공개 완료라고 표시하지 않으며, main의 `docs/**` 반영이 Pages 자동 배포를 유발한다는 점은 이후 게시·병합 승인에서 설명한다.

## 7. 검증 계획과 완료 기준

- **전체 문서 연결:** HTML 21개의 헤더에서 글꼴 안내 경로와 상대 경로 해석을 검사한다. 글꼴 안내의 현재 위치 표시와 홈 배너 링크가 올바른지 확인한다.
- **반응형 화면:** 홈을 320·360·390·768·1024·1440px로 확인한다. 글꼴·업데이트 목록·최신 소식·문의·최신/과거 릴리즈 노트는 헤더 변형을 대표하는 화면으로 선정한다. 모든 문서에 같은 스크린샷을 반복 저장하지 않는다.
- **실제 동작:** 헤더와 배너를 눌러 안내에 도착하는지 확인하고, 키보드 Tab 이동·초점 표시·현재 위치를 점검한다. 가로 넘침과 헤더/배너/본문 겹침이 없어야 한다.
- **다운로드:** 현재 페이지 두 곳의 URL과 접근성 이름이 v0.2.3에 맞는지 확인한다. 앱을 설치하거나 DMG를 다시 내려받지 않는다.
- **보존:** 기존 FAQ·푸터 경로, 과거 릴리즈 본문·해당 버전 다운로드, appcast bytes가 유지돼야 한다. 변경은 승인한 HTML/CSS와 작업 문서로 제한한다.
- **필요 회귀:** 영향받는 기존 news/Pages 계약 검사를 재사용하고 HTML/문서 링크·공백을 검사한다. 단순 링크 변경을 복제하는 새 단위 테스트나 앱 전체 빌드를 추가하지 않는다.
- **사용자 확인:** 완료된 화면을 스크린샷으로 보여주고 직접 조작할 미리보기 주소를 제공한다. 로컬 확인과 공개 배포 완료는 구분한다.

완료는 위 진입점·모바일 사용성·다운로드 정렬·보존 기준을 충족하고 단계별 근거와 최종 보고를 준비한 상태다. 실행하지 않은 브라우저·기기를 실제 시험한 것으로 표시하지 않는다.

## 8. 리스크와 저장 공간 관리

- 페이지마다 다른 헤더 때문에 메뉴가 누락되거나 상대 경로가 어긋날 수 있다. 전체 문서의 구조 검사와 대표 화면을 함께 사용한다.
- 헤더 높이가 바뀌면 기존 화면 높이·고정 영역과 충돌할 수 있다. 경계 폭·본문 시작·앵커 이동을 함께 점검한다.
- 모바일에서 보조 링크를 숨기면 접근 경로가 사라질 수 있다. 대체 위치와 키보드 접근까지 확인한다.
- 이전 릴리즈 본문/다운로드를 최신 버전으로 바꾸는 실수를 막기 위해 헤더 수정과 본문 보존 범위를 구분한다.
- 기존 CSS 캐시로 화면이 섞이지 않도록 필요한 참조 버전 변경을 구현계획에서 확정한다.
- 직전 정리에서 확보한 저장 공간을 유지한다. 소형 정적 서버로 기존 `docs/`를 직접 제공하며 전체 사이트/동영상 복사본·앱·Rust 빌드·DMG를 새로 만들지 않는다. 임시 결과는 `build.noindex/task590/`에 모으고 다음 단계에 불필요한 부산물은 정리한다.
- 작업지시자의 기존 자료·설치 앱·사용자 TXT·다른 이슈의 산출물은 변경하지 않는다.
