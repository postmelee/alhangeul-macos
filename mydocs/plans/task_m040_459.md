# Task M040 #459 수행계획서

## 목적

[Issue #459](https://github.com/postmelee/alhangeul-macos/issues/459)의 일반 인쇄 재진입과 PDF renderer navigation 세대 문제를 해결한다. 진행 중인 인쇄 controller를 두 번째 요청이 교체하지 못하게 하고, `RhwpStudioPagePDFRenderer`는 현재 render/navigation 세대에 속한 callback만 페이지 상태와 completion을 변경하게 한다. 실패·취소·정상 완료 뒤에는 다음 요청이 정상 진입하는 lifecycle을 자동 테스트와 architecture 계약으로 고정한다.

## 배경

- 기준 브랜치: `devel`
- 기준 커밋: `cb3ee87cd7d14bcd0da26fbedecd8939a9fc73f8`
- 작업 브랜치: `local/task459`
- GitHub milestone: `v0.4`
- 문서 milestone code: `M040`

Issue #455와 PR #458은 현재 editor의 page SVG를 `RhwpStudioPagePDFRenderer`가 offscreen `WKWebView.createPDF`로 변환하고, PDF 저장과 일반 인쇄가 같은 renderer를 사용하도록 통합했다. PDF export 자체의 request identity와 상태 고착은 PR #458 review 보완에서 해결됐지만 다음 두 lifecycle 위험은 후속으로 남았다.

1. `RhwpStudioWebView.Coordinator.printDocument(_:)`는 요청마다 새 `RhwpStudioPrintController`를 만들고 `printController`를 교체한다. 먼저 시작한 controller의 completion은 현재 슬롯의 identity를 확인하지 않고 `nil`로 만들 수 있다.
2. `RhwpStudioPagePDFRenderer`는 `didFinish`·`didFail` navigation, preparation JavaScript, `createPDF`와 timeout callback이 현재 render/page 세대에 속하는지 확인하지 않는다. 같은 renderer를 실패 뒤 재사용하면 이전 세대의 늦은 callback이 새 작업을 진행·종료할 수 있다.

Host bridge의 PDF 메뉴 override는 `aria-label`을 직접 복원하지만 observer의 `attributeFilter`에는 `aria-label`이 없다. Upstream이나 다른 script가 해당 속성만 바꾸면 native label을 자동 복원하지 못한다.

## 설계 방향

### 인쇄 controller 소유권

- Coordinator는 `printController != nil`이면 payload 수집이나 controller 교체를 진행하지 않고 사용자가 이해할 수 있는 기존 error presentation 경로로 중복 요청을 거부한다.
- 새 controller를 슬롯에 저장한 뒤 completion에서는 `self.printController === controller`인 경우에만 슬롯을 해제한다. 이전 controller completion이 이후 controller를 해제하지 못하게 identity를 계약으로 둔다.
- 실제 `NSPrintOperation` UI를 단위 테스트에서 띄우지 않고도 중복 거부, 정확한 identity 해제와 완료 후 재진입을 검증할 최소 lifecycle state 또는 controller factory seam을 둔다.
- `RhwpStudioPrintController.finish`의 exactly-once completion, 보유 `PDFDocument`·operation 정리는 유지하며 순환 참조를 만들지 않는다.

### Renderer generation과 navigation identity

- 각 `render` 시작에 이전 값과 겹치지 않는 generation을 발급하고, page load가 반환한 navigation과 page index를 해당 generation에 연결한다.
- Navigation 성공·실패, page preparation, `createPDF`, timeout callback은 캡처한 generation/page 또는 현재 active navigation과 일치할 때만 동작한다. Stale callback은 현재 document, page index, watchdog과 completion을 바꾸지 않고 무시한다.
- `finish`는 현재 generation을 먼저 무효화한 뒤 watchdog 취소, load 중단, pending navigation과 payload/document/page 상태 정리를 수행해 `stopLoading()`이 유발할 수 있는 늦은 delegate callback도 무해하게 만든다.
- Renderer 재사용 시 navigation delegate와 초기 main-frame 허용 상태를 새 generation에 맞게 다시 설정한다. 기존 CSP·font readiness·navigation allowlist는 넓히지 않는다.
- WebKit 객체를 직접 만들기 어려운 callback identity 검증은 production lifecycle과 같은 전이를 사용하는 작은 상태 seam으로 분리하되, test-only 분기나 공개 API 확장은 최소화한다.

### Host bridge observer

- Native PDF menu item observer의 `attributeFilter`에 `aria-label`을 추가한다.
- Override가 이미 canonical value이면 attribute를 다시 쓰지 않는 기존 조건을 유지해 mutation loop를 만들지 않는다.
- Host bridge source test는 `title`뿐 아니라 `aria-label` 변경도 observer가 감시하고 canonical label을 복원하는 계약을 확인한다.

## 검증 계획

### 자동 테스트

- 중복 인쇄 요청: 기존 controller 유지, 새 controller 생성 0회, 사용자 오류 1회
- Completion identity: 이전 controller completion이 현재 controller 슬롯을 해제하지 않음
- 인쇄 재진입: 실패·취소·정상 완료 뒤 다음 요청 수락
- Renderer 재진입: 진행 중 중복 render는 기존 `renderingInProgress` 유지
- Stale navigation: 이전 generation의 finish/failure callback이 현재 page와 completion에 영향 0회
- Stale async work: 이전 preparation·`createPDF`·timeout callback이 현재 generation을 종료하지 않음
- Exactly once: failure, timeout, process termination과 늦은 callback 조합에서도 generation별 completion 1회
- Host bridge: `aria-label`이 observer filter에 포함되고 canonical `PDF로 저장` 복원
- 기존 PDF 보안·font·text 선택성·page geometry·payload·orientation test 전부 유지

## 리스크

- `WKNavigation`과 delegate callback은 WebKit이 소유해 arbitrary stale 객체를 단위 테스트에서 직접 생성하기 어렵다. Generation 판단을 과도한 production hook 없이 검증할 seam 설계가 필요하다.
- `webView.stopLoading()` 자체가 failure callback을 만들 수 있으므로 generation 무효화와 delegate cleanup 순서를 잘못 잡으면 현재 completion 중복 또는 다음 render 무응답이 생길 수 있다.
- Preparation JavaScript와 `createPDF` closure는 navigation delegate 이후에도 늦게 도착할 수 있다. Navigation identity만 검사하고 generation/page를 캡처하지 않으면 문제가 남는다.
- `NSPrintOperation.run()`과 print panel은 modal AppKit 동작이므로 직접 UI 자동화는 불안정할 수 있다. Controller factory·state seam으로 ownership을 검증하고 실제 panel smoke는 최소화한다.
- 중복 요청 오류를 modal alert로 처리하면 현재 print panel과 충돌할 수 있다. 기존 `onError` presentation semantics를 확인해 비차단·명시적 거부를 함께 만족해야 한다.
- `aria-label`을 observer filter에 추가하면 override 자체가 mutation을 다시 유발한다. Exact-value guard와 frame 단위 coalescing을 유지해 무한 refresh를 방지한다.

## 승인 요청 사항

1. `devel` 기준 `M040` Task로 진행하는 방향
2. 인쇄 중복 요청은 기존 작업을 유지하고 두 번째 요청을 명시적으로 거부하는 방향
3. Controller identity와 renderer generation/page/navigation token을 별도 build identifier나 upstream 변경 없이 HostApp 내부에서 관리하는 방향
4. Stale navigation뿐 아니라 preparation·`createPDF`·timeout callback까지 같은 generation 계약으로 묶는 방향
5. PDF menu observer `aria-label` 보완을 Stage 1의 작은 회귀로 함께 처리하는 방향
6. 위 4개 Stage와 자동 test seam 우선, 실제 print panel smoke 최소화 원칙 승인 후 구현계획서 작성 진행 승인
