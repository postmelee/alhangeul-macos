# Task M014 #305 수행계획서

## 목적

`samples/복학원서.hwp`를 Quick Look preview와 Finder thumbnail로 볼 때 CoreGraphics 경로에서 PUA 문자가 깨져 보이는 문제를 v0.1.4 배포 재개 전에 최소 범위로 보정한다.

완료 후에는 기존 Quick Look/Thumbnail 기본 정책인 `.coreGraphicsOnly`를 유지하면서, 서명란의 `U+F012B`는 의도된 `(인)` 표시로 보이고 하단 filler 성격의 `U+F081C`는 깨진 글리프로 노출되지 않아야 한다.

## 배경

v0.1.4 draft DMG 설치 smoke 준비 중 `samples/복학원서.hwp` Quick Look preview에서 PUA 문자가 fallback glyph/tofu로 표시되는 문제가 확인되었다.

현재 앱의 Quick Look/Thumbnail 기본 경로는 upstream PageLayerTree가 아니라 `PageRenderTree`를 Swift `CGTreeRenderer`가 그리는 CoreGraphics 경로다. 이 경로의 `TextRunNode`는 `text`만 소비하며, upstream `rhwp v0.7.13`에 포함된 PageLayerTree `displayText` 계약을 사용하지 않는다. 따라서 `edwardkim/rhwp#982` 계열의 PageLayerTree 표시 문자열 보정이 현재 기본 preview surface에 자동 반영되지 않는다.

장기적으로는 Swift 쪽에 upstream PUA 보정을 계속 복제하기보다 PageLayerTree `displayText`와 resolved payload를 소비하는 방향이 맞다. 그러나 해당 전환은 Skia/PageLayerTree backend, Thumbnail cache signature, visual/performance gate를 함께 다뤄야 하므로 이번 release-blocking 작업에서는 제외한다.

## 범위

포함:

- Swift/CoreGraphics 텍스트 렌더링 경로에서 확인된 PUA의 최소 표시 보정
- `U+F012B`를 서명란 `(인)` 표시로 대체
- `U+F081C` filler를 화면에 깨진 문자로 그리지 않도록 처리
- Quick Look preview와 Finder thumbnail이 공유하는 renderer 경로에 보정 적용
- `samples/복학원서.hwp` 중심 render tree/native output smoke
- 기존 `.coreGraphicsOnly` 기본 정책과 `.skiaOptIn` 진단 경로 유지 확인

제외:

- Quick Look/Thumbnail 기본 backend를 PageLayerTree/Skia로 전환
- Swift PageLayerTree renderer 신규 구현
- upstream `rhwp` 수정 또는 unreleased commit pin 적용
- release workflow, DMG, signing/notarization, Homebrew, Pages/appcast 변경
- 일반 PUA 전체 매핑 테이블 도입

## 설계 방향

보정 위치는 `CGTreeRenderer`가 실제 CoreText 문자열을 만들기 직전의 공통 텍스트 변환 지점으로 제한한다. 이렇게 하면 Quick Look preview와 Finder thumbnail이 동일한 `HwpPageImageRenderer`/`HwpNativePageCompositor` 경로를 쓰는 한 같은 결과를 얻을 수 있다.

이번 변경은 `복학원서.hwp`에서 확인된 두 codepoint만 다룬다. `U+F012B`는 표시 문자열 `(인)`으로 변환하고, `U+F081C`는 빈 문자열로 처리한다. 빈 문자열이 된 run은 layout/draw가 의미 없으므로 drawing을 생략하는 방향을 우선 검토한다.

기존 `run.text` 기반 layout width와 `charPositions` 처리는 보정 문자열과 원문 글자 수가 달라질 수 있다. 따라서 보정된 문자열을 CoreText attributed string과 layout plan 입력에 같이 사용하되, 문자 수가 달라지는 경우 `charPositions`를 그대로 쓰지 않는 방식으로 안전하게 제한한다.

1. Stage 1: 현행 PUA 재현과 렌더링 입력 inventory

   - `CGTreeRenderer` 텍스트 렌더링 직전 보정 helper를 추가한다.
   - 보정 문자열이 빈 문자열이면 draw를 생략한다.
   - 보정 문자열과 원문 길이가 다르면 `charPositions`를 사용하지 않도록 한다.

   - `samples/복학원서.hwp`의 CoreGraphics native output을 재생성해 PUA 깨짐이 사라졌는지 확인한다.

   - 최소 보정 범위, 검증 결과, 장기 PageLayerTree/Skia 전환 후속 관계를 정리한다.

## 리스크

- `U+F012B`를 `(인)`으로 바꾸면 원문 1 codepoint가 3글자 표시 문자열로 바뀌므로 기존 `charPositions`와 폭/정렬이 맞지 않을 수 있다.
- CoreGraphics 쪽 임시 보정이 늘어나면 upstream PageLayerTree `displayText` 계약과 중복 유지보수 비용이 생긴다.
- 일반 PUA 전체를 추정 매핑하면 오탐 위험이 있으므로 이번 작업은 확인된 codepoint만 다룬다.
- Quick Look UI cache와 Finder thumbnail cache 때문에 소스 보정 후에도 설치본 smoke에서 이전 bitmap이 보일 수 있다.
- release 직전 작업이므로 backend 정책이나 광범위 renderer 구조를 바꾸면 배포 리스크가 커진다.
