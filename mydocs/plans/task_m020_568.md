## 1. 목적

Studio에서 사용하는 설치 참조·관리 복사본을 PDF·인쇄와 native·Quick Look·Thumbnail에도 연결한다. 문서가 요청한 family/style과 실제 선택된 face/bytes를 소비자별로 확인하고, 출력 중 문서·글꼴 변경이나 권한 실패가 다른 문서 또는 오래된 자산의 출력으로 이어지지 않게 한다.

기존 이슈의 A(PDF·인쇄)를 먼저 진행하고 B(native·Quick Look·Thumbnail)는 별도 완료 기준으로 유지한다. A의 성공만으로 #568 전체를 완료하거나 Finder 지원을 선언하지 않는다. Mac 수용은 #566 Windows ZIP 완료를 기다리지 않고 진행하며, Windows 입력 수용은 후속 조건으로 구분한다.

## 2. 배경과 시작 조사

#567에서 공식 core/Studio `v0.8.7` / `1a76570e833917d15817415a53c09ad61ab3203f`를 반영하고 공유 설치 catalog·필요 bytes 공급·관리 snapshot/lease를 기존 글꼴 메뉴와 문서에 연결했다. [최종 보고](../report/task_m020_567_report.md)와 [소비자 인계 계약](../tech/font_library_integration.md)을 재사용한다. core pin이나 Studio 산출물을 다시 갱신하는 일부터 시작할 필요는 없다.

2026-10-08 현재 소스를 읽고 확인한 출발점은 다음과 같다. 아직 새 실험을 수행한 결과는 아니다.

| 위치 | 확인한 현재 동작 | 후속 판단 |
|------|------------------|-----------|
| `RhwpStudioHostBridgeScript.documentPages()` | `getPageSvg`로 페이지 SVG를 수집 | portable SVG에 필요한 face의 식별·출력 문서 상태를 묶는 방법 확인 |
| `RhwpStudioPagePayload` | 파일명·페이지 수·SVG 배열만 포함 | 출력 작업의 문서 identity와 글꼴 snapshot 계약 보강 |
| `RhwpStudioPagePDFRenderer` | PDF·인쇄 공용의 별도 nonpersistent WKWebView, content JS 차단·준비 script·page timeout | 사용자 face를 준비한 뒤 `createPDF`, 취소·실패·재진입 수명 유지 |
| `RhwpStudioPDFFontProvider/Style` | exact Noto WOFF2 4종만 허용, 한글 alias와 미분류 한글을 Noto로 대체 | 정확한 사용자 face와 기존 Noto fallback의 적용 범위를 분리 |

공식 host-font API는 화면 연결에 사용 중이지만, JS가 차단된 PDF WebView에 그 연결을 그대로 복사하지 않는다. 기존 좁은 리소스 공급 방식과 앱 소유 준비 script를 확장하는 방안을 우선 검토한다. 추가 upstream 출력 API를 필수 선행 조건으로 둘 근거는 현재 없다. Stage 1에서 실제 source와 필요한 최소 실험으로 확인한다.

## 4. 설계 방향

- `InstalledFontServiceProvider.shared`와 `FontLibraryService.shared`를 재사용한다. 출력마다 전체 글꼴을 선읽거나 관리 저장소에 복사하지 않고 실제 필요한 face만 검증해 공급한다.
- 출력 작업은 문서 epoch/revision, 설치 generation, 관리 선택·snapshot digest와 선택된 face identity를 함께 소유한다. 관리 lease는 완료/취소까지 유지하고, 설치 참조는 읽을 때 원본 상태를 검증한다. 전체 작업의 변경 감지·이미 읽은 bytes의 수명·최종 게시 조건은 Stage 1에서 확정한다.
- #567의 관리 선택·동명 충돌·설치 후보 정책과 upstream matcher를 재사용할 경계를 조사한다. 이름만 같다는 이유로 다른 원본/버전/굵기를 선택하지 않고 내부 출력 alias를 원본 문서에 저장하지 않는다.
- 내장 Noto의 exact route와 제한을 보존하고 사용자 snapshot에만 유효한 opaque ID 기반 공급 경계를 둔다. 문서가 지정한 임의 경로·URL, 외부 네트워크·탐색·content script로 공급 범위를 넓히지 않는다.
- 현재 Noto 한글 대체가 exact 사용자 face를 덮지 않게 하되, 공급 대상이 아닌 글꼴의 기존 fallback과 한글/자모·ASCII·수식·Hanja 경계를 유지한다. 준비 실패를 시스템 fallback 성공으로 숨기지 않는다.
- `FontFace.embeddingFlags`의 기술적 제약과 `FontUsageEvidence`의 `unknown/allowed/restricted`를 구분한다. `unknown`을 허가로 바꾸지 않고 기존 사용 근거를 유지한다. 허용되지 않거나 증명할 수 없는 face의 취소/명시 대체 정책은 Stage 1에서 결정하며, 새 라이선스 승인 UI를 지금 전제하지 않는다.
- PDF는 font resource·PS/스타일·임베딩과 `/ToUnicode`, 문자열 추출·검색·선택·복사를 함께 검증한다. 화면처럼 보인다는 이유나 파일 크기만으로 성공 판정하지 않는다.
- 인쇄는 같은 renderer를 사용하더라도 요청 시점·문서 전환·패널·completion 수명을 따로 검증한다. PDF 저장 성공으로 인쇄 완료를 대신하지 않는다.
- B의 native·확장은 필요한 공통 경계만 `devel`에서 다룬다. native HostApp UI 전환은 범위가 아니다. RhwpCoreBridge의 AppKit/UIKit 금지와 FFI 수명을 유지하며, 추가 core API가 실제 필요하면 해당 단계 진입 전에 의존성과 계획을 다시 승인받는다.

## 7. 검증 계획

- Stage 1의 조사 범위에서는 현재 v0.8.7 source와 #563/#564/#565/#567 증거를 재사용한다. 계획 문서 작성 때문에 제품 전체 빌드를 반복하지 않는다. 구현 변경 후 해당 경계의 최소 검증을 적용한다.
- 다운로드 승인으로 확보한 고운바탕 Regular/Bold·OFL/provenance와 기존 설치 NanumSquareR/B의 유효 상태를 확인해 격리 문서에 사용한다. 한국어 표시·정확한 style/PS/hash·파일 공급 성공을 별도로 기록하고 영구 OS 설치 없이 시작한다.
- 기존 PDF renderer/export/print lifecycle 테스트, 글꼴 109개·JS 25개 기준과 실제 문서 lifecycle smoke의 관련 회귀를 확인한다. 새로운 snapshot/route/cancellation 경계에 필요한 테스트만 추가한다.
- PDF는 HWP/HWPX 각각의 현재 편집 본문과 목표 face를 확인한다. `CGPDFFontResourceInspector`, PDFKit 선택·검색·문자열, 가능한 `pdffonts`/`pdftotext`로 독립 대조한다. 실제 PDF 뷰어의 선택·검색·복사와 확대 화면을 확인하고 PDF·인쇄를 따로 집계한다.
- 공급 없는 대조군·Noto fallback 대조군·설치와 관리의 동명 충돌을 구분한다. Regular/Bold 모두 실제 bytes 및 PDF font resource를 확인해 기존 시스템 대체가 실패를 가리지 않게 한다.
- 출력 도중 설치 상태·사용 설정·관리 선택/제거·문서 revision이 바뀌는 경우, 빠른 재출력·취소·timeout·WebContent 종료·쓰기 실패에서 일관성·lease 해제·기존 목적지 보존을 검사한다.

- 합성 문서·별도 output과 probe를 `build.noindex/task568/` 아래에 둔다. 실제 사용자 문서·설치본·열려 있는 #567 테스트 창을 바꾸지 않는다. 로컬 서명·새 폴더 권한 등 필요한 구체 조작은 대상이 준비된 시점에 승인 범위를 확인한다.

## 8. 리스크

- portable SVG만으로는 화면 provider의 정확한 face 선택과 bytes를 출력에 보장할 수 없다. SVG 요청 스타일·host matcher·실제 출력 face의 연결을 먼저 검증해야 한다.
- 기존 Noto 한글 대체는 Unicode mapping을 보강하기 위한 정책이다. 이를 제거하거나 사용자 font로 바꾸면 표시가 맞아도 검색·복사·ToUnicode가 퇴행할 수 있다.
- 설치 참조는 managed lease처럼 원본을 고정하지 못한다. 출력 작업 중 원본·권한·generation이 바뀌는 경우 이미 읽은 bytes와 새 요청을 섞지 않는 정책이 필요하다.
- `StudioFontSupply`의 화면 DTO는 출력의 임베딩/사용 근거를 모두 담지 않는다. 그대로 직렬화해 출력 허가나 일관성을 보장했다고 주장하지 않는다.
- B는 HostApp과 다른 sandbox·메모리·수명·Finder 캐시를 가진다. A의 성공이나 App Group 존재만으로 확장 원본 접근·정확한 face 사용을 완료 처리할 수 없다.
- TTC/가변·동명 충돌·부족한 사용 근거·최소 OS와 실제 서명 환경의 한계는 소비자별로 남긴다. #566 미완료를 Mac 검증으로 덮지 않는다.
