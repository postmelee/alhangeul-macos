## 1. 목적

Mac의 활성 설치 글꼴과 별도로 가져온 관리 글꼴을 실제 Studio 문서 표시·편집에 연결한다. 정상 권한에서는 재실행 후에도 사용자 재탐색·재가져오기 없이 필요한 글꼴을 적용한다. 목록에 나타나는 것과 정확한 face가 렌더링되는 것을 구분해 검증한다.

## 2. 배경

#565는 설치 목록·설정·권한 지속 및 native 공급 API를 제공하지만 제품 Studio는 아직 연결되지 않았다. 독립 probe에서 NanumSquare Regular/Bold의 공급을 확인했으나 실제 HWP/HWPX 편집·저장·재열기 검증을 대신하지 않는다. [공통 연동 계약](../tech/font_library_integration.md)을 기준으로 기존 rhwp 매칭과 캐시를 재사용한다.

Stage 3.2 출발 시 제품 core/Studio 기준은 `v0.8.6`, `f1f9c6ae58344ee9368996d3543f76b9345cf227`이다. 호스트 글꼴 공급 API는 upstream [#7405](https://github.com/edwardkim/rhwp/pull/7405)로 병합되었고 [v0.8.7](https://github.com/edwardkim/rhwp/releases/tag/v0.8.7)에 포함되었다. 2026-10-07 조회한 동일 릴리즈 sync PR은 없다. 정식 태그로 core/Studio를 반영한 뒤 준비한 앱 어댑터의 실제 제품 통합을 검증한다. [진행 순서·관련 이슈 검토](../tech/task_m020_567_replan.md)를 따른다.

## 3. 범위(포함·제외)

포함:

- 단일 설치 catalog 소유권, 설정과 Studio가 공유하는 초기화·갱신 흐름.
- 신뢰한 WebView 메시지 경계에서 catalog 및 opaque ID 기반 필요한 bytes 공급.
- 기존 PS/full/family+style·별칭 매칭 재사용, 관리 복사본과 설치 참조의 충돌·우선순위 확정.
- CSS/SVG/Canvas2D와 CanvasKit 각각의 정확한 face 적용 및 로드 완료 후 측정·표시 갱신.
- 설치 상태·설정·권한·관리 자산 선택 변경 시 열린 문서와 캐시 갱신.
- 글꼴 선택·입력·저장·재열기와 원래 문서 글꼴 이름 보존.
- 지원 상태에 맞는 설정 안내 조정, 실제 화면·직접 조작 경로 제공.

제외:

- Windows ZIP 입력 UI(#566), PDF·인쇄·native·Quick Look·썸네일 연결(#568), 제품 웹 안내·전체 수용(#569).
- 한컴 앱 내부 자동 추출, 한컴 제거, 사용자 기존 글꼴 삭제, 상용 글꼴 재배포, HFT 지원.
- TTC/가변의 무조건적 지원, 원본 삭제 후 설치 참조 유지 보장, 전체 레이아웃 완전 재현, 릴리스.

## 4. 설계 방향

- 설치 service를 중복 생성하지 않고 UI와 Studio가 같은 actor를 사용한다. 생성·파일 읽기는 UI 스레드를 막지 않는다.
- WebView에는 경로·bookmark를 전달하지 않는다. 신뢰한 frame/session과 요청 크기·수명·취소를 검증하고 ID+generation으로 읽는다.
- catalog 열거는 전체 bytes 읽기를 유발하지 않는다. 필요한 요청만 공급하고 동시 요청 병합·제한 및 일시적인 busy 재시도를 연결한다.
- 설치 generation 변경은 진행 중 요청과 Typeface·측정·실패 캐시를 함께 무효화한다. 문서 전환·종료 후 늦은 응답이 다른 문서에 적용되지 않게 한다.
- 관리 복사본은 snapshot/lease/digest 수명을 유지한다. 원본 의존 설치 참조와 독립 저장을 구분하고 중복·동명 버전 선택을 암묵적으로 합치지 않는다.
- 내부 renderer alias는 문서에 저장하지 않는다. 정확한 스타일 증거가 없는 TTC/가변은 제한과 fallback을 명시한다.
- 현재 사용 설정의 기본값은 false다. 기존 사용자 선택을 보존하며 초기 자동 사용 기본값·이전 설정 이관 여부를 구현계획에서 명확히 제안한다. 준비 중 안내는 실제 제품 연결이 검증된 범위만 수정한다.
- 병합된 `window.rhwpStudio.fonts` API를 사용한다. 별도 임시 core 확장 없이 앱 어댑터를 준비하고, 정식 릴리즈의 core/Studio pin·sync 후 제품에 연결한다. bundled minified 산출물을 직접 패치하지 않는다.

## 7. 검증 계획

- 기존 설치 NanumSquare Regular/Bold로 실제 한글 표시의 기준을 확인한다. 저장소 자체 fixture는 이름·충돌·손상·권한·캐시 상태 전이용으로 사용하며 실제 한글 품질 검증으로 주장하지 않는다.
- 실제 OS 설치·비활성화·제거 수용에는 기존 시스템/번들 글꼴과 구분되는 테스트용 한글 family의 static Regular/Bold를 사용하는 방안을 권장한다. 새 파일을 선택할 때 공식 배포처·라이선스·버전·해시를 기록한다. 2026-09-20 사용자가 웹 다운로드를 승인하여 고운바탕 Regular/Bold와 OFL을 테스트 폴더에 확보했다. OS 지속 설치는 아직 수행하지 않았다.
- OS 지속 설치가 필요하면 테스트 파일·설치 위치·복구 범위를 제시해 승인받고 해당 테스트 자산만 변경한다. 프로세스 등록 fixture 결과와 실제 OS 설치 결과를 구분한다.
- 렌더러별 요청 이름·스타일 → 선택된 ID/PS/face → 검증 bytes hash → 실제 표시 증거를 남긴다. CSS 적용 또는 fallback 성공을 CanvasKit의 해당 글꼴 적용 성공으로 대신하지 않는다.
- 설치 원본 부재 시 fallback과 독립 관리 복사본 유지, 관리 복사본도 없는 대조군을 확인한다. 동일 이름의 시스템 대체 글꼴 때문에 공급 실패가 가려지지 않게 한다.
- 실제 HWP/HWPX에서 선택·입력·저장·재열기 시 이름·굵기 보존, 내부 alias 미유출을 검증한다.
- cold/warm/반복 열기의 읽기 수와 캐시 재사용, generation 변경·빠른 문서 전환·실패 복구를 확인한다.
- 변경 유형별 HostApp 빌드, 글꼴·Studio 관련 테스트 및 lifecycle smoke를 실행한다. signed sandbox 새 프로세스에서 설정·권한 복원과 실제 적용을 검증한다.
- 시각적 변경 시 실제 스크린샷과 직접 조작할 창 또는 실행 경로를 제공한다. 산출물은 `build.noindex/`에 두고 개발 확장 등록은 표준 smoke 정리 절차를 따른다.
- macOS 12 대상 컴파일과 실제 최소 OS 실행을 구분한다. 확보되지 않은 환경은 미검증으로 기록한다.

## 8. 리스크

- 현재 pinned Studio에는 새 API가 없다. 어댑터의 격리 검증과 제품 전체 적용을 구분하고, 릴리즈에 API가 실제 포함되었는지 확인한 뒤 동기화한다.
- WKWebView의 CSS 접근과 CanvasKit bytes 공급은 다르다. 별도 증거 없이는 동일 지원으로 묶지 않는다.
- 원본 상태와 renderer 캐시 갱신이 어긋나면 삭제된 글꼴이 계속 보일 수 있다. 세대·문서 수명과 실패 캐시까지 검증한다.
- 동명 글꼴·별칭·굵기 우선순위를 잘못 선택하면 기존 문서가 달라질 수 있다. 정확한 선택을 증명하지 못하면 정상 fallback과 제한을 기록한다.
- probe의 권한 성공을 모든 설치 위치·제품 전체 소비자 권한으로 확대하지 않는다. 기존 사용자 글꼴과 권한 설정을 훼손하지 않는다.

## 9. 승인 요청 사항

기존 수행·구현계획과 무료 글꼴 다운로드는 승인되었다. 2026-09-26 Stage 3.1, 2026-10-07 v0.8.7 반영과 연결 지시에 따른 Stage 3.2, 기존 글꼴 목록 통합 지시에 따른 Stage 3.3을 완료·보고했다. Stage 4/5는 기존 단계 승인 절차를 따른다. OS 지속 설치·제품 배포는 이번 승인에 포함하지 않는다.
