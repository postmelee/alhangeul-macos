# Task #558 — Threads 기존 소식 수동 표시와 Meta 문의

## 목적과 승인 범위

- 이슈: https://github.com/postmelee/alhangeul-macos/issues/558
- 브랜치: `local/task558`, 통합 대상: `devel`, 공개 대상: `main`.
- 작업지시자는 2026-09-15 Meta 문의 제출과 현재까지 올라온 게시글로 공개 소식 목록을 채우도록 지시했다.
- 문의 제출은 기존 초안 범위로 승인되었다. 코드 구현은 본 수행계획 검토 후 단계 절차에 따라 진행한다.

## 현재 상태

Task #555 및 PR #557 UI는 공개됐다. 자동 수집은 비활성이고 현재 수집 helper는 비활성일 때 빈 seed를 강제한다. 기존 snapshot을 그대로 공개하면 48시간 뒤 만료하므로 수동 목록을 명시적으로 구분해야 한다.

## 수행 범위

1. Meta 개발자 지원에 전체 사용 목적 문의를 제출하고 접수 URL·번호 또는 실제 제출 장애를 기록한다. AI 답변·커뮤니티 답변을 Meta의 개별 승인으로 간주하지 않는다.
2. 계정 소유자가 요청한 기존 공개 게시물을 공개 원문에서 확인하여 수동 순서 목록으로 구성한다. 초기 후보는 기존 검증에서 확인한 6개이며 공개 접근·작성자·알한글 태그를 다시 확인한다.
3. 자동 수집과 독립된 수동 목록 모드를 추가한다. 목록에는 플랫폼과 영구 링크만 저장하고 본문·사진·영상·임베드 HTML을 복제하지 않는다.
4. 수동 목록은 자동 수집 시각을 꾸미거나 48시간 갱신을 가장하지 않는다. 수동 목록의 표시·제거·추가 절차를 별도로 정의한다. 공식 Threads 임베드가 원문 표시를 담당한다.
5. 홈 최신 1개, 전용 페이지 5개 단위 추가 표시와 승인된 스켈레톤·전환 UI를 유지한다.
6. Docs-only/Release Pages 조립 모두 수동 목록을 보존하고 자동 수집이 우선되는 경우를 명시한다. 비활성·수동·자동 상태를 혼동하지 않게 검증한다.
7. PR 검증 후 승인된 공개 배포를 진행하고 appcast bytes 동일성·공개 화면을 확인한다.

## 제외

자동 수집 공개 활성화, Meta 앱 게시·추가 권한 신청, 앱 DMG 릴리스, X 연동, 비공개 게시물 및 API 결과 본문 재게시.

## 예상 단계

- Stage 1: 문의 접수 결과와 공개 게시물 확인, 수동 데이터 계약·운영 방식 확정.
- Stage 2: 수동 데이터·검증·UI 및 두 Pages 경로 구현, 모드 간 회귀 검사.
- Stage 3: 브라우저 검증·운영 안내·최종 보고·PR·공개 반영 검증.

## 검증

수동 목록 정상/중복/잘못된 URL, 자동 snapshot 만료 유지, 비활성 빈 목록, 수동 모드의 토큰 없는 처리, Pages 재배포 보존, 기존 수집·UI·Pages 테스트, 공식 임베드 실제 표시·홈1/목록5+1, 공개 appcast 보존을 확인한다.
