# Task M019 #336 수행계획서

## 목적

`rhwp Upstream Sync PR` workflow가 upstream `rhwp`의 WASM build 전에 `.env.docker`를 준비하지 않아 실패하는 문제를 수정한다.

완료 후에는 upstream release에 viewer impact가 있어 자동 sync PR 후보 생성 경로가 build 단계로 진입했을 때, upstream repository가 `.env.docker.example`만 제공하더라도 workflow가 `.env.docker`를 준비하고 WASM/rhwp-studio build 명령을 계속 실행할 수 있어야 한다.

## 배경

2026-06-05 scheduled GitHub Actions run `26996434439`에서 `rhwp Upstream Sync PR` workflow가 실패했다.

- workflow: `rhwp Upstream Sync PR`
- job: `Create rhwp-studio sync PR candidate`
- 실패 단계: `Build upstream rhwp-studio assets`
- current bundled release: `v0.7.13`
- target upstream release: `v0.7.14`
- impact detection: `has_viewer_impact=true`, `impact_reason_count=171`

실패 로그의 직접 원인은 upstream checkout root의 `.env.docker` 누락이다.

```text
couldn't find env file: .../build.noindex/rhwp-upstream/.env.docker
```

upstream `edwardkim/rhwp`의 `v0.7.13`과 `v0.7.14`에는 `.env.docker`가 없고 `.env.docker.example`만 있다. example 파일은 `.env.docker`로 복사한 뒤 `docker compose --env-file .env.docker run --rm wasm`를 실행하라는 사용 방식을 안내한다. 현재 workflow는 이 준비 단계를 생략한 채 `--env-file .env.docker`를 지정한다.

## 범위(포함·제외)

포함:

- `.github/workflows/rhwp-upstream-sync-pr.yml`의 `Build upstream rhwp-studio assets` 단계 보강
- upstream root에서 `.env.docker`가 없고 `.env.docker.example`이 있으면 `.env.docker`를 생성하는 방어 로직 추가
- workflow YAML parse와 shell helper syntax 검증
- 로컬에서 가능한 수준의 build 단계 사전 조건 검증
- 필요 시 `mydocs/manual/ci_workflow_guide.md`의 upstream sync PR 실패 해석 또는 재현 절차 보강 검토

제외:

- bundled `rhwp-studio` asset 갱신
- `rhwp-core.lock` 갱신
- RustBridge dependency 갱신
- upstream `edwardkim/rhwp` 수정
- release, signing, notarization, Homebrew 배포
- 자동 sync PR 실제 생성, push, merge

## 설계 방향

수정은 upstream checkout을 소비하는 build 단계 내부에 한정한다. upstream source tree에는 `.env.docker.example`이 tracked file로 제공되고 `.env.docker`는 로컬 실행용 파일이므로, CI에서는 build 직전에 example을 복사해 Compose가 요구하는 env file을 명시적으로 준비한다.

구현은 다음 조건을 우선한다.

- `.env.docker`가 이미 있으면 덮어쓰지 않는다.
- `.env.docker`가 없고 `.env.docker.example`이 있으면 `cp .env.docker.example .env.docker`를 실행한다.
- 둘 다 없으면 명확한 오류 메시지를 출력하고 실패한다.
- Docker Compose 명령과 후속 `npm ci`, `npx tsc`, `npx vite build --base ./` 흐름은 유지한다.

이 변경은 이전 #287의 LFS smudge skip 보강과 별개로, 그 다음 build 단계에서 발견된 환경 파일 준비 누락을 해결하는 follow-up 성격이다.

최종 확인 기준:

- workflow가 upstream `.env.docker.example`을 CI용 `.env.docker`로 준비한다.
- `.env.docker`가 이미 있는 경우 덮어쓰지 않는다.
- workflow YAML parse와 shell helper syntax 검증이 통과한다.
- bundled `rhwp-studio`, `rhwp-core.lock`, RustBridge dependency는 변경하지 않는다.
- GitHub-hosted runner에서의 실제 Docker/WASM build 재실행은 PR 이후 또는 workflow_dispatch로 확인할 잔여 항목으로 기록한다.

## 리스크

- `.env.docker` 준비 이후에도 upstream Docker image build, wasm-pack, npm dependency, TypeScript, Vite build 단계에서 별도 실패가 드러날 수 있다. 이번 작업은 현재 확인된 env file 누락을 해결하되, 후속 build 실패는 별도 원인으로 분리한다.
- GitHub-hosted runner의 Docker Compose 버전 차이로 로컬 검증과 실제 Actions 결과가 다를 수 있다.
- upstream이 향후 `.env.docker.example` 파일명을 변경하면 같은 방식이 다시 실패할 수 있으므로 오류 메시지는 원인 파악이 쉬워야 한다.
- 자동 sync PR 실제 생성은 repository write 권한과 upstream build 전체 성공이 필요하므로 로컬에서 완전히 대체할 수 없다.
