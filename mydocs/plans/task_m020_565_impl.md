## 확인한 재사용 경계

기준은 `rhwp-core.lock` 및 bundled Studio의 v0.8.6 / `f1f9c6ae58344ee9368996d3543f76b9345cf227`이다.

- Studio `src/core/local-fonts.ts`: 저장된 목록, PS/full/family+style 매칭, 모호한 family 처리, 필요 bytes 요청 및 진행 중 요청 병합이 있다. 현재 bytes 로더는 Local Font Access 경로를 요구하므로 WKWebView native 공급이 자동으로 연결된다고 가정하지 않는다. 진행 중 Promise 병합은 영구 bytes 캐시가 아니다.
- Studio `src/view/canvaskit-renderer.ts`: local font bytes와 typeface 사용 경로가 있다. 변경 알림에 따른 기존 typeface 무효화는 실험에서 확인한다.
- native `src/renderer/font_paths.rs`: 시스템 폴더를 custom 경로에 넣으면 family당 단일 typeface로 스타일 선택을 잃을 수 있어 기존 시스템 FontMgr 매칭 경계를 유지한다. OS 폴더를 custom font_paths에 일괄 추가하지 않는다.

## Stage 1–2 — 완료 이력

[Stage 1](../working/task_m020_565_stage1.md), [Stage 2](../working/task_m020_565_stage2.md)의 탐색·일시 scope·가져오기 서비스·화면은 유지한다. OS 폴더 파일 탐색은 활성 face 감지를 대신하지 않으며, 복사 성공은 설치 글꼴 자동 사용의 성공이 아니다. 기존 Stage 3 충돌/삭제 UI 계획은 아래 단계로 대체한다.

## Stage 3 — 최소 native→rhwp 연결 실험

제품 UI 확장 전에 독립 probe로 필요한 연결 위치와 한계를 확정한다. 실험 소스·로그는 재현 가능하게 보존하되 제품 완료로 간주하지 않는다.

1. CoreText 활성 descriptor에서 PS/full/family, style/traits, face/축, 실제 원본 identity를 추출하고 폴더 후보 목록과 구분한다. 기존 설치된 사용 가능한 글꼴을 우선하며 사용자 설치 상태를 변경하지 않는다.
2. 고정 Studio의 기존 이름·스타일 선택을 거쳐 native가 제공한 식별자와 필요한 bytes가 실제 renderer face에 연결되는 최소 adapter를 실험한다. CSS 존재 감지와 CanvasKit 데이터 사용을 구분한다.
3. 일반/굵은 스타일 요청과 동명/모호한 이름 음성 대조군을 실행한다. 요청 이름, 선택 PS/face/style, 원본 식별, 공급 bytes 지문, 실제 renderer 선택 증거와 문서 화면을 기록한다. 단순 육안 유사성은 통과 기준이 아니다.
4. cold/warm/새 프로세스에서 요청·실제 읽기 수와 캐시 수명을 측정한다. 최소 설정 복원 실험과 권한 경계를 확인하되 완성된 지속 계층은 Stage 4에 둔다.
5. 자체 fixture/주입 오류로 원본 부재·권한 실패·손상 시 fallback을 확인한다. 사용자 글꼴 삭제·비활성화는 하지 않는다. 실제 설치 상태 변경 테스트가 필요하면 자체 fixture와 변경 범위를 먼저 명시한다.

산출물: 재현 명령, 선택 근거, 화면, 공급 계약 초안, signed sandbox에서 확인한 범위/미확인 범위. 기존 rhwp 계약으로 불가능하거나 upstream 수정이 필요하면 이유와 최소 변경안을 보고하고 후속 범위를 재승인받는다. 최소 연결 실패를 catalog/UI만 구현하여 우회 완료하지 않는다.

## Stage 4 — 활성 목록·설정·권한 지속

- HostApp 서비스가 CoreText의 활성 face를 기준으로 catalog를 만든다. 경로만으로 식별하지 않고 원본 resource identity/변경 정보, PS/face/style/축과 catalog generation을 함께 다룬다. 같은 PS의 다른 원본·버전을 임의로 덮어쓰지 않는다.
- 사용 설정과 메타데이터를 지속한다. 정상 접근이 가능한 경로는 불필요한 권한 요청을 하지 않는다. 실제 sandbox에서 필요한 경로에 한해 선택 URL/bookmark의 지속 권한을 검증하며 stale bookmark·resolve 실패·원본 이동/권한 상실을 구분한다.
- 시작 시 가벼운 재검사, 설치 상태 알림의 병합 처리, 수동 새로고침, 사용 직전 유효성 검사를 조합한다. 변경된 원본은 catalog와 소비자 cache generation을 갱신하고 오래된 in-flight 결과를 적용하지 않는다.
- bytes는 필요할 때 제한된 크기로 읽고 동시 요청을 병합한다. 전체 bytes 영구 복사나 매번 모든 파일 읽기를 하지 않는다. 읽기 중 교체/손상도 실패로 처리한다.
- 검증: 새 프로세스 설정 복원·scope 균형·권한 복구·동명 충돌·변경/삭제/비활성·알림 누락·오래된 결과 무시.

## Stage 5 — UI와 공급 계약

- 설정을 ‘Mac에 설치된 글꼴 사용’과 ‘글꼴 목록 새로고침’ 중심으로 구성한다. 기본 사용은 복사/import 동작을 호출하지 않는다.
- 초기 감지·사용 가능·일부 제한·권한 복구·오류 상태를 안내한다. 설치 글꼴 원본을 삭제하는 관리 기능을 제공하지 않는다. 별도 가져오기 데이터와 설치 참조의 수명을 구분한다.

- 상태 전이·취소/오래된 응답·설정 지속 테스트와 실제 UI 스크린샷/실행 경로를 제공한다. 시각 확인은 밝은/어두운 모드, 긴 이름, 키보드 동작을 포함한다.

## 2. 탐색 계약

### 출처와 범위

- 자동 한글 탐색은 `/Applications`와 실제 사용자 홈의 `Applications`를 대상으로 한다. sandbox의 컨테이너 홈을 사용자 홈으로 오인하지 않도록 홈 해석을 분리·테스트한다. 실제 외부 폴더 접근 실패는 위치 선택으로 복구한다.
- 일반 디렉터리만 제한 깊이로 순회하고 `.app`에서 내부 앱 재귀 탐색을 멈춘다. 확인된 뷰어 bundle ID와 조사 자료를 근거로 설치본을 식별한다. 미확인 편집기 ID를 추측해 확정 목록에 넣지 않는다. 이름만 유사한 앱은 자동 한컴 출처로 확정하지 않는다.
- 앱 내부는 `Contents/Resources/Hnc/Shared/TTF/Install`, `Contents/Resources/Hnc/Shared/TTF/Hwp`, `Contents/Resources/Hnc/Shared/Fonts`만 문서 글꼴 후보 경로로 읽는다. 직접 선택한 앱도 전체 번들을 글꼴 폴더처럼 재귀 탐색하지 않는다.
- 직접 선택한 일반 폴더는 그 폴더 범위 안에서 순회한다. 알려진 앱으로 확인되지 않은 입력은 ‘직접 선택한 폴더’ 출처로 남긴다.
- OS 설치 글꼴은 사용자 `Library/Fonts`와 `/Library/Fonts`를 별도 묶음으로 제시한다. `/System/Library/Fonts`는 이전 대상에서 제외한다. CoreText에 없다는 사실을 부재 판단에 사용하지 않는다.
- 설치본별 표시 이름·버전·위치와 후보 파일명·크기·출처를 보여준다. 탐색에서는 font bytes 전체 파싱을 반복하지 않고, 실제 형식·메타데이터·중복은 공통 importer가 최종 판정한다.

### 한도와 오류

| 항목 | 초기 구현 기준 |
|------|----------------|
| Applications 검색 깊이 | 루트 기준 4단계, 앱 내부는 알려진 경로만 |
| 선택 글꼴 폴더 깊이 | 루트 기준 32단계 |
| 한 번의 탐색 방문 항목 | 파일·디렉터리 합계 20,000개 |
| 가져오기 후보 | 세션 전체 최대 4,096개, 여러 출처 선택을 합산 |
| 실제 읽기 | 기존 importer의 파일 64 MiB·배치 1 GiB 한도 유지 |

디렉터리 항목을 한 번에 무제한 배열로 적재하지 않고 제한된 순회로 수집한다. symlink·alias를 따라가지 않으며 루트 밖 접근과 순환을 방지한다. 후보 확장자는 대소문자를 구분하지 않고 TTF·OTF·TTC·OTC를 수집한다. HFT는 미지원 발견 건수로 안내하고 가져오기 선택에서는 제외한다. 확장자만으로 지원 성공을 표시하지 않는다.

한도 도달은 ‘일부만 검색됨’으로 명시하고 더 좁은 폴더 선택을 안내한다. 발견된 부분 목록은 확인 후 가져올 수 있으나 완전 탐색으로 보고하지 않는다. OS 오류는 미존재·접근 거부·기타 읽기 실패로 구분한다. 접근 거부는 권한 테스트 주입과 실제 sandbox 양쪽에서 검증한다.

중복 경로는 세션 내 식별자로 합치고, 서로 다른 위치의 동일 bytes는 공통 저장소가 중복 판정한다. 정상 탐색 완료 시 표시 순서를 정렬하며 부분 탐색의 수집 범위는 제한에 따라 달라질 수 있음을 기록한다.

## 3. 권한과 비동기 수명

- NSOpenPanel은 앱 또는 디렉터리를 선택하게 하며 취소는 오류 경고 없이 이전 화면으로 돌아간다. 자동 탐색 실패 뒤 선택 URL을 받으면 해당 위치를 다시 탐색한다.
- `FontImportSourceSession`이 직접 선택한 URL의 성공한 scope 시작을 보유한다. 후보 확인 화면에서도 유지하고, 가져오기 종료·뒤로 이동·세션 폐기 시 정확히 한 번 해제한다. false 반환만으로 접근 불가를 단정하지 않는다.
- import 요청에는 선택한 부모 URL을 accessURLs로 전달한다. 기존 서비스가 추가 획득한 scope는 기존 서비스가 해제하고, 세션 scope는 별도로 짝을 맞춘다. 영구 bookmark는 만들지 않는다.
- 탐색 I/O는 전용 직렬 작업 큐에서 수행한다. MainActor는 상태 반영만 담당하고, 취소 토큰은 반복 지점마다 확인한다. worker 종료 전 접근 scope를 해제하지 않는다.
- 모델은 동시 탐색·import·선택·삭제를 제한한다. 요청 ID로 늦게 돌아온 이전 탐색 결과를 무시한다. Task 취소는 실제 서비스 작업에 전달한다.
- 가져오기 중 화면 닫기는 취소 요청으로 처리하고 worker 완료까지 모델·session을 유지한다. 완료 후 manifest를 재조회하여 취소 전에 저장된 항목도 표시한다.

## 4. 화면과 상태

### 설정과 진입

기존 Settings scene을 `AppSettingsView`로 감싸 ‘개인정보’와 ‘글꼴’ 탭을 둔다. 기존 개인정보 토글과 설명을 유지한다. 글꼴 탭은 약 720×560pt를 기준으로 스크롤 가능한 목록을 제공하고, macOS 12에서 사용할 수 있는 API만 사용한다. 실제 창 크기 전환은 Stage 2에서 검증한다.

글꼴 탭 상단은 ‘가져온 글꼴’, ‘기존 한글 글꼴 가져오기…’, ‘새로고침’을 제공한다. 가져오기 sheet에서 ‘이 Mac의 한글’과 ‘Mac에 설치한 글꼴’을 선택한다. 미발견 화면에서도 ‘한글 앱 또는 글꼴 폴더 선택…’을 항상 제공한다.

### 가져오기 상태

`출처 선택 → 탐색 중 → 후보 확인 → 가져오는 중 → 결과`로 전이한다. 위치 선택 취소는 기존 후보를 보존하고, 새 출처 탐색은 이전 탐색 작업을 종료한 뒤 시작한다. 서비스 준비 오류는 재시도 가능한 안내로 표시하고 입력 처리 버튼을 비활성화한다.

- 후보 확인: 출처별 그룹·파일명·크기, 선택/전체 선택, 검색 제한·접근 실패 안내. 개별 폰트 파일 선택을 강요하지 않는다.
- 처리 중: 불확정 진행 표시, 선택한 총 파일 수, ‘취소’. 서비스에 없는 항목별 완료 수나 퍼센트를 만들어 표시하지 않는다.
- 결과: 추가됨·이미 있음·선택 필요·미지원·손상·읽기/저장 실패·취소 수와 항목별 조치. candidate ID로 입력과 결과를 연결한다.
- ‘가져옴’은 관리 복사본 저장을 뜻한다. 현재 renderer 미연동은 ‘문서 표시·출력 적용은 준비 중입니다’처럼 사용자 언어로 표시한다. 개발 이슈 번호·manifest·해시·generation을 기본 UI에 노출하지 않는다.
- TTC/가변은 저장 상태와 적용 제한을 함께 표시한다. 사용 조건 unknown을 사용 허가로 바꾸거나 ‘한컴 삭제 가능’으로 안내하지 않는다.

### 관리와 오류 복구

저장 목록은 family/full name → PostScript → 파일명 순으로 표시명을 선택하고 스타일·출처·제한을 보조 정보로 보여준다. 상세에서 버전과 사용 조건 상태를 확인할 수 있다. 파일 단위 삭제이므로 collection의 여러 face가 함께 제거됨을 삭제 확인에서 알린다.

동명 충돌은 사용자가 지원 가능한 face를 명시적으로 선택하도록 한다. 현재 선택을 먼저 표시하고 unsupportedSelection 대상은 활성화하지 않는다. `selectActive`와 `remove`는 조회한 generation을 전달한다. staleGeneration이면 재조회하고 사용자가 다시 선택하도록 한다.

`visibleDurabilityUnconfirmed`는 ‘저장 결과 확인 필요’로 표시하고 재조회·동일 입력 재시도를 제공한다. 손상 manifest·객체는 자동 초기화하지 않는다. recover가 회수를 보류한 경우 저장 실패와 구분하며 사용자가 관리 파일을 직접 삭제하도록 유도하지 않는다. 저장 오류 메시지에 raw underlyingError·원본 절대 경로를 자동 출력하지 않는다.

## 6. Stage 2 — 설정과 가져오기 흐름

산출물: 설정 탭, 상태 모델, 자동/수동 탐색·후보 선택·일괄 import 및 기본 결과 화면.

검증: 서비스 준비 실패·탐색 재시도·panel 취소·중복 클릭·오래된 응답 무시·import 취소의 상태 전이를 테스트한다. 하나의 배치가 서비스에 전달되고 scope가 작업 완료까지 유지되는지 확인한다. HostApp 빌드와 개인정보 설정 회귀를 확인한다.

**첫 시각 확인 시점:** 실제 앱의 글꼴 빈 화면, 후보 화면, 처리 중/기본 결과 화면을 스크린샷으로 제시한다. fixture로 구성한 화면은 그렇게 명시한다. 직접 확인할 때는 실행 가능한 서명 산출물의 절대 경로·실행 명령과 ‘알한글 → 설정 → 글꼴’ 동선을 안내한다. 컴파일 전용 미서명 산출물을 사용자 실행용으로 안내하지 않는다.

완료 기준: 사용자 선택에서 공통 저장소 결과까지 실제 UI 흐름이 연결되고 화면 증거 또는 직접 확인 안내가 제공된다. 충돌·상세 관리는 다음 단계임을 명시한다.

커밋: `Task #565 Stage 2: 글꼴 설정과 Mac 일괄 가져오기 화면 구현`

## 7. Stage 3 — 결과·충돌·목록 관리

산출물: 상세 결과·부분 실패·재시도, 충돌 선택, 저장 목록·삭제·지원 제한 표시.

검증: 동일 bytes 중복, 동명 다른 버전, TTC/가변 제한, staleGeneration, 게시 후 내구성 미확인, 일부 성공 후 취소·재시도, 삭제·재가져오기를 확인한다. 배치 취소 결과와 재조회 목록이 일치해야 한다.

실제 화면의 긴 글꼴 이름·오류·충돌·삭제 확인·키보드 포커스·스크롤·밝은/어두운 모드를 확인한다. 정상 결과와 충돌/실패 화면의 스크린샷 및 사용자 확인 항목을 제공한다. 테스트용 실패 상태는 실제 운영 데이터 손상 없이 주입한다.

완료 기준: 저장·제한·실패가 혼동되지 않고 기존 선택 보존과 명시적 변경·삭제 동작이 검증된다.

커밋: `Task #565 Stage 3: 가져오기 결과와 글꼴 충돌·목록 관리 구현`

## 8. Stage 4 — signed sandbox·회귀·인계

- 실제 서명된 HostApp에서 자동 탐색과 NSOpenPanel의 선택·취소·재선택을 검증한다. 앱에 경로만 주입한 probe는 panel 접근 권한 검증으로 간주하지 않는다.
- 실제 뷰어와 자체 fixture 결과를 구분한다. 편집기 설치본이 없으면 미검증으로 남기며 실제 편집기 수용이 필요한 조건을 보고한다.
- 테스트 전용 원본을 제거한 뒤 새 프로세스에서 저장 목록·관리 bytes가 유지되는지 확인한다. 사용자 원본 앱·Fonts는 수정하지 않는다. 검증용 저장소는 제품 경로와 격리하고 격리 조건을 기록한다.
- 글꼴 테스트, HostApp 빌드, 설정 변경 관련 테스트, Studio 문서 수명주기 회귀를 수행한다. macOS 12 target 컴파일과 최소 OS 실제 실행을 구분한다.
- 산출물·로그·화면은 `build.noindex/task565-stageN/` 아래에 둔다. 직접 확인용 앱은 서명과 실행 가능 여부를 검증한 뒤 안내한다. 개발 앱 등록 상태는 `scripts/check-extension-registration-hygiene.sh --check-only`로 확인하며 본 작업이 만든 등록은 정리한다. Finder 확장 등록은 표준 smoke 절차 밖에서 수행하지 않는다.
- 화면 캡처는 실제 해당 창으로 한정하고 사용자 문서·경로가 노출되면 자체 fixture로 재현한다. 캡처 접근이 불가능하면 직접 확인 동선과 기대 결과를 안내하고 미확인 항목을 기록한다.
- `font_library_integration.md`에 확정된 탐색/권한/UI 계약과 #566·#567·#569 인계 내용을 보완한다. 릴리스·공증·배포는 수행하지 않는다.

완료 기준: 수용 기준별 PASS/FAIL/미검증을 기록하고 실제 화면·권한 경계의 증거를 제공한다. 미검증 환경을 합격으로 대체하지 않는다.

커밋: `Task #565 Stage 4: Mac 글꼴 가져오기 통합 검증과 인계 정리`
