실제 Mac Spotlight 본문 검색의 환경 차이는 [#587](https://github.com/postmelee/alhangeul-macos/issues/587)에서 추적한다. 새 후보의 실제 Mac 결과와 이전 버전의 예외 승인 근거를 구분한다.

실제 Mac 대조에서는 v0.2.4/22 Quick Look 제공자로 OLE 제보 HWP와 HWPX 모두에서 `SVG` 자리표시자를 확인했다. 작성자가 제공한 한컴 PDF에는 차트가 있고 같은 제보에 첨부된 다른 PDF 두 개에는 동일한 OLE 미지원 자리표시자가 있다. #613이 사용한 공개 회귀 파일과 이 제보 원본은 별개다. 비공개 원본과 비교용 PDF는 공개 릴리즈 자산에 포함하지 않는다.

공식 rhwp v0.9.1 macOS CLI의 공개 SHA-256을 대조한 뒤 두 제보 문서를 각각 PDF로 내보냈다. 두 1쪽 출력 파일의 해시가 같았다. 한컴 PDF와 비교해 막대, 축, 범례를 확인했고 글꼴 외형 차이가 있었다. 이 결과는 알한글 후보의 문서 또는 Finder 검증 범위에 합산하지 않는다. 검증 Mac의 Polaris Office 9.0.86과 Finder가 인식한 `com.infraware.polarisofficeservice.hwp`를 확인했다.

## macOS 예비 검사

이전 동기화 실행 44696814904의 공식 태그 Studio receipt와 root Cargo.lock을 확인했다. 이번 실행 44748954259의 패키지 7개와 Studio dist 파일 125개를 예비 검사 파일과 대조해 해시가 모두 같음을 확인했다. 진단 앱은 v0.9.0 native FW를 링크했다. HWP/HWPX의 실제 WebKit 저장·취소·재열기, 글꼴 전송을 검증한 43개 검사가 통과했다.

최초 표시·전환·재열기 각 실행에서 본문 캔버스와 올바른 활성 문서를 확인했다. 첫 묶음에서 픽셀 표식 일치 검사는 실패했다. 후속 반복에서는 HWPX 대조 2회가 `(28, 2217)`, HWP 대조 2회와 교체가 `(314, 32791)`이었다. 첫 묶음의 주입 없는 대조에서 두 값이 각각 `(34, 2457)`, `(282, 30533)`이었던 점을 기록한다. 반복 결과는 일치했고 초기 대조 차이의 원인은 확정하지 않았다. 같은 버전 native FW 및 서명 설치본에서 재검증한다.

예비 PDF 검사에서 레이어 스키마 `1.35`의 굵은 글자가 단순 SVG 획으로 남아 관리 글꼴 출력이 거부됐다. 익숙한 글자와 위치를 정확히 대조하는 변환에서 `1.35`를 추가했다. 수정 번들과 CI의 WASM이 같은 해시임을 확인한 뒤 진단 앱에서 HWP/HWPX PDF·인쇄용 PDF의 실제 Regular/Bold, 한글 검색·선택, 취소·재시도·문서 보존을 확인했다. 실제 인쇄 창에서는 취소했고 전송하지 않았다. 이 격리 앱의 결과는 서명 설치본의 수용을 대체하지 않는다.

PDF 수정 번들의 새 진단 앱 식별자에서도 첫 HWPX 대조가 `(34, 2457)`, 경쟁·반복·재열기는 `(28, 2217)`로 픽셀 일치가 실패했다. HWP 대조와 전환은 `(314, 32791)`로 일치했고 모든 실행에서 첫 페이지가 표시됐다. 설치된 서명·공증 v0.2.4 Studio 자산의 같은 격리 대조에서는 HWPX 반복 열기와 경쟁 주입 회차에 페이지 캔버스 없이 자리표시자만 남는 경우도 관측했다.

정확한 v0.9.1 native FW·Studio 자산을 사용한 WKWebView 검사에서는 HWP/HWPX 첫 페이지, 로딩 중 전환, 취소, 재열기를 확인했다. 격리 앱에서 보관 글꼴의 실제 Regular/Bold가 PDF 및 인쇄용 PDF에 적용되는 것을 확인했다. 서명된 설치판에서는 HWP/HWPX 열기와 검증용 사본 편집·저장·재열기, PDF 1쪽 출력, 실제 인쇄 대화상자 열기와 취소를 확인했다.

실제 Finder에서 Polaris HWP의 첫 페이지와 썸네일을 확인했다. OLE는 공개 회귀 표본과 별도로 제보 HWP/HWPX 양쪽의 빠른 보기에서 막대, 축, 범례를 확인했다. 같은 위치와 크기로 한컴 PDF의 차트 영역을 대조했다. 공개 OLE 표본의 썸네일에는 벡터 차트가 나타나지 않았다.

동기화 실행 44696814904에서 두 upstream 객체 저장소가 디스크를 소진했다. #620에서 Cargo 공유 clone과 staging 이동 범위를 좁히고 선행 가용 공간 검사와 단계별 사용량을 기록했다. 후속 macOS 러너에는 22,229,280 KiB가 남았다. 태그 동기화 후 native matcher가 v0.9.0을 가리키는 문제는 v0.9.1 모듈로 재생성하고 재생성·검증 절차를 워크플로에 반영했다. 이미 공식 태그가 반영된 상태에서는 [재실행](https://github.com/postmelee/alhangeul-macos/actions/runs/44856141808)으로 동기화 PR이 다시 생성되지 않는 것을 확인했다.

최근 Threads News Sync [수동 실행](https://github.com/postmelee/alhangeul-macos/actions/runs/44927653792)은 만료 검사에서 중단됐고, [일정 실행](https://github.com/postmelee/alhangeul-macos/actions/runs/44880294853)은 새 소식 수집 단계의 공통 오류로 중단돼 개별 API 응답을 판별할 수 없었다. 갱신 후 수동 dry-run과 공개 승격 작업의 새 소식 수집이 모두 성공했다.

열린 PR 중 [#577](https://github.com/postmelee/alhangeul-macos/pull/577)은 이전 v0.8.7 호환 작업으로 head `e0793cd3`에 실패와 병합 충돌이 있어 보류했다. ### 실제 Mac Spotlight

Sparkle 업데이트 후 T7에 만든 새 검증 표본을 605초 동안 관찰했다. 앱 종료 후 HWP/HWPX 영문·한글 본문과 TXT 양성 대조를 모두 검색하지 못했다. 사용자의 인덱싱 설정과 등록 상태는 그대로 두었다. 자동 검색 측정이 끝난 뒤 실행한 `mdimport -t -d3`에서는 설치된 알한글 importer가 HWPX 본문을 추출했다. 같은 Mac의 HWP는 Polaris UTI `com.infraware.polarisofficeservice.hwp`로 선택돼 importer가 연결되지 않았다. 이 UTI는 Finder 미리보기·썸네일 확장과 별개로 Spotlight importer의 지원 목록에 없다.

실제 Mac의 자동 검색은 [#587](https://github.com/postmelee/alhangeul-macos/issues/587)에서 추적한다. 1차 Intel의 재설치 시작 전 검색 소실은 위 설치 기록에 남겼다. 실제 Mac의 Spotlight 수용 조건이 남아 있어 [#621](https://github.com/postmelee/alhangeul-macos/issues/621)을 열어 둔다.

### Homebrew와 제보 후속 처리

[Homebrew tap #6](https://github.com/postmelee/homebrew-tap/pull/6) 병합 커밋은 `56e0027b860ff51b52b80e3c0d8233779a8938a5`다. `brew style --cask`와 일반 `brew audit --cask`를 통과했다. Cask가 내려받은 공식 파일의 SHA-256을 확인했다. T7을 임시 마운트 위치로 지정하면 읽기 전용 DMG attach가 거부돼 macOS 기본 임시 마운트 위치로 재시도했다. 다운로드와 검증 기록은 T7에 두었다.

Cask receipt를 0.2.4에서 0.2.5로 갱신했다. 이 시험 직전 실제 앱은 Sparkle로 설치한 0.2.5/23이었다. 일반 제거 후 같은 Cask로 신규 설치해 receipt, 빌드 23, 해시, 서명 및 staple을 다시 확인했다. Finder 최초 실행에서 Apple 검사 통과 문구가 있는 일반적인 다운로드 앱 열기 확인이 표시됐다. 확인 후 앱이 실행됐고 두 번째 HWP의 첫 페이지가 표시됐다. 사용자 설정 초기화 옵션은 사용하지 않았다.
