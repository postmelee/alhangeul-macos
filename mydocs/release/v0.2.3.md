# Alhangeul v0.2.3 릴리즈 준비 기록

## 상태와 기준

**미공개 · Stage 2 소스·안내 후보 준비 중 · 최종 DMG 생성/설치·공개 수용 미실행.** 작업지시자는 Stage 1 결과를 수용하고 Stage 2의 소스·안내 후보 준비와 unsigned 검증을 승인했다. 이번 기록은 출시 완료 보고가 아니며 최신 공개 앱은 여전히 [v0.2.2](https://github.com/postmelee/alhangeul-macos/releases/tag/v0.2.2)다.

Cargo tag/commit/features, generated build info, bundled Studio/menu adapter, native matcher receipt와 네 bundle 기준을 확인했다. 기준 header/staticlib의 실제 SHA256·size도 lock과 일치했다. native-skia feature가 포함되지만 Finder 기본 정책은 CoreGraphics를 유지하며 Skia 기본 전환을 이번 변화로 표시하지 않는다.

업스트림 [v0.8.7 릴리즈](https://github.com/edwardkim/rhwp/releases/tag/v0.8.7)에 2026-10-11 CLI Native Skia 재패키징 안내가 추가되었다. source tag/commit은 동일하다. 알한글은 해당 CLI 다운로드 파일을 번들하지 않고 고정 core/자체 bridge 산출물을 사용하므로 그 자산 교체만으로 새 pin/재동기화가 필요하지 않다.

## GitHub Release 본문 구조 후보

이 구획은 helper가 추출할 사용자 본문 후보다. 최종 DMG 수용 전에는 공개하지 않으며 실제 DMG hash·source/tag/run은 생성 후 기록한다.

### 변경 요약

- Mac에 설치된 글꼴 사용을 켜고 문서의 기존 글꼴 목록에서 선택할 수 있습니다.
- 지원 글꼴을 문서 화면과 저장·재열기, PDF·인쇄 및 Finder 미리보기·썸네일에 연결했습니다.
- 반복 Finder 요청의 글꼴 준비와 여러 파일의 썸네일 요청이 겹쳤을 때 처리를 개선했습니다.

### 포함된 rhwp 변화

문서 처리 엔진과 편집 화면을 공식 [rhwp v0.8.7](https://github.com/edwardkim/rhwp/releases/tag/v0.8.7)로 함께 갱신했습니다. 표 너비와 쪽 나눔, 문단 배치, 일부 HWP/HWPX 저장본 호환성과 하이퍼링크·편집 동작을 보완했습니다. 호스트 글꼴 공급 기능을 통해 Mac 설치 글꼴을 알한글에 연결했습니다. 모든 문서의 한컴 동일 표현을 보장하지 않습니다.

### 알한글 앱 변화

- 설정(⌘,) → 글꼴 → **Mac에 설치된 글꼴 사용**을 켠 뒤, 문서의 기존 목록에서 **시스템 글꼴**을 고릅니다. 기본은 꺼져 있으며 처음 준비할 때는 잠시 기다려 주세요.
- 원본과 읽기 권한이 유지되면 다음 실행에도 사용 설정이 유지됩니다. 상세 동선은 [Mac 글꼴 사용 안내](https://postmelee.github.io/alhangeul-macos/fonts/)에서 확인할 수 있습니다.
- 별도 파일의 독립 복사본은 설정의 **보관한 글꼴 → 글꼴 가져오기…**에서 관리합니다. 설치 글꼴을 선택하는 데 매번 가져올 필요는 없습니다.
- PDF·인쇄에서 출력용 글꼴을 준비하지 못하면 취소하고 안내합니다. 대체 글꼴 출력을 직접 선택하면 모양과 배치가 달라질 수 있습니다.
- Finder의 반복 글꼴 준비에서 검증된 정보를 재사용하고 여러 썸네일 요청은 제한된 대기열로 처리합니다. 최초 준비·많은 파일에는 시간이 걸릴 수 있으며 모든 Mac의 실행시간이나 지연 상한을 보장하지 않습니다.

설치 글꼴은 원본의 존재·활성·권한에 의존합니다. 일반 TTF/OTF의 검증된 Regular/Bold를 중심으로 지원하며 TTC 개별 face·가변 축·HFT 전체 지원, 한컴 내부 글꼴 자동 추출과 한컴 제거 후 모든 글꼴 유지를 보장하지 않습니다. Windows 폴더·ZIP 가져오기는 별도 후속 기능입니다. 글꼴의 사용권은 각 배포 조건을 확인하세요.

기존 저장 한계도 유지됩니다. 암호 보호를 유지하는 저장과 HWP3 원형 저장은 지원하지 않습니다. 보호 원본의 덮어쓰기를 막고 안내 뒤 새 평문·변환 복사본으로 저장합니다. “저장하지 않음”으로 닫은 문서가 다음 실행의 복구 목록에 남는 문제는 별도 후속으로 남아 있습니다.

## 지원 범위와 수용 경계

Mac 기능은 활성 설치된 일반 TTF/OTF의 검증된 Regular/Bold를 중심으로 한다. 설치 원본의 존재·활성·권한이 필요하며 한컴 앱 내부 추출 또는 한컴 제거 후 모든 글꼴 유지를 보장하지 않는다. 별도 가져온 독립 복사본과 설치 참조를 구분한다. TTC 개별 face·가변 축·HFT·전체 complex shaping/쪽 배치·외부 사용 라이선스·모든 시스템 글꼴은 보장 범위 밖이다.

기존 #569 signed 진단 앱의 실제 NanumSquare·문서/PDF·인쇄 취소·Finder 수용과 #580 반복 metadata 약 160~170ms/provider 약 328~343ms 증거를 인계한다. 원래 <300ms 미충족과 다수 파일 첫 miss 지연은 유지한다. 이전 232 family/809 records는 그 Mac의 당시 관측이며 새 후보의 정답으로 고정하지 않는다.

최종 일반 Release·공증 DMG, 새 ARM/Intel VM 설치·재설치, 실제 Mac 및 v0.2.2 → v0.2.3 실제 Sparkle 업데이트는 미실행이다. 최소 macOS 12·Intel 실기기 GUI·실제 한컴 제거·물리 인쇄도 미검증이다. 기존 격리 앱, VM 검색 성공 또는 static universal slice 검사로 대체하지 않는다.
