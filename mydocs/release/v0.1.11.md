Finder 제공자는 기존 앱·HOP 등록을 일시 분리해 검증했으며 자연 선택·Sparkle 실제 업데이트 성공으로 확대하지 않는다. 상세는 [Stage 4 수정 후보 검증 완료](../working/task_m900_494_stage4.md#수정-후보-검증-완료--2026-09-07)에 기록했다. 2026-09-06 Stage 2에서는 포함 PR과 연결 이슈 원문, 완료 보고서를 대조했다. 아래 공개 본문은 승인된 source 변화에 근거한 배포용 후보이며, 새 v0.8.6 통합 후보와 signed 설치본의 검증 성공을 의미하지 않는다. Stage 3~4 검증 뒤 후보를 재검토하고 Stage 5 공개 전 준비 상태 문구를 갱신한다.

Stage 1에서는 세 target의 version/build와 두 workflow 기본 입력을 정렬했다. main 전용 5개 merge는 실제 content가 이미 공통 조상에 있어 history-only back-merge를 생략했다. [Stage 1 보고서](../working/task_m900_494_stage1.md)의 tree 근거를 Stage 4 main merge 직전에 재확인한다.

## 사용자용 요약

- 암호 문서와 HWP3 문서를 저장할 때 원본을 덮어쓰지 않도록 보호하고, 변환·보호 해제를 안내한 뒤 새 복사본으로 저장합니다.
- PDF의 한글 텍스트 선택·검색·복사를 보강하고, PDF·인쇄를 반복 실행할 때 중복 요청과 이전 작업의 응답이 새 작업을 방해하지 않도록 수정했습니다.
- 지원하지 않는 파일을 열어도 기존 문서를 유지하며 다시 시도할 수 있고, 글자색·형광펜 색상 선택기의 표시와 위치를 보정했습니다.
- `rhwp v0.8.6`의 문서 조판·저장 호환성과 한글 입력·표 편집 개선을 반영했습니다.

암호 보호 유지·새 암호 설정과 HWP3 원형 저장은 지원하지 않는다. 이번 저장 변화는 원본 보호와 새 복사본 저장에 한정한다. v0.1.10 과거 기록의 저장 위험 안내는 해당 버전의 실제 동작이므로 보존한다.

## GitHub Release 본문 구조 후보

### 변경 요약

- 암호 문서와 HWP3 문서를 저장할 때 원본을 덮어쓰지 않도록 보호하고, 변환·보호 해제를 안내한 뒤 새 복사본으로 저장합니다.
- PDF의 한글 텍스트 선택·검색·복사를 보강하고, PDF·인쇄를 반복 실행할 때 중복 요청과 이전 작업의 응답이 새 작업을 방해하지 않도록 수정했습니다.
- 지원하지 않는 파일을 열어도 기존 문서를 유지하며 다시 시도할 수 있고, 글자색·형광펜 색상 선택기의 표시와 위치를 보정했습니다.
- `rhwp v0.8.6`의 문서 조판·저장 호환성과 한글 입력·표 편집 개선을 반영했습니다.

### 포함된 rhwp 변화

- Core와 bundled `rhwp-studio`를 [rhwp v0.8.6](https://github.com/edwardkim/rhwp/releases/tag/v0.8.6), commit `f1f9c6ae58344ee9368996d3543f76b9345cf227`로 함께 갱신했습니다.
- 표의 페이지 분할, 글상자·개체와 특수 글리프 배치를 보정하고, HWPX 개체·본문과 HWP3 본문을 보존하는 열기·저장 경로를 넓혔습니다.
- 한글 IME, 머리말·꼬리말, 배율·표 크기 조절과 중첩 표의 검색·치환을 개선했습니다.
- 비정상 문서의 입력 경계와 재귀 깊이 검사를 보강했습니다. 새 글꼴 인스턴스와 HWP 2024 호환 옵션은 명시적으로 선택하는 경로이며 기존 기본 경로를 바꾸지 않습니다.

### 알한글 앱 변화

- 보호된 HWP/HWPX는 저장 전에 보호 해제를 알리고 새 평문 복사본만 허용합니다. **암호 보호를 유지하는 저장과 새 암호 설정은 아직 지원하지 않습니다.**
- HWP3는 형식 변환을 안내하고 새 HWP5 또는 HWPX 복사본으로만 저장합니다. 원본과 다른 기존 파일도 덮어쓰지 않으며, 새 복사본의 파일 저장 권한 오류를 수정했습니다. HWP3 원형 저장은 지원하지 않습니다.
- 내보낸 PDF의 한글 글꼴에 문자 대응 정보를 포함해 선택·검색·복사를 보강했습니다. 이미지 글자 OCR이나 모든 수식·글꼴의 완전한 텍스트 추출을 제공하는 것은 아닙니다.
- PDF·인쇄의 중복 실행을 막고 이전 작업의 늦은 응답을 무시해 취소·오류 뒤 다시 실행하는 경로를 안정화했습니다.

## 알려진 한계와 후속

- native 암호 저장은 미지원이며 Issue #480 항목은 OPEN으로 유지한다. 보호 상태 판정 불능 문서도 원본 덮어쓰기를 허용하지 않는다.
- HWP3 원형 저장은 미지원이다. 배타적 rename 미지원 파일시스템에서는 변환 저장이 실패할 수 있으며 원본과 기존 destination 보존을 우선한다. 과거 HWP3 저장 직후 종료 시 변경 경고가 한 차례 재표시된 현상은 통합 후보에서 다시 관찰한다.
- 저장한 모든 문서 요소의 의미론적 완전 무손실은 보장하지 않는다. HWPX runtime signature 검사는 완전한 ZIP 구조 검사를 대신하지 않는다.
- PDF 한글 mapping 보강은 positioned SVG의 논리 읽기 순서, Hanja·일부 수식/기호의 system font와 이미지 문자 선택을 모두 보장하지 않으며 OCR을 제공하지 않는다. 전체 page SVG 보유에 따른 memory, 문서 전체 progress/deadline·수집 중 취소 UI 제한은 유지된다.
- 앱 WKWebView와 native Finder renderer는 글꼴·배치가 다를 수 있다. smoke 성공을 원본 한글 프로그램과의 모든 문서 시각 정합성으로 설명하지 않는다.
- upstream 키보드 활성화 수정은 v0.8.6 이후이며 이번 색상 선택기 위치 보정의 효과에 포함하지 않는다. 혼합 서식 소실 문제는 현재 후보 검증 전 해결됐다고 표시하지 않는다.
- Debug·기본 개발 configuration에는 production endpoint가 없지만 unsigned Release에는 포함된다. 개발용 Release는 정적 bundle 검증으로 확인하고 승인된 실제 배포 smoke와 구분한다. 과거 운영 행의 삭제·재분류나 공개 앱 개인정보 정책 변경은 없다.
- Stage 3의 저장 후 종료 안내가 Stage 4 signed HWPX에서도 Command+Q 경로로 재현됐다. 저장 선택으로 종료했고 HWP5 재열기 후 native 메뉴 종료는 안내 없이 성공했다. keyboard edit 분류 가능성을 별도 확인하며 원인을 확정하지 않는다.
- Intel Mac과 macOS 12 실기기 검증은 실제 실행 전 통과로 쓰지 않는다.
