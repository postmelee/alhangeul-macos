# #587 3단계 — 실제 Mac의 볼륨 소유권과 자동 본문 검색

macOS 26.5.2 (25F84) Apple Silicon에서 공개 v0.2.7 빌드 25를 사용했다. 원래 외장 APFS는 색인이 활성화되어 있었고 소유권은 꺼져 있었다. 원래 볼륨과 별도로 같은 장치에 작은 APFS 시험 이미지를 만들었다. 모든 시험은 합성 파일에서 진행했다.

## 공개판 HWPX

| 비교 | 소유권 무시 | 소유권 활성화 |
|---|---|---|
| 새 APFS 이미지 두 개에서 동시에 시작 | 5초에 TXT·RTF가 검색됐고 150초까지 HWPX 본문·제목 없음 | 45초 관측에서 영문 본문으로 HWPX·TXT·RTF가 검색됐고 importer 제목 확인 |
| 같은 APFS 원본·볼륨 이름에 매번 빈 쓰기 오버레이 사용 | 150초에 영문은 TXT·RTF, 한글은 TXT만 검색. HWPX 제목 없음 | 30초에 한글 본문 및 HWPX 제목, 55초에 영문·한글 모두 HWPX와 대조군 검색 |

같은 앱, 파일 내용, 한컴 HWPX UTI를 유지했다. 파일 이름에는 검색어가 없었다. 마운트할 때 시험 이미지의 색인을 활성화하고 문서를 새로 복사했다. 자동 관측 동안 문서나 importer를 지정해 재색인을 요청하지 않았다. 같은 원본 이미지에서 Spotlight가 기록한 파일 소유자는 소유권을 켰을 때 로그인 사용자, 무시했을 때 메타데이터 서비스 계정이었다. 이 차이는 관측했으나 macOS 내부에서 어떤 분기로 작업을 배정했는지는 확인하지 못했다.

기존 색인을 보존한 채 두 이미지를 서로 반대 조건으로 재마운트한 비교에서는 양쪽 모두 150초까지 TXT도 검색되지 않았다. 이 구간은 형식별 결과 판정에서 제외했다. 원래 외장 볼륨에서 이전 표본을 다시 조회했을 때는 TXT·RTF만 검색됐다.

## 수용 절차

실제 Mac에서 문서 본문이 빠지면 같은 위치의 TXT와 볼륨 소유권 상태를 함께 기록한다. 외장 볼륨 설정을 보존하면서 소유권을 활성화한 작업용 APFS 이미지에서 같은 문서로 자동 검색을 비교할 수 있다. 공개판의 HWPX 추출기는 변경하지 않았다.

## #639 후보의 실제 설치 경로

같은 공개 앱에 2단계의 universal importer를 넣고 로컬 배포용 인증서로 서명한 후보를 사용했다. 전체 서명·bundle 계약과 CFPlugIn 직접 호출 회귀가 통과했다. 공개 앱이 실행되지 않은 것을 확인하고 정식 설치 경로의 앱과 후보를 교환했다.

초기 시험에서 Spotlight가 이미 제거한 사용자 시험용 importer 경로를 계속 선택했다. TXT·RTF가 검색돼도 150초까지 두 문서가 빠졌다. 그 뒤 목록이 정식 앱의 importer 하나로 돌아왔고 동일 경로가 Polaris HWP의 본문을 반환하는 것을 확인했다.

다시 소유권을 켠 시험 이미지의 빈 오버레이에 새 파일을 만들었다. 후보 앱이 종료된 상태에서 6.5초 관측은 결과가 없었고, 15.1초 관측에서 영문은 HWP·HWPX·TXT·RTF, 한글은 HWP·HWPX·TXT가 검색됐다. RTF 표본에는 영문만 있다. 같은 HWP·HWPX에 후속 시험 추출을 실행해 Polaris·한컴 UTI와 정식 설치 경로의 importer 선택을 확인했다. 새 표본의 자동 관측 동안 파일 단위 재색인 요청을 사용하지 않았다.

시험 뒤 기존 공개 앱의 설치 객체, 실행 파일·importer 해시 및 전체 서명을 확인하고 시험 볼륨을 분리했다. 원래 외장 디스크는 소유권 무시 상태를 유지했다. 이 후보는 로컬 서명 설치로, Polaris 수정의 공개 배포 후 확인은 다음 릴리스에서 진행한다.
