# Task M020 #513 Stage 9 — 동일 버전 재설치 실제 검색 검증

## 후보와 환경

Stage 8 제품 소스 `b48a6bc`, universal Release ad-hoc 0.2.0(18) 후보를 현재 macOS 26.5.2 arm64에서 실행했다. ZIP SHA256은 `25153d77deb1eb84ee29a53e19fa30f9a1bfbbdc33f00c9139f419ae683ba07a`다. 공개 v0.2.0 DMG/tag/서명/배포 자산은 변경하지 않았다. package 과정의 portable Rust/ABI·golden·universal build·bundle/callback 검증도 통과했다.

처음에는 공개 앱을 유지했으나 설치 전부터 합성 본문이 색인돼 사전 미검색 조건이 실패했다. 이 공존 시험은 성공 증거에서 제외하고 소유 문서를 정리했다. 이후 실행 중인 공개 앱이 없음을 확인하고 전체 bytes와 설정을 비공개로 백업한 뒤, 설치본을 noindex 보관 위치로 이동하고 기존 등록을 잠시 분리했다. 설치 이력이 없는 OS로 간주하지 않는다.

재설치 전후 요청 기록의 경로·빌드·수정 시각은 같고 설치 식별자만 달라졌다. 시험 중 요청 키 제거/초기화, corpus 열기, 외부 lsregister 등록·mdimport 색인 또는 touch는 하지 않았다. 공개 앱의 격리·복원은 시험 전후 환경 조치로 별도 기록한다. `mdimport -t` 진단은 본문 검색 성공 뒤 실제 후보 선택을 확인하며 색인 저장을 하지 않는다.

## 검증 도구와 정리

표준 smoke에 `prepare-reinstall`, `reinstall-app`, `reinstall-search`를 추가했다. 소유 경로·기존 요청 키·사전 미검색·동일 후보·새 설치 식별·실제 검색과 종료 후 유지가 모두 필요하다. 외부에서 몰래 같은 bytes/mtime로 교체한 앱은 새 설치 객체 비교로 일반 최초 설치 판정에서 제외한다. Python 운영 회귀 **36개**, 기존 릴리스 검증 회귀 **11개**, bundle 회귀 **5개**, 구문과 `git diff --check` PASS다.

표준 cleanup에서 소유 문서/앱/프로세스·검색 결과 제거와 격리 당시 provider 보존은 PASS였으나 카탈로그가 60초 한도 뒤에도 남았다. 공개 앱을 복원한 뒤 정확한 소유 경로의 등록 해제를 재확인하자 카탈로그 제거를 확인했다. 최초 정리 MISS는 삭제하지 않고 후속 PASS와 구분한다. 전역 색인/LaunchServices 초기화나 daemon 종료는 하지 않았다.

공개 앱의 전체 파일 hash/symlink, 설정 전체 dictionary, 원래 provider 선택을 모두 복원·확인했다. `defaults import` 이후 남은 후보 전용 창 위치 키 1개는 백업에 없는 것을 확인해 제거했다. 이는 시험 후 복원이며 재설치 전에 요청 키를 지워 성공시킨 것이 아니다. 원시 preferences·로그는 `build.noindex`에만 보존하고 공개 증거에 포함하지 않는다.

[정제 결과 JSON](../report/assets/task_m020_513/same-version-reinstall-results.json)에 공존 시험 제외·최초/재설치·정리 및 복원 결과를 함께 보존했다. 이번 실측은 CLI/요청 기록 검증이며 새 Spotlight GUI 캡처는 없다. 이전 화면을 새 후보 증거로 재사용하지 않았다.

## 남은 수용

개발 후보의 같은 버전 재설치 회귀는 통과했다. 새 서명·공증 배포 후보의 최초 설치/동일 버전 재설치/실제 Sparkle와 macOS 12 실행은 별도 관문이다. 공개 v0.2.0의 알려진 재설치 한계를 해결된 것으로 고치거나 #513 / #337 을 종료하지 않는다.
