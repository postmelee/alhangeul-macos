# Task M020 #513 Stage 7 — 최종 후보 실패 시나리오 재검증

## 승인과 기준

2026-09-10 작업지시자가 PR #515 병합 전 재검증·원인 조사와 필요한 보완·결과 갱신을 승인했다. PR head e6331c8, 제품 소스 3aa2722, universal Release ad-hoc 0.1.11(17) ZIP SHA-256 `f9134bb199236fd0e9076270bd937008790f99d0266beb8aea74a813dacefa8d`를 고정했다. Stage 6 시험 세 건의 cleaned를 확인했다. 이번 시스템 시험 동안 앱 빌드를 병행하지 않는다.

## 조사 기준

- 복사·첫 실행 이후 자동 검색과 앱 종료 후 복원·수정·삭제를 구분한다. 실패 뒤 추가 대기는 최초 제한 시간 내 통과와 구분한다.
- TXT 대조를 설치 전에 확인한다. 일반 TXT 미검색을 importer 결함으로 판정하지 않는다.
- 요청 접수, 실제 importer 추출, Spotlight 저장소의 검색 반영은 별도 증거다. Apple의 [Spotlight importer 문제 해결 문서](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/MDImporters/Concepts/Troubleshooting.html)를 참조하며, 오래된 문서의 기대 동작을 현재 OS의 실측 결과 대신 사용하지 않는다.
- 원본 사용자 앱·문서·기본 연결, 전역 색인 설정은 변경하지 않는다. 합성 시험만 소유 경로에서 실행하고 표준 cleanup으로 정리한다.

## 진행 기록

첫 새 시험의 설치 전 TXT 대조가 60초 내 검색되지 않았다. macOS의 `/`, Data 볼륨은 Indexing enabled이며 일반 파일 metadata도 아직 제공되지 않는다. 앱 설치는 진행하지 않았고, 파일을 변경하지 않는 추가 관찰로 일시 지연 여부를 분리한다.

TXT는 최초 60초에 이어 무조작 추가 180초에도 검색되지 않았다. 기존 설치 앱의 메타데이터는 정상 조회된다. 동일 소유 workspace의 별도 폴더에서 직접 작성, copyfile, copy2 방식의 TXT를 비교한다. 원래 HWP/HWPX corpus 및 후보 앱은 변경하지 않는다. 시스템 로그의 최근 오류/시험 경로 조회에서는 원인을 특정할 메시지를 얻지 못했다.

## 동시 작업의 importer 발견

TXT 비교의 세 파일은 시작 약 117.07초에 모두 자동 검색됐다. 직후 예정한 직접 작성 TXT 한 개의 수동 `mdimport -i`도 실행했으므로 이 요청은 자동 검색 회복의 원인 증거가 아니다. 해당 조작을 state에 명시했고 원래 HWP/HWPX에는 수동 재색인을 요청하지 않았다.

환경 재확인에서는 후보 설치 전 HWP3/HWP5/HWPX 세 파일이 이미 검색돼 `pre-install-body-absent`가 실패했다. 시험 시작의 importer catalog에 별도 #516 작업의 Debug 앱이 등록되어 있었고, 원본 HWP에 대한 `mdimport -t -d1` 진단은 해당 Debug importer를 실제 선택했다. 이 결과는 #515 최종 후보의 자동 발견·색인 성공이 아니다. 이전 Stage 6 실패의 원인으로 소급하지 않는다.

별도 작업 「저장할 문서 없음 오류 분석」은 실행 중이다. 해당 산출물은 변경하지 않았고 작업지시자에게 빌드·실행 검증 일시 중지 및 등록 정리 조율을 요청했다. 이번 시험은 후보 설치·실행·lifecycle에 도달하지 못했다. 소유 합성 문서만 표준 cleanup으로 정리한다.

## 검증 도구 보완

TXT가 60초 및 추가 관찰 후 늦게 검색되는 현상에 따라 `prepare --search-timeout`(1–600초, 기본 60초)을 추가했다. 각 검색의 실제 경과 시간과 설정 한도를 성공·실패 모두 기록해 관찰 조건을 공개한다. 기본 한도나 제품의 600초 발견 정책을 바꾸지 않았다. 양성 검색의 실패 기록에서 `control_ok`가 기대 경로 존재만으로 true였던 진단 오류도 고쳤다. 이제 TXT를 실제 조회하므로 이전 기록의 해당 true 값만으로 실패 당시 색인 서비스 정상을 단정하면 안 된다.

운영 회귀 29개 PASS(기존 26 + 신규 3): 검색 한도 CLI 검증, 80초 지연 성공의 120초 한도/경과 기록, 양성 검색 실패 시 실제 대조 부재 및 명시적 한도 우선 적용을 검증했다. 제품 앱 bytes는 변경하지 않았다.

작업지시자 승인 후 #516 작업에 조율을 요청했고, 해당 작업은 빌드·실행 검증 중지를 확인했다. 읽기 전용 catalog 재조회에서 알한글 importer가 모두 제거된 것을 확인한 뒤 두 번째 시험을 준비했다. 첫 시험은 cleaned이며 사용자 앱 hash/provider가 보존됐다. 두 번째 시험은 새로운 합성 토큰과 소유 경로, 검색 관찰 한도 600초를 사용한다.

## 두 번째 시험의 첫 실행과 복원 진단

최종 후보의 새 경로 첫 실행: 설치 전 환경 10.91초, 발견 101.23초(launch 전체 101.40초), 검색·실제 후보 선택 6.40초, 앱 종료 후 검색 2.82초 PASS. HWP3/HWP5/HWPX 영문 3개와 HWP5/HWPX 한글 2개, 실제 후보 선택을 확인했다. 최초 snapshot은 실행 1회·보조 조작 없음·원본 corpus/후보 bytes 및 시각 보존 상태로 고정했다.

뒤이은 lifecycle은 삭제 영문/한글 반영 후 복원 대기 중 `mdfind` 자체가 30초 무응답으로 실패했다(단계 전체 94.71초). 문서와 state를 보존했다. 자기 importer는 catalog에 남아 있고 복원 파일은 아직 기본 metadata가 없었다. 같은 소유 Files에 새 TXT를 직접 작성하자 약 127.23초에 자동 검색됐고, 보존한 HWP도 추가 수정/수동 재색인 없이 복원 약 263.56초 시점의 재조회에서 검색됨을 확인했다(정확한 최초 반영 시점은 미측정). 이는 이번 관찰의 지연·명령 응답 실패 근거이며, 앞선 모든 반복 설치 실패의 원인을 확정하지 않는다.

검색 조회 오류를 남은 관찰 시간 안에서 재시도하도록 도구를 보완했다. 오류마다 FAIL 기록을 보존하고 각 명령 timeout을 30초와 남은 관찰 시간 중 작은 값으로 제한한다. 재시도 중 빈 결과를 삭제 성공으로 인정하지 않는다. 영속 오류/회복/남은 시간 제한 회귀를 더해 운영 31개 PASS다. 동일 제품 후보·앱 종료 상태에서 전체 lifecycle을 다시 시작했다.

Spotlight UI는 computer-use의 com.apple.Spotlight 접근이 timeout으로 실패해 아직 양성 화면을 확보하지 못했다. 기존 스크린샷으로 대체하지 않는다.

재시도 lifecycle은 33개 판정 모두 PASS였으며 조회 오류가 다시 발생하지 않았다. 각 검색 관찰 중 최장 시간은 10.43초로 모두 기존 60초 안에 반영됐다. 앱 종료 상태를 유지했고 HWP/HWPX에 외부 재색인·등록·touch를 하지 않았다. 이후 표준 cleanup은 첫 호출에서 cleaned였다. 이 성공은 앞선 mdfind 무응답 실패와 추가 TXT 비교를 지우지 않으며, 별도 snapshot으로 보존했다. 동일 패키지·동일 fixture의 새 소유 경로 반복 설치 시험을 다음 순서로 시작했다.

## 새 경로 반복 설치와 화면 증거

동일 패키지·fixture를 새 경로에 설치한 세 번째 시험은 설치 전 환경 10.93초, 첫 실행 발견 273.17초(launch 전체 273.35초), 검색·실제 후보 선택 29.89초 PASS다. 앱 종료 후에도 28.16초에 PASS했다. 각 영문/한글 검색 중 가장 긴 관찰은 26.34초였다. 실행 1회·보조 조작 없음·corpus 및 후보 bytes/시각 보존을 독립 snapshot으로 고정했다.

Finder의 시험 폴더 범위 검색에서 파일명에 없는 `AlhangeulFinal20260910`으로 HWP3/HWP5/HWPX 3개, `나비`로 HWP5/HWPX 2개가 표시됨을 확인했다. 실제 후보의 앱 종료 상태에서 촬영한 [영문 검색 화면](../report/assets/task_m020_513/final-finder-body-search.png)과 [한글 검색 화면](../report/assets/task_m020_513/final-finder-korean-search.png)을 제공한다. 개인정보가 있는 사이드바를 가린 원본 캡처이며 합성 파일명/검색어만 포함한다. 별도 Spotlight 패널 화면으로 표현하지 않는다. 촬영 후 사이드바를 복원하고 새 시험 창/탭만 닫아 기존 Downloads 창으로 돌아갔다.

같은 세 번째 설치에서도 앱 종료 상태의 전체 lifecycle을 재실행한다.

세 번째 설치의 전체 lifecycle도 33개 판정 모두 PASS였으며 조회 오류가 없었다. 최장 검색은 원본 HWP 복원 40.65초로 모든 검색이 기존 60초 안에 반영됐다. 두 번의 완료된 lifecycle에는 제품 변경·외부 HWP/HWPX 재색인·앱 재실행이 없었다. 최종 소유 설치와 검색 결과를 정리하고 PR의 최신 CI를 확인한다.

## 최종 정리와 판정

세 시험 모두 소유 앱·문서·프로세스·검색 결과·importer catalog를 제거해 cleaned로 마쳤다. 두 최종 후보 시험은 첫 cleanup 호출에서 통과했다. 마지막 catalog에 알한글 importer가 없고 기존 두 사용자 앱 hash/provider가 보존됐으며 HWP/HWPX 기본 연결은 모두 기존 한컴 뷰어였다. 추가 TXT 비교 파일의 검색 잔존도 0건이다. #516 작업에 실제 Mac 관찰 종료와 빌드·실행 검증 재개 가능 상태를 전달했다. 이후 그 작업의 재등록은 이 최종 정리 시점과 구분한다.

이번 병합 전 개발 후보 재검증은 완료했다. 전체 lifecycle을 두 번 통과했고 각 검색은 모두 기존 60초 이내였다. 간헐적 조회 무응답과 자동 색인 지연을 발견해 검증 도구에서 오류/한도/실제 대조 기록을 보완했으며 제품의 추가 수정은 하지 않았다. 과거 실패 원인 전체나 깨끗한 최초 설치·공개 배포의 안정성을 확정한 것은 아니다. #513 및 #337 이슈는 열린 상태를 유지하고 PR #515 본문과 코멘트에 최신 CI 결과를 함께 게시한다. 병합·이슈 종료·버전 상향·공개 서명/공증/배포는 하지 않았다.

### Stage 7.1 최종 코드 검토

관찰 한도 만료와 실제 조회 명령 오류의 기록을 분리했다. 한도에 도달해 명령을 실행하지 않은 경우에는 최종 검색 timeout만 기록하며 `query-error`를 만들지 않는다. 영속 오류는 실제 호출 횟수만큼 기록되는지, 단순 미검색은 명령 오류로 기록되지 않는지 기존 회귀를 강화했다. 운영 31개가 다시 PASS했다. 완료된 두 lifecycle은 명령 오류/관찰 한도 만료가 없어 이 보정의 관찰 결과는 변경되지 않는다. 제품 bytes도 동일하다.
