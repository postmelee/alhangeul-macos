# Task #558 Stage 2 — 수동 소식 구현과 데이터 검증

## 변경 결과

- v3 manual 목록에 공개 원문 6개를 고정하고 기존 v2 자동 수집 계약은 유지했다.
- 수동 collect/prepare는 토큰·네트워크 없이 동작한다. 현재 docs의 수동 목록과 조립 입력이 다르면 거부한다.
- 자동 활성 시에는 기존 새 수집·만료 검증을 반드시 통과해야 한다. 자동 실패를 수동 목록으로 대체하지 않는다.
- Docs-only와 Release Pages 모두 수동 목록을 전달한다. UI는 수동 목록의 만료 타이머를 만들지 않고 기존 카드 표시를 재사용한다.
- 새 JS 버전을 참조하여 이전 데이터 계약의 캐시가 남지 않게 했다.

- 기존 수집 43개, Pages 통합 14개, UI 데이터 9개 PASS.
- actionlint와 shell 구문 검사 PASS.
- 토큰 없는 공식 oEmbed 검사 6개 모두 PASS. HTML·본문은 저장하지 않았다.
- 수동 collect → 실제 Pages 조립 6개 PASS, appcast bytes 보존.
- 테스트의 누락 파일 예상 예외를 실제 계약인 OSError로 보정하고 다시 통과했다.
