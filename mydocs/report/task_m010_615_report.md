# #615 최초 문서 열기 빈 화면 수정 결과

v0.9.0 번들에서 글꼴 완료 통지가 최초 렌더 선택을 대체하면 기존 호출이 페이지 목록을 만들기 전에 반환했다. HostApp의 실제 문서 열기에서 로딩 완료와 빈 자리표시자가 함께 남는 경로를 확인했다. [수정 전 대조군](../working/task_m010_615_stage1.md)

문서 초기화는 현재 문서에서 진행 중인 최신 렌더 준비를 기다리고 첫 페이지 구성 결과를 확인한다. 문서가 교체되면 이전 호출의 완료 처리를 중단한다. 보정은 고정 소스의 빌드 변환으로 관리하고 원본·변환·생성 자산의 해시를 검증한다. [빌드 검증](../working/task_m010_615_stage2.md)

정상 열기 두 건, 단일·반복 통지, 대기 중 문서 교체, 명시적 재열기에서 첫 페이지와 파일명을 대조했다. macOS PR CI에도 같은 검사를 추가했다. [회귀 결과](../working/task_m010_615_stage3.md)

## 업스트림 반영 시 제거 조건

업스트림 수정이 포함된 정식 버전으로 동기화할 때 최초 렌더 어댑터와 관련 빌드 증명을 제거하고 번들을 재생성한다. 같은 WKWebView 회귀 검사에서 문서별 첫 페이지와 완료 표시를 확인한다. 호스트 글꼴 수집에 따른 입력 성능은 별도로 추적한다. [초기 렌더 #9164](https://github.com/edwardkim/rhwp/issues/9164) · [입력 성능 #9165](https://github.com/edwardkim/rhwp/issues/9165)
